# IQUIPAGE Maps · implementation R2

Переиспользуемая фича карт, сессий и сценариев действий. Карта не владеет навигацией платформы, авторизацией или проектом. Одинаковый модуль используется в примерах Sprintique-подобной оболочки и отдельного приложения.

**Статус: исполняемая reference-реализация с исходниками и автоматическими проверками модели/API. Браузерная приёмка заблокирована в среде автора. Это не внедрение в production Sprintique.**

## Запуск готового архива

Нужен Node.js 20 или новее. Зависимости npm для сервера и функциональных тестов не требуются.

```sh
cd iquipage-maps
npm test
npm run dev
```

Открыть `http://127.0.0.1:4317/`. Отдельная оболочка: `http://127.0.0.1:4317/?standalone=1`.

Сервер сохраняет данные в `.dev-state/`. Остановка: Ctrl+C в его терминале. Не удаляйте этот каталог, чтобы сохранить карты, архив и историю запусков. Второй процесс с тем же каталогом запрещён. Сервер намеренно слушает только localhost и не предназначен для публичного размещения.

Для другого порта и отдельной базы:

```sh
MAPS_PORT=4320 MAPS_DATA_DIR=/absolute/path/to/maps-data npm run dev
```

Вариант только с браузерным хранилищем: `http://127.0.0.1:4317/?storage=browser`. Здесь используется IndexedDB; серверные автоматизации недоступны. В примере первоначальная карта создаётся только при первом открытии пустого проекта. Внутри самого модуля демонстрационных данных нет.

## Предварительный HTML

Рядом с ZIP передан `IQUIPAGE-Maps-R2.html`: автономная сборка для ознакомления, не прошедшая браузерную приёмку. Она всегда использует локальный браузерный режим и не запускает server-side события. Хранение при file:// зависит от браузера; для воспроизводимого запуска и событий используйте ZIP и localhost. Не считать HTML отдельным production-продуктом.

## Что реализовано

- Встроенная поверхность без внешних горизонтальных полей, с доступной навигацией оболочки; переходы на отдельный экран задач и настройки в примере.
- Постоянные карты и сессии: создание, редактирование, поиск, пауза, завершение, архив только для чтения, продолжение отдельной копией.
- Сохранение по версиям, отказ записи, восстановление локальной копии, импорт и экспорт. Редактор — настоящий IQUIPAGE whiteboard, а не замена картинкой.
- 16 шаблонов с понятными названиями, назначением, моментом применения и предпросмотром. Свои шаблоны из целой карты или выделения; личная, проектная и общая видимость в reference-адаптере.
- Отдельная модель сценария: вход, преобразование, условие, LLM, подтверждение, создание задач, результат. Проверка графа, тест и исполнение — разные операции.
- Сохранённые подтверждения, входы/выходы шагов, ошибки, отмена и ограниченные повторы. После подтверждения создаются реальные **локальные** задачи стенда.
- UI правил запуска вручную, по расписанию, входящему запросу и событию проекта. Reference runtime умеет расписания, проверку подписанного входящего запроса, дедупликацию и события проекта.
- Контекст для агента, валидируемое предложение изменений, предварительный просмотр и принятие одним изменением карты. Самостоятельно подключённого AI-чата нет.

## Проверить сквозной сценарий

Откройте карту, нажмите «Начать сессию», запишите мысли. Перейдите в «Сценарий действий» и добавьте начальную цепочку. «Проверить» покажет ошибки структуры. В «Тест и запуск» выполните тест: подтвердите отредактированный список и убедитесь, что журнал показывает проверочные результаты, а задачи не созданы. Затем выполните обычный запуск, подтвердите список и откройте «Доска задач». Вернитесь к карте, завершите сессию с итогом, откройте архив и создайте продолжение. Исходная архивная карта останется неизменной.

Шаблон «Из встречи в план действий» тоже позволяет начать этот путь. LLM для начального сценария не обязателен: стандартный шаг преобразования убирает повторы без модели.

## Границы готовности

Навигация примера **не является реальными маршрутами Sprintique**, задачи стенда — не задачи его production-базы. Нет production-авторизации, общей командной синхронизации/CRDT, общего голосования и распределённой очереди. Таймер и голоса обозначены как локальные. Внешние LLM-вызовы не выполнены: ключей и подключённого gateway нет.

Браузерный запуск автора остановлен ошибкой `net::ERR_BLOCKED_BY_ADMINISTRATOR`. UI-тесты написаны, но не заявлены пройденными. Оценка внешнего вида по реальному браузерному кадру не выполнена. Возможные проблемы компоновки и браузерных взаимодействий должен закрыть следующий агент до пользовательской приёмки.

## Сборка в исходном репозитории

Ветка содержит отдельный пакет `packages/maps`. Поставку `design-system/` нельзя менять или смешивать с другой версией. В копии исходного репозитория:

```sh
cd packages/maps
npm run build
npm test
npm run dev
```

В самостоятельном архиве, если нужна официальная пересборка из поставки:

```sh
IQ_DS_ROOT=/absolute/path/to/iquipage-design-system/design-system npm run build
```

Build проверяет все файлы исходного манифеста и собирает отдельный DS source candidate. Исходная 05.7 остаётся неизменной. В архиве имеется предварительно собранный диагностический `dist/vendor`, восстановленный из приложенного HTML; его происхождение описано в `dist/PROVENANCE.json`. Он позволяет запустить архив без полной копии исходной DS, но не заменяет финальную официальную пересборку и браузерную проверку.
