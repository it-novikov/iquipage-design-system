# IQUIPAGE Maps · R4 / 0.2.0

Переиспользуемый модуль карт, сессий и исполняемых сценариев. Навигация, авторизация,
проекты и подключения принадлежат приложению-хозяину. Примеры показывают встроенную
Sprintique-подобную оболочку и самостоятельное приложение; это не production Sprintique.

## Запуск

Из репозитория сначала собрать проверенный вариант дизайн-системы:

```sh
cd packages/maps
npm run build
npm test
npm run dev
```

Из распакованной поставки R4: `cd IQUIPAGE-Maps-R4/packages/maps`, затем `npm test` и
`npm run dev`. Собранный runtime уже внутри. Нужен Node.js >=20; сервер и Node-тесты
не требуют npm-зависимостей. Адрес: `http://127.0.0.1:4317/`.
Отдельное приложение: `http://127.0.0.1:4317/?standalone=1`.

Данные находятся в `.dev-state/`. Для другой базы задайте `MAPS_DATA_DIR`, для порта —
`MAPS_PORT`. Не удаляйте базу ради обновления кода. Сервер слушает только localhost.
Для автономного просмотра откройте `IQUIPAGE-Maps-R4.html`: хранение в IndexedDB,
серверные расписания и события в этом режиме недоступны. Переносите данные через
экспорт/импорт: разные file:// пути и браузеры не обещают общее хранилище.

## Основные возможности

Постоянные карты и сессии с архивом, продолжения, 16 различных шаблонов и свои шаблоны;
пакетное добавление шести типов объектов, схемы, связи, отмена/повтор и сохранение по версиям.
Доска задач использует композицию IQUIPAGE и шесть согласованных колонок. Она является
начальной вкладкой платформенного примера, но не частью навигационной ответственности Maps.

Сценарии: вход, преобразование, условие, LLM, подтверждение, создание задач, результат.
Проверка схемы, тест без внешних эффектов и исполнение различаются. Сохраняются версия,
входы/выходы и журнал. Подтверждение человека обязательно перед созданием задач.

Host может включать эти поверхности через `uiCapabilities` и отдельно ограничивать
`allowedCreateTypes`. Внешняя task-ссылка хранится в `externalTaskId`, открывается через
публичное событие/callback и остаётся редактируемой только в task-сервисе. Полный контракт,
типы событий и пример подключения: `docs/INTEGRATION.md`.

## Автоматизация

Расписание, подписанный webhook, изменения карты, смена статуса задачи и завершение сессии.
Изменение документа и событие фиксируются вместе; для каждого правила сохраняются версия
сценария и входные данные. Позднейшая правка карты не изменяет старое событие.
Завершение архивной сессии может выполнить только ранее включённое завершающее правило
из доверенной очереди. Обычный запуск, webhook и расписание архивной карты запрещены.

Журнал: `Сценарий действий → Автоматизация → Доставка событий`. После пяти неудач доставка
останавливается; доступны до трёх ручных повторов и закрытие без повтора. Операции проверяют
проект и версию. Повтор доставки не равен повтору уже созданного запуска или подтверждению.
История доставки ограничена 500 записями; рабочие данные и архивные карты не удаляются.

## Проверка и сборка поставки

`npm run verify` заново собирает DS, запускает все Node-тесты, браузерные сценарии и
автономный HTML. Для браузерного прогона требуется Playwright с установленным Chromium
либо явные `MAPS_PLAYWRIGHT_MODULE` и `MAPS_CHROMIUM_PATH` разрешённой среды.
`npm run package` проверяет fingerprint исходников и отчёт PASS перед созданием ZIP.
Результаты: `evidence/final/`; скриншоты — `artifacts/`, только синтетические данные.

Серверные секреты не входят в карту. LLM требует настройки `MAPS_LLM_GATEWAY` и при необходимости
`MAPS_LLM_GATEWAY_TOKEN`; live-вызовы не заявлены проверенными. Без подключения шаг блокируется.
Production API Sprintique, совместное realtime-редактирование, общий таймер/голоса,
распределённая БД, проверка реальных сенсорных устройств и скринридеров в эту поставку не входят.
Контракты интеграции: `docs/INTEGRATION.md`, актуальный handoff: `docs/RELEASE-R4.md`.
