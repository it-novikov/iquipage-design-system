# Sprintique Board B2.1.1 — завершение обложек

Полная поставка переиспользуемого модуля и локального reference-стенда.
Она заменяет B2.1 только как следующий пакет и не перезаписывает прежние поставки.
Это не production-развёртывание Sprintique.

## Запуск и проверка

Откройте `Sprintique-Board-B2.1.1.html` в Chromium для автономного режима на
IndexedDB без внешних HTTP-запросов. Для локального сервера из `packages/maps`:

```sh
npm ci --ignore-scripts --no-fund --no-audit
npx --no-install playwright install chromium
npm run verify
npm run dev
```

CI использует Node.js 22. Тесты создают временные каталоги и браузерные профили;
рабочая `.dev-state` не используется. Упаковщик принимает только PASS текущего
fingerprint и включает отчёт `cover-finish`.

## Что исправлено после B2.1

- Последний выбор обложки побеждает при конкурентных ответах A/B/C.
- Снятие и выбор существующего вложения инвалидируют старые pending-замены.
- Отмена file chooser не отменяет уже принятое намерение; retry сохраняет ID,
  но не возвращает обложку после более позднего снятия.
- Удаление pending-строки и закрытие без сохранения блокируют позднее назначение.
- Preview становится ready только после decode; повреждённые bytes дают явное
  recoverable-состояние и не меняют сохранённый `coverAttachmentId`.
- Без `attachmentAdapter` документ и карточка объясняют недоступность хранилища,
  не оставаясь в бесконечной загрузке.
- Thumbnail decode можно повторить после rerender; поздний ответ после destroy
  не меняет новый DOM, а принадлежащие UI object URL освобождаются.

Все файлы остаются отдельными от JSON задачи. Выбор меняет только черновик;
задача и связи фиксируются одной записью с `baseRevision`. Снятие обложки не
удаляет вложение. Production adapter обязан реализовать авторизацию/ACL,
проверку содержимого, квоты, хранение и эксплуатационные политики.

## Граница готовности

Проверяется reusable module, HTTP reference server, IndexedDB и автономный HTML.
Не проверены production Sprintique API/auth/ACL/deploy, AV/CDR и облачный Blob,
live LLM, совместная работа, виртуализация и нагрузка, реальные Safari/touch/IME/
screen reader. Headless motion-проверка не является замером FPS на устройстве.
