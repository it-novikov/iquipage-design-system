# Sprintique Board B1 — проверяемая рабочая основа

Это промежуточная поставка доски: исправления компоновки, навигация, сортировка,
типы, базовая вложенность и Markdown-панель. Это НЕ завершение всего плана B1–B5
и НЕ production-внедрение Sprintique. План и приёмка: docs/board в корне архива.

## Запуск

```sh
cd Sprintique-Board-B1/packages/maps
npm test
npm run dev
```

Нужен Node.js 20+. Сервер: http://127.0.0.1:4317/. Данные — .dev-state/.
Не удаляйте эту папку ради обновления. На другой порт/базу указывают MAPS_PORT/MAPS_DATA_DIR.
Самостоятельные карты: ?standalone=1. Демонстрационный гость: ?guest=1.
Sprintique-Board-B1.html открывается без сервера и использует IndexedDB.
Серверные расписания и webhook в file-режиме не выполняются.

## В этой поставке

Один вертикальный скролл; шесть закреплённых заголовков; карточки не сжимаются.
Только счётчики колонок, без WIP, общего количества, bulk и сворачивания колонок.
Навигация: доска/карты; настройки рядом с профилем; автоматизация в настройках.
Типы task/bug/epic; подзадача определяется родителем, не четвёртым типом.
Дети одного статуса раскрываются под родителем; других — остаются в своих колонках.
У родителя три уникальных исполнителя детей и +N; источник в UI задачи отсутствует.
Родитель выбирается поиском в «Связях». Проверка циклов/проекта внутри транзакции.
Markdown DS, предпросмотр/редактирование, срок, тип, приоритет, защита несохранённого текста.

## Переиспользование

Экспорт `@iquipage/maps/board`: mountTaskBoard(root,{repository,project,canEdit,viewState}).
Импортируются стили DS одной сборки, общие `@iquipage/maps/styles.css` и
`@iquipage/maps/board/styles.css`. Владелец приложения предоставляет ограниченный по
высоте root, маршруты, аутентификацию, права и репозиторий. Board не создаёт профиль,
демонстрационные задачи или навигацию. `readyToLeave()` проверяется перед сменой экрана,
`destroy()` освобождает подписки и обработчики. Browser/Memory/File — локальные адаптеры,
не замена production ACL. Внедрение в другой host отдельно проверяется на реальном API.

## Проверка

`npm ci --ignore-scripts`, затем `npx --no-install playwright install chromium` и
`npm run verify`: сборка, Node-тесты, сохранённые Maps-сценарии, новая доска и offline HTML.
Только синтетические временные базы. Точные результаты: artifacts/final/verification.json.
`npm run package:board` запрещает упаковку при изменившемся fingerprint или FAIL.

## Следующие обязательные этапы, не готовые в B1

B2: отдельные именованные чек-листы, файловое хранилище, треды с решением, справочники
релизов/тегов и их UI, шаблоны base+type, полноценные связи depends/related.
B3: фильтры по релизу/тегам/исполнителю, сохранённые условия, виртуализация, полный
набор конкурентных/сетевых состояний перемещения и реальные устройства.
B4: отдельные map-task ссылки, карта правил, GitHub/GitLab inbox и интеграции,
типизированные действия/уведомления, ограниченные полезные LLM-сценарии.
B5: production host API/auth/ACL, нагрузка 1000/10000, frame p95/long tasks,
скринридеры, touch и проверка миграций/резервных копий. Высокий FPS не заявлен измеренным.
Бэклог и массовые действия — отдельное последующее ТЗ; их нет на доске.

Не переносить результаты B1 на весь этот scope. Проверки здесь — self-review,
не независимая команда агентов или пользовательское исследование.

Нормальный motion отдельно проверяется указателем: автоматическое место, ручной порядок,
общий auto-scroll и отмена. Записанный headless frame sample не доказывает FPS на устройстве.
