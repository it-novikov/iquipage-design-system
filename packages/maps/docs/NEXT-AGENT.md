## Приёмка интерфейса — первый незакрытый этап

Автор не смог открыть даже собственный localhost в управляемом Chromium: `net::ERR_BLOCKED_BY_ADMINISTRATOR`. Это BLOCKED, а не PASS. Не отключать browser policy и не обходить её data-URL/setContent/proxy. Запустить в разрешённой тестовой среде:

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r tests/requirements-ui.txt
python -m playwright install chromium
# в другом терминале уже работает npm run dev
MAPS_TEST_URL=http://127.0.0.1:4317 python tests/ui.py
```

Если браузер уже предоставлен инфраструктурой, `MAPS_CHROMIUM_PATH` задаёт его путь. Это выбор разрешённого executable, не изменение политики безопасности. Требования к Python и браузеру проверить на своей машине; автор не устанавливал пакеты глобально на Mac пользователя.

Скрипт пишет `artifacts/ui-report.json` и кадры light/dark/mobile. Сам скрипт тоже пока не прошёл полный browser-run: найденные ошибки селекторов нужно исправить, не ослабляя пользовательские сценарии. Вручную просмотреть реальные кадры. Проверить открытие из standalone и embedded, высоту холста, читаемость меню, overlay-фокус, переносы, touch, keyboard, IME и zoom браузера. Нельзя объявлять визуальную приёмку по одному `npm test`.

## Порядок работ

1. Сохранить полный пакет в разрешённую ветку и на компьютер, исключив базы, токены, node_modules, .venv, шрифты и screenshots с чужими данными.
2. В копии исходного репозитория выполнить `npm run build` для официального DS candidate из проверенной 05.7, затем повторить тесты и browser-run на этой сборке. HTML-reconstructed vendor из архива не объявлять официальным релизом.
3. Закрыть визуальные и функциональные browser-findings. Особое внимание: DOM/focus сохранение во время controlled commit, карточки/кнопки при маленькой высоте, последовательное закрытие dialog, конфликт внешней версии, изменение метаданных, отмена после отказа записи.
4. Изучить **реальный** Sprintique repo/router/auth/API, определить правильный продуктовый репозиторий совместно с владельцем. В пакете есть host callbacks и типы, но нет выдуманной реализации API Sprintique.
5. Встроить Maps под feature flag, оставив глобальную навигацию хозяину приложения. Не переносить shell примера целиком и не ломать task board/settings. Обновить один vendor boundary после регрессионной проверки.
6. Подключить storage и task-adapter платформы, затем LLM gateway. Проверить отказ/повтор/таймаут и отсутствие дубликатов реальных эффектов в отдельной sandbox-площадке.
7. Выполнить production-требования из AUTOMATION-BACKEND.md: ACL, queue/outbox, версии публикации, секреты, rate limits, идемпотентность и наблюдаемость.

## Известные границы, которые нельзя замаскировать

Сессии сохраняются и архивируются, но совместный сервер/CRDT и общий таймер/голосование не поставляются. Голоса локальные. Начальный workflow deterministic, не AI-ответ. Test LLM помечен simulation. Gateway не настроен, live-вызовы не выполнены. Сценарии только DAG с одним путём, без произвольного кода и параллельного исполнения. Продолжение создаёт копию, не редактирует исходный архив. Generic UI metadata writes сбрасывают внутреннюю историю DS; undo не является серверной компенсацией.

Весь текущий review — self-review по исходникам и автоматическим тестам. Другой агент/UX-команда не запускались; независимая проверка остаётся отдельной задачей. Не менять baseline lock или заявления о пройденных тестах, чтобы получить формальный PASS.
