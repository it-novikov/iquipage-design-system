# DS-GAP и публичный контракт кандидата

Решение владельца: утверждён план R1 и реализация с поправками R2. Исходный релиз 05.7 сохраняется. `npm run build` проверяет ВСЕ хеши его манифеста и собирает отдельный source candidate `0.6.0-maps.1` в `.build/ds-candidate`, затем помещает ESM/CSS в `dist/vendor`. Патчи исходника перечислены в build.mjs и проверяют единственность точки применения. Это не изменение прототипов после регистрации и не app-override внутренних селекторов.

## GAP-01: встроенная поверхность

`board.surfaceMode = 'embedded'` заполняет высоту контейнера, убирает только повторный заголовок самой доски и не создаёт модального fullscreen. Контекстная строка, инструменты, редактор и ошибки сохранения остаются. Библиотека исходно закрыта. Nav принадлежит host. Обычный `standard` сохраняется.

## GAP-02: внешняя справка и библиотека

Событие `iq-host-command` с `{command: 'help'|'guide'|'templates'|'session'|'fullscreen'}` передаёт встроенные entry points владельцу поверхности. Host открывает один диалог, а не обращается к `panel`, `renderPanel` или DOM доски.

## GAP-03: команды и атомарная интеграция

`command(id)` — ограниченный список действий из public-api.inc.js. `applyDocument(value, baseRevision, reason)` валидирует версию и использует ту же историю и controlled commit. `flush()` завершает ввод и возвращает отсутствие неподтверждённых данных. `saving`, `dirty`, `draftData` — публичные readonly-свойства для guard переходов и экспорта восстановления. Нельзя считать локальный preview сохранением. Последующие повторы/отмена/конфликт остаются штатными операциями DS.

## Граница совместимости

В одном приложении используется ОДНА собранная поставка DS: её core, advanced, whiteboard и CSS. Нельзя параллельно загружать baseline и candidate под разными URL. Host, уже использующий IQUIPAGE, должен обновить свою единственную vendor boundary после проверки; standalone использует candidate напрямую. Модуль не импортирует `dist/modules` или `src/modules`.

Все старые операции whiteboard сохраняются: заметки, области, изображения, фигуры, связи, импорт/экспорт, keyboard, undo, readonly и recovery. Workflow — отдельная модель; визуальное представление не является исполнительной семантикой. Полное покрытие baseline не заявляется новым self-review.
