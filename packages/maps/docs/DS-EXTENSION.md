# DS source candidate 0.6.0-board.7

База — неизменённая IQUIPAGE 05.7. Разрешение на реализацию плана с публичными расширениями получено в текущем пользовательском сообщении. Новые возможности не выдаются за уже существующий API оригинальной 05.7.

`npm run build` проверяет каждый файл MANIFEST.sha256, копирует поставку в `.build/ds-candidate`, применяет перечисленные однозначные патчи исходника и запускает исходную сборку. Оригинальные `design-system/` и release lock не меняются. Это не runtime monkeypatch и не внешний app CSS override.

- `surfaceMode: 'standard'|'embedded'`: встроенный холст занимает контейнер, убирается только повторный заголовок DS. Платформенная навигация не становится inert. Библиотека исходно закрыта.
- `iq-host-command`: встроенные help/guide/templates/session/fullscreen передаются приложению. У приложения нет обращения к panel/renderPanel/internal DOM.
- `command(id)`: ограниченный перечень существующих действий. `applyDocument(value,baseRevision,reason)` использует ту же историю и controlled commit.
- `saving`, `dirty`, `draftData`, `flush()`: публичные границы перехода и восстановления. Успешный локальный preview не означает запись.
- Внутренний main доски заменён section, чтобы embedded-компонент не создавал второй основной landmark.

CSS внутренних .wb-* применяется исключительно в файле источника кандидата `ds-extension/embedded.css`. В `src/maps.css` таких селекторов нет. Основной UI использует публичные iq-btn, iq-select, iq-dialog и токены DS. Локальный HTML-reconstructed dist — диагностический материал; официальная пересборка на Mac отдельно прошла для первого DS-checkpoint, но не является UI-приёмкой всей новой фичи.

Регрессии оригинальной поставки, пользовательская проверка, браузерная матрица и production cutover должны быть выполнены до смены единственного vendor boundary в рабочей платформе.

## Additive v3 contracts

`ds-extension/ux-v3.mjs` adds only owner-approved capabilities to the copied source tree. Public declarations: `ds-extension/v3-api.d.ts`, emitted alongside `dist/vendor`.

- `iq-image-crop.aspectRatio`: width/height, 0.1–10, default 1. The attribute is `aspect-ratio`; invalid attributes fall back to 1, invalid property assignments throw. Ratio changes center the crop and cancel pending acceptance. Source pixel coordinates remain the public `value`. Export `size` is the longest edge, so portrait output cannot exceed the existing 2048 px bound. The square avatar default and controlled acceptance protocol are unchanged. Task cover ratio is 12:5; only PNG/JPEG/WebP are accepted. The host stores original bytes plus normalized crop metadata; previews derive the same frame without destructive recompression.
- `iq-markdown-viewer.interactiveTasks` / `interactive-tasks`: opt-in, false by default. Checklist activation emits `iq-task-toggle` with exact original `source`, one-character `position`, next `checked`, and next `value`. It does not persist or mutate the viewer itself. Hosts accept only while their draft still equals source. Fenced code is excluded; uncertain source-to-render correspondence remains passive. This is reusable by any authorized editor host, not task-specific logic.
- `iq-whiteboard.editorMode`: `inline` default preserves the old editor; `host` emits `iq-edit-object` for object/connection identity without inserting a layout row or refocusing the canvas. The host performs changes through existing `prepareDocument` / `applyDocument` and controlled revision acceptance. Embedded host mode uses overlay library/command/footer geometry inside the candidate boundary. Shift+1 fits all; Shift+2 fits selection. Existing cursor-anchored wheel zoom, pan, Space and hand controls remain shared.

Evidence is generated by `tests/browser-ux-v3.mjs` and the isolated v3 DS fixture. Synthetic wheel events are not proof of physical trackpad pinch or Safari gesture handling. No production release or public API stability beyond this candidate is implied.

## Targeted editor follow-up (v3.1 preview)

User request: retain the actual DS Markdown editor, remove the separate description edit button, enter editing on preview-content click and return on outside click. `editor-preview.mjs` adds this opt-in interaction to the copied editor source; the task host uses only public properties/events, not internal editor DOM.

- `previewOnBlur` / `preview-on-blur` defaults false. When enabled, non-interactive preview content (or Enter/Space on the preview) opens editing. A click outside or keyboard Tab exit returns to preview after the intended action. Nested dialogs are excluded; composition finishes before preview. Links and task controls keep their own actions.
- `previewMode` explicitly selects a mode without replacing the textarea, its draft or undo history. Existing `preview()` and `focusEditor()` remain available. Read-only/disabled editors cannot activate editing. Height/opacity transitions honor reduced motion and cancel on rapid switches/disconnection.
- `interactiveTasks` / `interactive-tasks` defaults false. Native editor preview can toggle Markdown checkboxes, record undo and emit existing `iq-change`. Source positions use the textarea's normalized newlines; fenced code and ambiguous mappings stay passive. Rendering stays within the DS's safe Markdown boundary.
- `iq-preview-change` emits `{preview:boolean}` only when mode changes. Public declarations are in the emitted `v3-api.d.ts`.

Isolated acceptance: `tests/browser-editor-preview.mjs`; application/save acceptance: `tests/browser-board-interactions.mjs`, `tests/browser-ux-v3.mjs`. This replaces the previous app-owned viewer/editor composition, not the pinned IQUIPAGE 0.5.7 release.

## Targeted polish (v3.2 preview)

The requested neutral copy confirmation is an opt-in style in the source candidate: add `data-copy-tone="neutral"` to an existing `iq-btn` used with the unchanged `copyAtButton` API. Success uses neutral semantic tokens; failure retains the original error state. The task number and icon are separate buttons, with both activating the icon's confirmation so the number and header geometry remain stable.

Compact picker-only upload and Markdown footer actions remain pending explicit approval. They are not included in board.5. Native file rows and `iq-file-preview` are integrated without modifying their implementation; existing server upload/retry/cancel ownership stays in the application.

## Focus and selection follow-up (v3.3 preview)

The owner's explicit request supersedes the usual visible-focus requirement for buttons only. `ds-extension/button-focus.mjs` transforms copied CSS source selectors, excluding `button`, `.iq-btn`, role buttons and button-type inputs from focus-only presentation. Input/textarea focus remains, as do hover/pressed/selected/disabled states. Keyboard behavior is unchanged. This is an intentional accessibility exception, not WCAG approval. The manifest records the focus policy hash; the original release is not modified.

Editor preview-on-blur now distinguishes an independent outside click from a selection gesture. Pointerdown origin and movement survive until click; selecting text across the editor boundary and releasing outside must not switch modes. Pointer cancellation/window blur resets the gesture. Tab, IME and nested-dialog contracts remain unchanged. Tests use real mouse selection in addition to the earlier editor scenarios.

The same two upload/footer API choices remained pending in board.6. The explicit v3.4 request now authorizes the Markdown editor and its decision action; the compact upload variant remains separate.

## Compact Markdown editor and decision action (v3.4)

`density="compact"` is opt-in on the shared editor; the default remains `comfortable`. All formatting, history, checklist and preview behavior is preserved. Compactness adjusts spacing and minimum textarea height, not the tools or text size. A description with `previewOnBlur` has no redundant mode header or helper footer. The application uses the public property/attribute in task descriptions, discussion composition and replies.

`footerActions: MarkdownEditorAction[]` renders up to four controlled toggle buttons inside the native editor footer. `iq-editor-action` carries `{id, pressed, previous}` as an intent, not an automatic state change or save. Labels are text, not HTML; setters validate and copy the action data. Identity of the textarea and existing action controls is preserved. Disabled/read-only and reduced-motion behavior belong to the component. `tone: 'warning'` gives a selected decision action the existing semantic warning colors; no app CSS targets the editor internals.

Sprintique supplies one action, «Требует решения», and persists its selection in the existing `requiresResolution` field only when publishing a discussion. The draft is retained after failures; successful acknowledgement clears both text and flag. Lost-response retries reuse message identity, reject mismatched text or decision flags, and never silently duplicate or rewrite the original discussion. Published states use existing DS badges: neutral comment, warning unresolved, success resolved. This is a discussion property, not a new task status.

The reusable API and recipe are documented in [MARKDOWN-COMPACT.md](MARKDOWN-COMPACT.md).
