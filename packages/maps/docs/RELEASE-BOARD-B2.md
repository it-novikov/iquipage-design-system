# Sprintique Board B2 — содержание задач и проектные справочники

Промежуточная исполняемая поставка утверждённого плана. Не production-внедрение Sprintique.
Содержит Board B1, Maps R4 и новые функциональные сценарии; B1 не перезаписывается.

## Реализовано
- Несколько независимых именованных чек-листов со стабильными ID и отдельными пунктами.
- Проектные теги: имя, шесть семантических цветов DS, изменение, архив и восстановление.
- Проектные релизы: плановый/выпущенный, дата, создание из настроек и выбора в задаче.
- Теги и релиз выбираются по ID; переименование отражается в карточках без перезаписи задач.
- Базовый шаблон и шаблоны task/bug/epic с явным inherit/append/replace/exclude и итоговым превью.
- Смена типа не переписывает авторский текст и выбранный вручную приоритет. Применение шаблона явно подтверждается.
- Обсуждения: обычные комментарии или требующие решения, ответы, resolve/reopen; нерешённые первыми.
- Сохранение обсуждений независимо от основной формы задачи; сетевой повтор с тем же ID не дублирует сообщение.
- Зависимости и обычные связи с вычисляемыми обратными подписями. Ребро одно; циклы и чужой проект запрещены.
- Поиск и три видимых условия доски: исполнитель, релиз, теги; OR внутри поля, AND между полями, any/all для тегов.
- Транзакционная проверка ссылок в Memory/IndexedDB/FileRepository. Обновление IndexedDB 1 → 2 сохраняет старые данные.
- Обсуждения выводятся порциями по 20. Редактор ответа создаётся при раскрытии; сохранённый DOM сохраняет черновики.

## Запуск
Для просмотра без сервера открыть `Sprintique-Board-B2.html`. Хранилище — IndexedDB браузера.
Для сервера из распакованной папки:
```
cd packages/maps
npm test
npm run dev
```
Открыть `http://127.0.0.1:4317/`. Самостоятельные карты: `?standalone=1`.
Для гостевого демонстрационного лендинга: `?guest=1`. Это не реальная авторизация.

## Проверка
```
npm ci --ignore-scripts
npx --no-install playwright install chromium
npm run verify
npm run package:board
```
Проверки используют отдельные временные базы и синтетические данные. Точные результаты относятся
к fingerprint в `verification.json`, не к произвольной последующей правке.
`package:board` проверяет успешность текущей приёмки и совпадение fingerprint/HTML.

## Границы интеграции
Модуль `@iquipage/maps/board` получает repository, project, canEdit, canManageCatalogs и viewState.
canManageCatalogs по умолчанию false. Demo-shell явно включает управление справочниками.
UI-флаги не заменяют серверные роли: production-host обязан проверять права каждого запроса.
Repository должен поддерживать новые коллекции tags/releases/taskSettings/threads/taskLinks.
Форма задачи сохраняет task revision; обсуждения и связи имеют собственные ревизии.
Обновлённые типы данных находятся в `types/board.d.ts`.

## Не завершено в этой поставке
Файлы задач: blob-хранилище, загрузка/отмена/повтор/проверка/скачивание — следующий блок.
Здесь нет фиктивных загрузок или хранения файлов как base64 в JSON задачи.
GitHub/GitLab, расширенный редактор правил на карте, production API/auth/ACL, виртуализация,
нагрузочная проверка 1000/10000 задач, реальные touch/screen-reader/Safari остаются впереди.
Сервер тредов пока загружает записи проекта: порции UI не выдаются за курсорную серверную пагинацию.
Транспорт файлов и server pagination не считаются принятыми по зелёному B2-тесту.
Реальный LLM не подключён, оплачиваемых вызовов нет. Независимая команда агентов не запускалась.
Все проверки — автоматические и self-review; пользовательские интервью не проводились.
