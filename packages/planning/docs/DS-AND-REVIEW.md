# PN2 — дизайн-система, приёмка и следующие границы

## Реальная основа
Текущий approved UI: `iquipage-design-system` main `f3dd146`, UX v3.4 `37b2399`. Собираемый кандидат `0.6.0-board.7` сохраняет исходную IQUIPAGE 0.5.7; manifest исходных 297 файлов проверяется перед приёмкой. Ни один исходный файл DS/Maps в этом треке не изменяется.

| Поверхность | Применённый публичный компонент/композиция |
|---|---|
| Заголовок | `iq-work-header`, публичные атрибуты/slot actions |
| Список задач | Native table с `iq-work-table` и `iq-table-wrap`; это не ARIA treegrid |
| Выбор | `ui.check`, native input/indeterminate; отдельные состояния выбора и раскрытия |
| Поля, состояния | `iq-select`, `iq-date-field`, ui.field/badge/alert; отдельные правильные тона |
| Поиск получателя | `iq-remote-combobox` с provider, AbortSignal, cursor |
| Подтверждение | `iq-dialog`, documented native form composition; public show/close |
| Документ/доска/карта | Неизменённые модули v3.4 в demo host, одна repository-идентичность |

Общее расположение групп, indent и sticky задаёт продуктовая композиция через токены, а не override внутренних selector/Shadow DOM. Shared DS controls используют своё движение; новый набор motion-токенов не введён. Planning локально возвращает видимый keyboard focus на своих кнопках/ссылках через уже опубликованные focus tokens: это opt-in для нового экрана, не молчаливое изменение v3.4 других экранов.

## Открытые DS gates
**PL-DS-01:** сгруппированный виртуализированный hierarchical grid с range selection/DnD пока не предоставлен текущим публичным API как полноценный компонент. Native таблицы, checkbox, disclosure и страницы — честная первая композиция. Не заявляем виртуализацию/DnD готовыми и не ставим `role=treegrid` без клавиатурного контракта. Следующий этап — source-owned общий компонент у владельца DS.
**PL-DS-02:** независимая сборка библиотеки и отказ от string-patches текущего кандидата принадлежат соседнему треку. PN2 потребляет единственную совместимую границу, не форкает библиотеку.
**PL-DS-03:** настройки календаря, временные зависимости и согласованное управление датами релиза требуют PN5 и backend-команд. Рисованный локальный timeline их не заменяет.

## Находки, закрытые в этом проходе
**PN2-F01:** host не ожидал асинхронное уничтожение карты, поэтому её поздняя очистка удаляла уже созданный Planning. Исправлен `demo/app.js`: await lifecycle перед новым mount. Проверка перехода в реальную карту и обратно включена в browser.mjs.
**PN2-F02:** неизвестный результат сохранения мог преждевременно разблокировать закрытие формы. Busy и close берутся из состояния операции. Проверена потеря ACK после commit и чтение receipt без второго эффекта.
**PN2-F03:** невалидное подтверждение/receipt не должны стать успехом. Добавлена проверка размеров/полей preview и defensive copy; committed требует operation ID.
`evidence/failure.png` — исторический кадр PN2-F01 до исправления, не финальное состояние. Финальные снимки имеют имена `planning-{theme}-{width}.png`.
