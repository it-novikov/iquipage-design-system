# ИИ-подключения и агенты на сервисных аккаунтах

## Цель

Владелец хочет, чтобы сервисный аккаунт мог сам работать над задачами с помощью языковой модели по ключу API: Claude, ChatGPT или любой сервис, совместимый с OpenAI (OpenRouter и подобные). Администратор пространства добавляет ИИ-подключение, владелец аккаунта настраивает агента, а агент по назначению задачи или по кнопке читает её, действует инструментами MCP с правами аккаунта и отвечает в обсуждении. Результат проверяется тестами против фейковых провайдеров, гейтами и PR.

## Рамки

- **Входит:** миграции V20261001000064–067, сервер (подключения, шифрование ключей, исходящий HTTP, профиль агента, очередь и исполнитель запусков), UI настроек и действие в задаче, тесты, ADR 0005 и operations.md.
- **Не входит:** триггер по упоминанию (упоминаний в main нет), реальные ключи и вызовы реальных провайдеров, мобильная вёрстка, деплой.
- **Ограничения:** миграции только 064–067 (050 у планирования уже в main, 056–059 и 060–063 у веток уведомлений и упоминаний); только DS; тексты и ответы агента без списков.

## Приёмка

- [x] A1. ИИ-подключения пространства (anthropic, openai, openai_compatible): ключ только на запись, AES-GCM с версией ключа, «…last4», «Проверить» с реальным минимальным вызовом; права — workspace.settings
- [x] A2. Исходящий HTTP: таймауты, без редиректов, лимит ответа, запрет приватных/loopback/link-local адресов кроме явного allowlist; ключи не логируются, ошибки провайдера очищены
- [x] A3. Профиль агента на сервисном аккаунте: подключение, модель, инструкции ≤ 8000, триггеры (назначение, ручной запуск), лимиты шагов/токенов/запусков в час, вкл/выкл
- [x] A4. Исполнение: цикл вызова инструментов в нативном формате Anthropic/OpenAI через те же операции, что MCP, от имени сервисного аккаунта (права, RLS, аудит, потолок владельца); шаги, токены, идемпотентность; итоговый или аварийный комментарий; остановка
- [x] A5. UI: «ИИ-подключения» в настройках пространства, раздел «Агент» у сервисного аккаунта, «Запустить агента» и строка статуса в задаче; только DS, русский текст
- [ ] A6. Тесты (фейковые провайдеры, шифрование, SSRF, права, prompt injection, триггеры, лимиты, стоп), документация (operations.md, ADR), гейты npm test и verify-vnext зелёные, PR открыт и не слит

## Решения

- **D1** (2026-10-01) Исходящий HTTP закрепляет проверенный адрес (свой HTTP/1.1-клиент) — JDK HttpClient разрешал имя повторно, что открывало DNS rebinding
- **D2** (2026-10-01) Бюджет токенов на запуск (V20261001000066, 500 000 по умолчанию) — шаги и токены ответа не ограничивали цену запуска
- **D3** (2026-10-01) «Проверить» — одна попытка без повторов и CheckGate (по одной на подключение, 2 одновременно и 30 в минуту на пространство); при проверке ключ перешифровывается текущим ключом сервера
- **D4** (2026-10-01) Триггер по упоминанию не делаем — упоминаний в main нет
- **D5** (2026-10-01) Триггер по упоминанию сделан после слияния #40 (V20261001000067): запускает агента, только если у автора есть «Менять задачи»; отвечает в ветке упоминания; выключается в профиле
- **D6** (2026-10-01) Полное чтение длинного первого сообщения в ветке: сводка обрезана на 160 символов, ответ агента обрывался
- **D7** (2026-10-02) Запуск ограничен правами инициатора (решение владельца по #45): on_behalf_of в учётных данных runtime, app.on_behalf_of в auth.can_project и auth.can, пересечение в ProjectAccess.membership; потеря доступа инициатором останавливает запуск INITIATOR_ACCESS_LOST; запуск только от человека
- **D8** (2026-10-02) Миграции перенумерованы в V20261001000064–067: 050 планирования в main деплоится раньше, Flyway строгий по порядку
