# Публичный API и удалённый MCP-сервер Sprintique (api.iqui.page)

## Цель

Людям нужен программный доступ к Sprintique: скрипты с токеном и ИИ-ассистенты (Claude как custom connector и другие MCP-клиенты), которые работают с задачами как сервисный аккаунт человека (никогда не от его имени) и не шире его прав. Нужен публичный REST API на `https://api.iqui.page` с bearer-учётными данными вместо cookie и удалённый MCP-сервер `https://api.iqui.page/mcp` (Streamable HTTP) с авторизацией OAuth 2.1 по спецификации MCP: PKCE S256, метаданные ресурса и сервера авторизации, динамическая регистрация клиентов, согласие на sprintique.iqui.page, ротация refresh-токенов, привязка к ресурсу (RFC 8707), отзыв из настроек. Скрипты — токенами сервисных аккаунтов; персональных токенов нет (требование владельца 2026-09-30). Результат проверяется e2e-тестом полного потока и ручной проверкой официальным MCP-клиентом.

## Рамки

- **Входит:**
  - сервисные аккаунты с владельцем-человеком: OAuth-токены доступа и токены скриптов (скоупы `read`/`write`, срок, хэши, отзыв), роль reader/editor не выше владельца, финансы только явной выдачей, 50 на пространство, приостановка без владельца;
  - сервер авторизации OAuth 2.1: `/.well-known/oauth-authorization-server`, `/.well-known/oauth-protected-resource[/mcp]`, DCR (RFC 7591), authorize с согласием на sprintique.iqui.page, token (code + refresh с ротацией и обнаружением повтора), revoke (RFC 7009);
  - REST API `/api/v1/…` по bearer на api.iqui.page, cookie на API-хосте не авторизуют, CORS нет;
  - MCP Streamable HTTP (stateless) с инструментами: проекты, поиск задач, задача с обсуждением, создание, изменение полей (CAS + идемпотентность), смена статуса, комментарий, релизы, вехи, сводки карт;
  - настройки «Сервисные аккаунты» (список, аккаунт, проекты и финансы, токены, приложения, владелец, удаление), группа в участниках проекта; экран согласия с выбором/созданием аккаунта на DS;
  - лимиты по учётным данным, аудит с клиентом, метрики с ограниченными метками;
  - operations.md, ADR, тесты (unit, integration, HTTP e2e).
- **Не входит:** план работы агента из agent-bridge.md (карточка 20260927-sprintique-agent-work); Client ID Metadata Documents и загрузка чего-либо по URL клиента; CORS для браузерных клиентов; сессии MCP и серверные потоки SSE; ресурсы и промпты MCP; изменения nginx и выкладка.
- **Ограничения:** миграция `V20260929000027__…` (после 025/026 или перенумеровать перед слиянием); нет raw-SQL/generic execute; OAuth-токены не пересылаются другим сервисам; текст задач и комментариев — недоверенные данные; операции безопасности (агенты, участники, одобрения, токены) только в интерактивной сессии; Docker только через контекст `colima-sprintique-vnext-qa`; данные стенда и `output/infra/*` не трогать; не сливать.

## Приёмка

- [x] A1. Полный поток OAuth + MCP проходит e2e-тестом против сервера на настоящем PostgreSQL: регистрация → authorize с PKCE → token → initialize → tools/list → чтение → запись → refresh → revoke → отказ
- [x] A2. Bearer-запросы действуют строго как сервисный аккаунт под потолком владельца (RLS, роль, скоуп read/write, аудитория RFC 8707); cookie не авторизуют на API-хосте; операции безопасности требуют интерактивной сессии; тесты безопасности на каждое правило
- [x] A3. Сервер авторизации соответствует спецификации MCP: метаданные, DCR без загрузки URL, redirect только точное совпадение https/loopback, только S256, без implicit/password, ротация refresh с обнаружением повтора, отзыв; токены только хэшами
- [x] A4. Человек видит и отзывает подключённые приложения и токены своих сервисных аккаунтов в настройках; согласие на sprintique.iqui.page на компонентах DS, защищено от фрейминга и CSRF
- [x] A5. Лимиты по учётным данным, аудит «кто и каким клиентом» без содержимого в логах, метрики с ограниченными метками; operations.md и ADR описывают настройку и подключение Claude
- [x] A6. Гейты зелёные: npm test продукта, Kotlin unit+integration, корневой verify-vnext; ручная проверка на локальном сервере официальным MCP-клиентом; независимое ревью, P0/P1 закрыты; PR открыт, не слит
- [x] A7. Сервисные аккаунты: согласие создаёт или выбирает аккаунт; права не шире владельца (живая проверка и RLS); финансы только явной выдачей; управление — владелец, администраторы проекта и пространства; никакого управления доступом; приостановка без владельца; 50 на пространство; видны в участниках с владельцем; персональных токенов нет

## Решения

- **D1** (2026-09-29) MCP-транспорт свой (stateless Streamable HTTP 2025-11-25), не Java SDK 2.0.1 — SDK отдаёт клиенту и пишет в лог e.getMessage(), тянет Reactor; совместимость проверяем официальным TS SDK
- **D2** (2026-09-29) Протокольные эндпоинты OAuth в /api/oauth/* (форматы RFC, открытые метаданные DCR), интерфейсные — в /api/v1 с Zod-контрактами; authorize — страница интерфейса /oauth/authorize на sprintique.iqui.page
- **D3** (2026-09-29) Делегированный токен = права человека ∩ скоуп; операции безопасности (агенты, участники, одобрения, токены, пространство) только в интерактивной сессии — иначе токен выпускает себе замену или обходит одобрение человека
- **D4** (2026-09-29) OAuth выдаёт токены только для ресурса MCP; весь REST — персональным токеном из интерфейса — согласие должно описывать ровно то, что умеет приложение (ревью R2 P2-2)
- **D5** (2026-09-30) Приложения и скрипты действуют только как сервисный аккаунт (principal kind service) с владельцем-человеком, не от имени человека; персональные токены человека убраны (токены выдаются сервисному аккаунту) — требование владельца 2026-09-30; ничего не ломается: персональные токены не были выпущены
- **D6** (2026-09-30) Права сервисного аккаунта — роль проекта reader/editor, не выше роли владельца в проекте (живая проверка в ProjectAccess и в auth.can_project); сервисный аккаунт принадлежит одному пространству; владелец вне пространства или отключён — аккаунт не действует, при удалении владельца из пространства — suspended до переназначения или удаления; администратор проекта меняет роль или убирает аккаунт из своего проекта, администратор пространства — переназначает владельца и удаляет; финансы — никогда (can_read_finance требует human)
- **D7** (2026-09-30) D7 Администратор проекта удаляет сервисный аккаунт целиком, только если администрирует все его проекты; иначе убирает его из своего проекта — принято координатором 2026-09-30
- **D8** (2026-09-30) D8 Финансы сервисному аккаунту — только явной выдачей finance.read/finance.write на проект, не выше владельца (участник читает, администратор ведёт); лимит 50 на пространство; создаёт любой участник пространства — требования владельца 2026-09-30, заменяет «финансы — никогда» из D6
- **D9** (2026-09-30) D9 Назначение нового владельца отзывает все токены и подключения аккаунта; токен действует, только пока выпустивший его — текущий владелец (ревью R3 P1)
