# Task overview recovery: причина, варианты и границы

## Наблюдаемая проблема

[PR84](https://github.com/it-novikov/iquipage-design-system/pull/84) добавил обзор результата, нейтральное состояние вопроса без права ответить и оформление раскрытия свойств. Следующий [PR87](https://github.com/it-novikov/iquipage-design-system/pull/87) описывает исправление `focusin` на summary, но его фактический commit `220af664ef561d3f5ff1b873122281ef352e8f25` также удаляет эти части и модельный тест. Состав изменения проверен через Git API и полное дерево; причина широкого удаления не установлена. Восстанавливаем полезное ранее принятое поведение отдельным reviewable PR.

Человеку нужны три ответа на первом экране: кто работал, что требует внимания, куда перейти. Название шага без результата не позволяет оценить готовую работу. Требование «Нужно ваше решение» для участника без права отвечать направляет к недоступному действию. Отдельная надпись «Работа завершена» рядом с возвращённым или заблокированным шагом смешивает состояние запуска и следующий шаг.

## Решение

Вернуть из принятого PR84 literal preview результата, нейтральный вопрос и соответствующие CSS/модельный тест. Дополнительную status-строку показывать только для существующего question/review; сохранить основной fallback для действительно завершённой работы. Это использует текущие данные и действия, без новых состояний, ролей и вычисляемого резюме. Префикс результата160 и полное представление на вкладке Work сохранены. Context агента не объявляется авторством текста результата.

Сохраняем весь `task-dialog.js` точного main220af, включая исправление раскрытия, создание и четыре + семь свойств. Восстановление восьми удалённых исторических PNG для runtime исправления не требуется: они доступны в принятом commit4f181ff и отдельном evidence пакете. Происхождение и удаление не скрываются.

## Рассмотренные варианты

| Вариант | Следствие | Решение |
| --- | --- | --- |
| Оставить main как есть | Теряются результат и ясное объяснение вопроса; оформление раскрытия больше не соответствует принятому решению | Отклонён по наблюдаемой потере информации |
| Вернуть весь PR84 целиком | Вернул бы также ошибочный focusin и чужие изменения вне причины | Отклонён; восстанавливаются только нужные части |
| Сократить preview до64 и изменить композицию | Старый эксперимент показал выигрыш, но это другая актуальная версия и отдельное эстетическое решение | Отложен до двух текущих длинных кадров |
| Восстановить ограниченный обзор и разделить уровни status | Сохраняет полезный результат, действующие права и обычную навигацию | Выбран для текущего PR |

## Проверка и доставка

Пять настоящих Task-сценариев проверяют selected rejected/blocked step, буквальный review с экранируемым текстом, нейтральный вопрос и genuine complete. Ожидания заданы данными, без вызова проверяемых функций модели. Два длинных кадра — информационные; они не утверждают идеальную геометрию или принятие Compact. Все семь небольших случаев остаются постоянным companion существующего browser workflow, без нового режима runner. Полный CI сохраняет существующие gates.

Исходный scope на4f181ff и его local-only checks сохранены в `predecessor/`; они не выданы за проверку новой композиции. План v1 сохранён побайтно, v2 записан до восстановления runtime. Откат — revert этого PR; данных/миграций и внешних эффектов нет. Push/PR и продолжение реализации явно разрешены владельцем; merge/deploy не выполняются.
