## Проверено без замечаний

- Миграция: FORCE RLS на трёх таблицах; `can_read_finance` проверяет `kind='human'`, `disabled_at` и `can_project` (включая `app.project_limit`); `can_manage_finance` требует роль `admin`; обе функции SECURITY DEFINER с `search_path=pg_catalog`, `REVOKE … FROM PUBLIC`, EXECUTE runtime получает через afterMigrate. У runtime нет DELETE на финансах и UPDATE на версиях; worker доступа не получает. Триггеры: ревизия +1, переходы, неизменность voided, void меняет только state/reason, фиксированы идентичность и создание. Смена членства применяется сразу: политики читают `project_members` на каждом запросе.
- Kotlin: `projectWriteFence` (авторизация → блокировка проекта → проверка credential → повторная авторизация) идёт до разбора тела; порядок блокировок проект → ledger advisory → `FOR UPDATE` операции. Агенту `FINANCE_*` выдать нельзя (`AgentGrantController` содержит enum из 6 значений), а RLS дополнительно отсекает по `kind`. Outbox/audit несут только id и ревизию, `ProjectEvents` скрывает `finance-%` от агентов, SSE идёт через тот же `page`. Суммы: bigint, агрегаты numeric → text, результат точен. Сводка: voided исключены, posted и planned разделены, баланс и прогноз верны. Курсор привязан к фильтру, keyset согласован с индексом `(project_id, entry_date DESC, id DESC)`, `limit ≤ 100`.
- UI: только DS-классы и токены (`npm run check:styles` PASS), тексты экранируются, суммы форматируются через BigInt/decimal-строку, валюта по ISO-экспоненте.
