# Sprintique: фото профиля с телефона, без аватаров проекта и пространства, создание задачи в идущем релизе

## Цель

В проде фото профиля не загружается (PUT /api/v1/profile/avatar → 422 без подробностей). Владелец решил убрать аватары проекта и пространства. На доске во время идущего релиза новая задача уходит в бэклог, хотя её ждут в релизе. Нужно: фото с телефона и компьютера загружаются, аватаров проекта больше нет, новая задача на доске попадает в идущий релиз после явного подтверждения, которое человек может отключить и вернуть в настройках. Плюс от координатора: MCP list_projects отдаёт пустое имя пространства сервисному аккаунту.

## Рамки

- **Входит:** причина и исправление 422 фото профиля, нормализация фото в браузере, лог кода отказа; удаление аватаров проекта (UI, API, контракты, документация, миграция с очисткой активов штатным asset.gc); создание задачи с доски в активном релизе с alert-диалогом и личной серверной настройкой; имя пространства в MCP list_projects для сервисного аккаунта.
- **Не входит:** изменение компонентов DS (пробелы — DS-GAP); новые права на состав релиза (ветка access-invites); аватары пространств — в vNext их нет (импортёр их не переносил).
- **Ограничения:** Docker только в контексте colima-sprintique-vnext-qa; данные стенда, output/infra и чужие ресурсы не трогать; номера миграций 033+ после access-invites (030–032) — могут потребовать перенумерации до слияния.

## Приёмка

- [ ] A1. Фото профиля: обычные фото с телефона и компьютера (HEIC/HEIF, JPEG > 10 МБ, > 40 Мп, PNG с альфой, EXIF-поворот, WebP, GIF) загружаются через UI; причина 422 найдена и исправлена; регрессионный тест на неудачный случай; код отказа пишется в лог; понятные сообщения по-русски для неподдерживаемых файлов
- [ ] A2. Аватары проекта и пространства удалены целиком: UI, API, контракты, документация; буквенные метки остаются; фото людей сохранены; прямая миграция удаляет данные, объекты S3 чистятся штатным путём или описан ручной шаг
- [ ] A3. Создание задачи на доске при идущем релизе кладёт её в этот релиз после подтверждения в диалоге DS с «Больше не показывать»; личная настройка на сервере возвращает подтверждение; правила планирования (допуск, CAS/идемпотентность, права; закрытые релизы не получают задач; без права — в бэклог с сообщением); клавиатура, a11y, тёмная тема, телефон
- [ ] A4. Гейты зелёные без пропусков: npm test продукта, Kotlin unit+integration, корневой verify-vnext; проверка на локальном запуске; независимое ревью, P0/P1 закрыты; PR открыт, не слит

## Решения

- **D1** (2026-09-30) Причина 422 фото: в проде /tmp смонтирован noexec, webp-imageio распаковывает libwebp в java.io.tmpdir, System.load падает (UnsatisfiedLinkError), bounded() превращает это в 422 IMAGE_DECODE. Воспроизведено в контейнере sprintique-probe:board-release: noexec → 422 IMAGE_DECODE на WebP из Chrome и PNG из Safari, exec → ok. Затрагивает и превью изображений задач/карт
- **D2** (2026-09-30) Исправление фото: нативная библиотека кладётся в образ (/app/native) и находится через java.library.path; /tmp остаётся noexec — жёсткость контейнера не ослабляем
