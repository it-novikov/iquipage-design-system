# Упоминания в обсуждениях и входящие сервисных аккаунтов

## Цель

Владелец: «нужно сделать возможность тэгнуть человека / сервисный аккаунт в проекте в тредах у задачи. И у сервисных аккаунтов чтобы также собирался список необработанных уведомлений». Сейчас упоминание — только набранное имя (PR #40), а сервисные аккаунты уведомлений не получают совсем. Нужен выбор участника по @ в редакторе обсуждения (часть DS), устойчивый к переименованию токен и входящие сервисного аккаунта, которые агент читает через MCP и REST, когда возвращается к работе.

## Рамки

- **Входит:** DS-автодополнение упоминаний и плашка в Markdown (vnext.29); токен и разбор в Kotlin; сервисные аккаунты как получатели; MCP и REST входящих; счётчик в настройках; адресат запроса — сервисный аккаунт.
- **Не входит:** доставка (каналы и пакеты — ветка feature/notification-channels), запуск агентов по упоминанию (feature/ai-connections), редактирование сообщений (его нет: сообщения только добавляются).
- **Ограничения:** миграции V20261001000060–063; не трогать app.raise_notification и таблицы доставки (их меняет ветка каналов); FORCE RLS; без маркированных списков в тексте продукта.

## Приёмка

- [ ] A1. В обсуждении задачи (новое, ответ) @ открывает DS-список участников проекта: люди, затем «Сервисные аккаунты» с владельцем; фильтр без учёта регистра и с кириллицей; ↑↓ Enter/Tab Esc и мышь
- [ ] A2. Выбор вставляет токен @[Имя](user:id), который переживает переименование; сообщение, превью и предпросмотр показывают спокойную плашку упоминания; токен не участника — обычный текст, уведомлений нет; старое совпадение по имени остаётся; не больше 20 получателей
- [ ] A3. Автодополнение — переиспользуемая часть DS в libraries/iquipage, обратно совместимая, выпуск 0.6.0-vnext.29 принят в продукте
- [ ] A4. Сервисный аккаунт получает уведомления mention, assigned, request, deadline как человек; своё действие не уведомляет, действие владельца уведомляет; без Telegram и почты
- [ ] A5. MCP list_inbox (старые первыми, страницы, unreadOnly по умолчанию, обёртка untrusted) и mark_inbox_read (ids или upTo), REST /api/v1/inbox; описания инструментов просят начинать работу с входящих
- [ ] A6. Число непрочитанных у аккаунта в настройках сервисных аккаунтов; RLS: аккаунт видит только свои и только в доступных проектах
- [ ] A7. Миграции только V20261001000060–063, FORCE RLS, jOOQ и контракты обновлены; тесты и документы; гейты DS и продукта зелёные
