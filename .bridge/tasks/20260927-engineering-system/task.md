# Инженерная система и мост для агентов

## Цель

У проектов нет общей основы, кроме дизайн-системы: стек, архитектура, имена, тесты и процесс выбираются заново, а агенты тратят токены на изучение истории чата при каждой передаче работы. Нужна инженерная система для всех будущих проектов и мост — формат и инструмент, через который агенты и люди передают задачу друг другу по триггеру (лимит, ошибка API) без потери контекста. Результат: `engineering/` с документами и ADR, работающий CLI моста с тестами, хуки Claude Code, независимое ревью системы и исправления по нему.

## Рамки

- **Входит:** принципы, стек (линия Jarnee), архитектура, имена, качество кода, тестирование, безопасность, процесс по уровням риска, ревью, ADR; мост: формат, протокол, CLI, эстафета, хуки, JSON Schema модели; проект интеграции моста в Sprintique; два независимых ревью.
- **Не входит:** перенос бэкенда (отдельная карточка `20260927-kotlin-backend`); реализация моста в продукте (`20260927-sprintique-agent-work`); синхронизация CLI с API платформы.
- **Ограничения:** CLI без зависимостей, Node ≥ 22; карточки в git без секретов; merge делает владелец.

## Передача

- **Состояние:** Документы, мост (18 тестов), хуки, ADR 0001–0003 и проект интеграции с Sprintique написаны, не закоммичены.
- **Сейчас:** S5 — подготовка независимого ревью.
- **Дальше:** Закоммитить, запустить два ревью с чистым контекстом (процесс и мост; стек и архитектура), исправить P0–P2.
- **Незакоммичено:** engineering/, .bridge/, .claude/settings.json, AGENTS.md, CLAUDE.md, products/sprintique/docs/agent-bridge.md
- **Ловушки:**
  - Корень репозитория без package.json: мост вызывается как `engineering/bridge/bin/bridge`, не через npm.
  - Хук Claude Code должен всегда завершаться с кодом 0, иначе ломает сессию.
- **Проверка:** `cd engineering/bridge && npm test && cd ../.. && engineering/bridge/bin/bridge check`
