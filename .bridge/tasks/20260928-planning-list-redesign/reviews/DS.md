## Итог (5 предложений)

Список Планирования строит контейнеры релизов, факты, дерево подзадач, пустые состояния и счётчики собственными `.pn-*` классами, хотя для каждого из них в DS уже есть публичная композиция (`.iq-settings-panel`/`.iq-settings-row`, `dl.iq-settings-facts`, `.iq-work-list-identity`/`.iq-work-list-context`, `.iq-empty.compact`, `.iq-section-count`). Иерархия читается плохо: одна вертикальная линия на уровень без продолжения линий предков, отступ 36px на уровень, подложка строк через `color-mix`, «3 подзадачи» без готовности — при том, что доска и `iq-relation-map` уже говорят «Подзадачи N из M» с `ui.progress`. Аватар исполнителя — `ui.avatar(initials,1)`: всегда один тон, без фото, с дублирующим `role="img"` внутри кнопки, тогда как `ui.personAvatar` даёт стабильный тон и фото. В a11y и мобильной раскладке разметка строки расходится с контрактом `work-list.css` (`.pn-row-identity` вместо `.iq-work-list-identity`, «Без даты» без `data-empty`, ручка перетаскивания <44px, `thead` первой карточки — единственный видимый заголовок колонок). Инженерно: `planning.css` содержит 6 мёртвых и 7 дублирующих правил, `lastChildren` — O(n²), а ключи рендера через `JSON.stringify(controller.filters/capabilities)` пересоздают `TableWindow` каждой группы при любом изменении фильтра.
