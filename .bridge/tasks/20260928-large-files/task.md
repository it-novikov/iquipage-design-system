# Большие файлы: видео, документы и архивы до 2 ГиБ

## Цель

Владельцу нужно хранить в задачах и на картах видео, документы, архивы и крупные изображения. Сейчас медиа-модуль принимает только PNG/JPEG/WebP/PDF/текст/ZIP до 10 МиБ, читает тело целиком в память (`ByteArray`), держит транзакцию и блокировку проекта на время записи в S3 и отдаёт файл целиком без Range, поэтому видео нельзя ни загрузить, ни посмотреть. Результат: файлы до 2 ГиБ загружаются потоком через API в приватный S3 (multipart), расширенный список типов с проверкой подписи и безопасным запасным `application/octet-stream`, отдача с Range и воспроизведение видео в задаче; проверено тестами против реального S3 и в браузере.

## Рамки

- **Входит:**
  - потоковая загрузка до 2 ГиБ с multipart в S3, проверкой подписи по первым байтам, SHA-256 и размера по потоку;
  - новые типы и запасной octet-stream; правила inline/attachment;
  - потоковое скачивание с Range, окно частичного ответа, перепроверка прав;
  - ограниченная обработка изображений (байты и пиксели), изображения без превью в задаче;
  - UI задачи: хеш в браузере по частям, прогресс, отмена, ошибки до отправки, видео в DS-поверхности, скачивание без Blob в памяти;
  - миграция 026, лимиты, документация (nginx, lifecycle), тесты.
- **Не входит:** докачка оборванной загрузки (возобновляемые части), прямая загрузка в S3 по presigned URL, транскодирование видео и постеры на сервере, аудиоплеер, превью офисных документов, изменение DS (разрыв записывается как DS-GAP).
- **Ограничения:** один экземпляр API (1,5 ГиБ, MaxRAMPercentage=75) за nginx; приватный bucket FirstVDS, path-style, `SPRINTIQUE_STORAGE_PREFIX`; миграция `V20260929000026` сливается после `V20260929000025` из `feature/project-finance`; данные стенда и `output/infra` не трогаем.

## Решения

- **D1** (2026-09-28) Загрузка потоком через API в S3 multipart, а не presigned direct-to-S3 — тот же origin, CSRF, RLS и лимиты; подпись, размер и SHA-256 проверяются до CompleteMultipartUpload, так что в bucket не попадают непроверенные байты; bucket без CORS и не виден браузеру
- **D2** (2026-09-28) SHA-256 по-прежнему считает браузер до резервирования (WebCrypto до 64 МиБ, потоковый JS-SHA-256 по частям для больших) — сохраняет контракт резервирования, идемпотентность и адресацию объекта по содержимому без копирования в S3
- **D3** (2026-09-28) Скачивание: Content-Disposition inline только для PNG/JPEG/WebP/GIF и видео, остальное attachment; частичные ответы ограничены 16 МиБ, чтобы приостановленное видео не держало запрос; права перепроверяются перед каждым окном 16 МиБ
- **D4** (2026-09-28) Квота проекта поднята с 5 до 20 ГиБ — при файлах до 2 ГиБ прежняя квота вмещала два видео; окончательное значение — решение владельца
- **D5** (2026-09-28) DS-GAP: iq-file-preview работает только с локальным File и не принимает URL, в DS нет медиаплеера — видео из хранилища показывается нативным <video controls> в диалоге DS; нужен режим iq-file-preview для удалённого источника

### Проработка

1. **Сценарии и роли.** Автор загрузки (писатель задач или карт, администратор каталога для аватара проекта) резервирует файл, загружает тело, прикрепляет к задаче. Читатель проекта смотрит и скачивает прикреплённое. Пограничные случаи: 0 байт, ровно 2 ГиБ, больше 2 ГиБ, подпись не совпадает, повторная загрузка того же тела, отмена посреди загрузки, отзыв сессии во время скачивания.
2. **Данные и доступ.** RLS, политика проекта и владелец загрузки проверяются как раньше; S3 только с серверными ключами, ключ объекта строит сервер (`assets/<project>/<asset>/<sha256>/<variant>`). Объект под ключом появляется только после совпадения SHA-256 и размера с резервированием, поэтому содержимое по ключу всегда проверено.
3. **Ошибки и повторы.** Отказ по содержимому (подпись, хеш, истечение) — карантин в короткой транзакции, как раньше. Обрыв связи — multipart отменяется, резервирование остаётся, клиент повторяет. Параллельные загрузки одного id пишут одинаковое проверенное содержимое. Завершение multipart и фиксация `ready` идут под блокировкой строки, поэтому очистка не пропустит поздний объект.
4. **Лимиты.** 2 ГиБ на файл, части 8 МиБ, 8 одновременных загрузок, отдельный счётчик скачиваний (32), окно частичного ответа 16 МиБ, превью до 32 МиБ и 40 Мп, квота проекта 20 ГиБ.
5. **Зависимости.** S3: multipart (Create, UploadPart, Complete, Abort, ListMultipartUploads) и GET с Range — есть у Garage и S3-совместимых сервисов; при отказе S3 загрузка отменяется, скачивание обрывается. nginx должен пропускать 2 ГиБ без буферизации.
6. **Миграция и откат.** `size` → `bigint`, проверка 1..2147483648. Откат схемы возможен, пока нет файлов больше 10 МиБ; после них — только вперёд. Ключи объектов не меняются, старые файлы читаются как раньше.
7. **Альтернативы.** Presigned multipart напрямую в S3 разгружает API, но требует CORS на bucket, открывает браузеру адрес хранилища (CSP connect-src), переносит проверку подписи и хеша на после записи (плохие байты попадают в bucket), а подписанные URL становятся носителями прав. Через API — тот же origin, CSRF, RLS и лимиты, проверка до фиксации объекта; трафик одного экземпляра для команды приемлем. Возобновляемые части — точка расширения.
