# План работы агента в задачах Sprintique (мост в продукте)

## Цель

Когда на платформу придут агенты, им и людям нужно вести работу над задачей так, чтобы любой участник продолжил с того же места: другой агент после сбоя провайдера, человек или агент из репозитория разработчика. Нужно встроить модель моста (`bridge/1`) в задачу Sprintique: план с шагами и критериями, «Передачу», решения, аренду, эстафету агентов проекта, выгрузку и загрузку `task.md`. Передача не должна становиться путём расширения прав одного агента через другого. Это одна из ключевых функций платформы для агентов.

## Рамки

- **Входит:**
  - модель и API плана работы;
  - права людей и агентов;
  - одобрение шагов при `risk: high`;
  - пометка автора и одобрение указаний от агента к агенту;
  - раздел «План работы» в задаче;
  - цепочка агентов проекта;
  - `agents/me/work`;
  - передача по причине завершения и по истечению аренды;
  - выгрузка и загрузка `task.md`.
- **Не входит:** исполнение агентов на стороне платформы; хранение ключей провайдеров моделей; уведомления по почте и webhook; синхронизация CLI с API (этап 4, отдельная задача).
- **Ограничения:** реализация на Kotlin-бэкенде после `20260927-kotlin-backend`; текст плана — данные, не инструкции; имена по конвенции; интерфейс только на компонентах IQUIPAGE.

## Приёмка

- [ ] A1. Агент и человек ведут план в задаче через API; права из таблицы проекта соблюдаются и покрыты тестами по обязательному списку
- [ ] A2. Карточка из репозитория загружается и выгружается; непереносимые поля перечислены в ответе, остальное совпадает
- [ ] A3. Указания агента не становятся указаниями другому агенту без одобрения человека; тест на эскалацию прав через передачу
- [ ] A4. При лимите или истечении аренды следующий агент цепочки получает задачу через `agents/me/work` со сводкой
- [ ] A5. Раздел «План работы» в задаче проверен в браузере, iquipage-review без P0/P1

### S4. Эстафета агентов проекта [todo]
- **Что:** Цепочка агентов в настройках проекта; `taskId` и `relayed_from_run_id` у запусков; передача по причине завершения и истечению аренды; событие `task.work.handoff`.
- **Как:** Расширить agent-runs, не меняя смысл `parent_run_id`.
- **Зачем:** Сбой провайдера не теряет работу.
- **Приёмка:**
  - [ ] Тест: запуск завершён с `limit`, следующий агент получает задачу и сводку через `agents/me/work`
  - [ ] Тест: истекшая аренда даёт передачу с причиной `timeout`
- **Покрывает:** A4
