# Быстрая навигация между разделами

## Цель

Владелец сообщает, что в продакшене (sprintique.iqui.page) навигация между разделами (Рабочий стол, Доска задач, Планирование, Карты, Финансы, Настройки, карточка задачи) идёт очень долго. Нужно найти настоящую причину на стенде с объёмом как в продакшене, измерить каждый переход до и после, устранить главные причины без изменения поведения, прав и интерфейса и открыть PR.

## Рамки

- **Входит:** web/main.js, web/repository.js, секции (доска, карты, финансы, настройки, Рабочий стол), выдвижная карточка задачи, тесты.
- **Не входит:** заголовки страниц планирования и Рабочего стола (их параллельно меняет другая ветка), продакшен, другие worktree, редизайн.
- **Ограничения:** миграции не понадобились; если понадобятся — с V20261001000077.

## Приёмка

- [x] A1. Причина медленной навигации найдена и подтверждена замерами на стенде с объёмом как в продакшене
- [x] A2. Переход между разделами и открытие задачи требуют меньше последовательных запросов, поведение, права и интерфейс прежние
- [x] A3. Замеры до и после по каждому переходу и горячим эндпоинтам в PR
- [x] A4. Гейты npm test и verify-vnext зелёные, PR открыт и не слит

## Решения

- **D1** (2026-10-03) Без миграции — горячие эндпоинты переходов на стенде с 450 задачами тратят на SQL 0,2–6 мс, кроме снимка Рабочего стола (~50–65 мс), который уже исправлен в #48 и укладывается в бюджет теста ёмкости; узкое место — число последовательных запросов на клиенте
- **D2** (2026-10-03) Поток событий проекта остаётся открытым между разделами, а на время монтирования его события удерживаются и отдаются после — это та же семантика, что прежний водяной знак events/head перед монтированием, но без лишнего RTT и переподключения
