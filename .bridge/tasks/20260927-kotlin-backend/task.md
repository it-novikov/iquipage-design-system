# Перенос бэкенда Sprintique на Kotlin и Spring Boot

## Цель

Бэкенд Sprintique написан на Node/Fastify: 282 КБ плотного TypeScript, около 3000 строк и 100 маршрутов. Инженерная система закрепляет для всех проектов Kotlin и Spring. Нужно переписать бэкенд на базовый стек (Kotlin 2.3.21, JDK 25, Spring Boot 4.1, jOOQ, Flyway, OpenAPI 3.1) по правилам архитектуры и имён.

Внешнее поведение HTTP API сохраняется один в один: интерфейс, данные и все сценарии тестов работают без изменений. Результат:

- Kotlin-приложение и воркер в `products/sprintique/server`;
- каждый сценарий текущих тестов проходит против него — по HTTP или как тест Kotlin;
- TypeScript-бэкенд удалён.

Этот каркас служит эталонным проектом линии стека.

## Рамки

- **Входит:**
  - все маршруты `/api/v1`, `/auth/*`, `/health`, `/ready`, `/internal/metrics`, статика;
  - RLS и роли базы;
  - идемпотентность, CAS, аудит и outbox;
  - OIDC и dev-login;
  - S3 и обработка изображений;
  - воркер заданий и SSE;
  - OpenAPI и Swagger UI;
  - скрипты запуска, тестов и стенда;
  - документация продукта.
- **Не входит:** новые функции продукта; изменения интерфейса; изменения схемы данных сверх перевода миграций в формат Flyway; выкладка.
- **Ограничения:**
  - Внешние имена API сохраняются: коды ошибок, пути, заголовки, поля JSON, имена схем OpenAPI (ADR продукта 0001, «Внешние имена»).
  - Схема базы та же: миграции 001–020 переводятся без изменения SQL.
  - Docker не используется: базу даёт изолированный кластер `scripts/test.mjs`.
  - Роль приложения без владения таблицами и без BYPASSRLS.
  - Dev-login существует только в `local`-артефакте.
  - Секреты не попадают в git.

- **D1** (2026-09-27) Внешние имена API сохраняются, конвенция действует внутри кода. Переменные окружения и имена миграций меняются: production нет, пользователи — только скрипты репозитория (R2 F3).

- **D6** (2026-09-27) check-local-oidc перенесён из S6 в S14 — проверке нужен локальный стенд с Kotlin-сервером, а стенд переключается в S14
