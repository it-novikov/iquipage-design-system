# Перенос бэкенда Sprintique на Kotlin и Spring Boot

## Цель

Бэкенд Sprintique написан на Node/Fastify: 282 КБ плотного TypeScript, около 3000 строк и 100 маршрутов. Инженерная система закрепляет для всех проектов Kotlin и Spring. Нужно переписать бэкенд на базовый стек (Kotlin 2.3.21, JDK 25, Spring Boot 4.1, jOOQ, Flyway, OpenAPI 3.1) по правилам архитектуры и имён.

Внешнее поведение HTTP API сохраняется один в один: интерфейс, данные и все сценарии тестов работают без изменений. Результат:

- Kotlin-приложение и воркер в `products/sprintique/server`;
- каждый сценарий текущих тестов проходит против него — по HTTP или как тест Kotlin;
- TypeScript-бэкенд удалён.

Этот каркас служит эталонным проектом линии стека.

## Рамки

- **Входит:**
  - все маршруты `/api/v1`, `/auth/*`, `/health`, `/ready`, `/internal/metrics`, статика;
  - RLS и роли базы;
  - идемпотентность, CAS, аудит и outbox;
  - OIDC и dev-login;
  - S3 и обработка изображений;
  - воркер заданий и SSE;
  - OpenAPI и Swagger UI;
  - скрипты запуска, тестов и стенда;
  - документация продукта.
- **Не входит:** новые функции продукта; изменения интерфейса; изменения схемы данных сверх перевода миграций в формат Flyway; выкладка.
- **Ограничения:**
  - Внешние имена API сохраняются: коды ошибок, пути, заголовки, поля JSON, имена схем OpenAPI (ADR продукта 0001, «Внешние имена»).
  - Схема базы та же: миграции 001–020 переводятся без изменения SQL.
  - Docker не используется: базу даёт изолированный кластер `scripts/test.mjs`.
  - Роль приложения без владения таблицами и без BYPASSRLS.
  - Dev-login существует только в `local`-артефакте.
  - Секреты не попадают в git.

## Передача

- **Состояние:** S1–S5 готовы; тестов Kotlin: 18 модульных, 9 интеграционных.

  Инвентаризация тестов — в docs/test-parity.md.
- **Сейчас:** пауза: исправление R4 моста в ветке инженерной системы
- **Дальше:** S6 — идентичность: учётные данные, CSRF, сессия, выход, dev-login в source set local, OIDC через Nimbus, агенты

  Затем `./gradlew check`.
- **Незакоммичено:** нет
- **Рабочая копия:** 1 файл(ов): .impeccable/ (2 files changed, 6 insertions(+), 4 deletions(-)) · HEAD 37c4b2f
- **Ловушки:**
  - pg_ctl и тесты падают без `LC_ALL=C LANG=C`.
  - Docker-контекст по умолчанию (colima default) сломан. Продукт запрещает трогать VM по умолчанию, поэтому тесты Kotlin берут базу из `scripts/test.mjs`.
  - Кластеры PostgreSQL для тестов — только `sprintique-test-*` (есть guard). Homebrew postgresql@16 и кластер Codex на порту 4391 не трогать.
  - Фронтенд импортирует zod-контракты из `contracts/`: их не удалять.
  - Spring Boot 4: автоконфигурации лежат в пакетах `org.springframework.boot.<модуль>.autoconfigure`.
  - Имена переменных окружения задаются явно в application.yaml: relaxed binding даёт `SPRINTIQUE_DATABASE_RUNTIMEROLE`.
  - Старый драйвер `pg` отдаёт int8 и numeric строками, а timestamptz — Date. Row повторяет это, иначе ответы разойдутся.
  - ktlint: профиль intellij_idea; ktlint_official ломает цепочки и when-ветки
  - pg_dump 18 добавляет \restrict со случайным ключом — сравнение схем его вырезает
  - java_home -v 25 без JDK 25 молча отдаёт другую версию: JDK проверяется по файлу release
  - Flyway нужно ≥2 соединения в пуле
  - Regex.matches в Kotlin требует совпадения всей строки; для суффикса — containsMatchIn
- **Проверка:** `cd products/sprintique/server && ./gradlew check`, затем из `products/sprintique`: `LC_ALL=C LANG=C TEST_S3_CONFIG=$PWD/output/infra/storage.json npm test`

## Решения

- **D1** (2026-09-27) Внешние имена API сохраняются, конвенция действует внутри кода. Переменные окружения и имена миграций меняются: production нет, пользователи — только скрипты репозитория (R2 F3).
- **D2** (2026-09-27) Интеграционные тесты Kotlin берут базу из изолированного кластера `scripts/test.mjs`, а не из Testcontainers (R2 F12). Так соблюдается правило продукта про Docker.
- **D3** (2026-09-27) Dev-login и тестовые маршруты стенда живут в source set `local`, которого нет в production-артефакте (R2 F13).
- **D4** (2026-09-27) Архитектурные тесты — ArchUnit (R2 F9).
- **D5** (2026-09-27) Порт SQL один в один: выверенные запросы переносятся как SQL с позиционными параметрами через слой `Transaction`, который повторяет типы node-pg. jOOQ-DSL — для нового и простого кода.
