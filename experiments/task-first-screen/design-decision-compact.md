# Compact summary: отдельная проба после actual narrow regression

2026-10-12. Решение root после независимого визуального разбора; реализация GPT-6 Astra. **Это новый экспериментальный вариант `vt1-compact`, не переименование исходного VT1 и не production acceptance.**

## Наблюдение и выбор

В immutable attempt2 (artifact `11739432628`, source `0c74ab69487fa5d7ec66ead92400043901e85af2`) все 14 initial frames были CAPTURED. На лично просмотренной паре 390×844 long review высота summary выросла с 184.77 до 360.72 px. В VT1 срок оказался частично под footer, приоритет и «Другие свойства» — ниже. Низ disclosure 906.16 px при нижней границе scrollport 793 px: дефицит около 113.16 px. Нового результата рендера этот документ не предсказывает.

Для человека, проверяющего работу агента, остаются полное название выбранного шага, явное состояние и прежний переход к этому же `review:id`. Планирующему работу нужно вернуть читаемые срок/приоритет и оценить доступ к остальным свойствам. Название Task не заменяет предмет выбранного шага, а новый result не должен вытеснять прямые свойства за счёт повторяющихся подписей.

Автор render и независимый reviewer согласились начать с **A: компактного выражения того же смысла внутри прежней рамки**. Root утвердил пробный бюджет 64 Unicode code points, включая многоточие. Это ограничение excerpt, **не гарантия двух строк, полного предложения или полноты смысла**.

- Question/review: одна естественно переносимая строка state + имя агента из той же существующей session. Например, «Результат на проверке · Кодекс». Повтор «Работа агента» уже присутствует во вкладке.
- Полное название выбранного шага или вопроса сохраняется. Work focus, порядок выбора, grants, данные и существующее действие не меняются.
- CTA находится перед preview в DOM и сохраняет прежнюю кнопку/label. Approve/reject остаются в полном review.
- Полный короткий result: inline «Результат шага: <literal>». Сокращённый: «Начало результата: <literal>…». Prefix берётся из того же `workText(result)`, обрезается по последней границе слова и проходит прежний escaping. Это не пересказ.
- Пустой result: прежнее «Описание результата не добавлено». Question без canAnswer остаётся нейтральным; generic status для других focus-ветвей не добавляется.

Рамка, padding, размеры шрифта, полный Task title и четыре прямых свойства сохраняются. Нет line-clamp, нового disclosure для результата или перемещения DOM после mount. Остальные семь контролов по-прежнему существуют в исходной форме один раз. `task-dialog.js` и `work-model.js` в compact overlay побайтово равны их исходному VT1 overlay; новая дельта только в `task-work-view.js`.

## Альтернативы и следующий критерий

Plain work-story остаётся адресным вторым рычагом, если A по факту недостаточен: он меняет визуальный акцент и не даёт автоматически 113 px. Перестановка свойств перед summary улучшила бы их доступ, но оттеснила выбранный result. Result-first без полного step title потерял бы предмет проверки при нескольких pending шагах. Эти альтернативы не стали обязательной матрицей.

На том же frozen 390×844 следующий кадр должен показать срок и приоритет целиком, полное название шага, достижимый CTA и различимое полное/частичное начало результата. Геометрия disclosure и hint измеряется отдельно, без обещания полной видимости до actual render. Две строки inline preview могли бы вернуть примерно 119 px, три — около 97 px; это только расчёт чувствительности по старому кадру.

Все прежние семь сценариев и 14 initial frames, same data/DS/baseline, native probes и их failure oracles сохраняются. Известный DS text200 reflow не считается исправленным. Readonly/accepted/create/cover/personal first screens и действия этим минимумом не принимаются; структурная editable/static parity и baseline create path сохранены. Synthetic reads не подтверждают backend save/reopen/conflicts, Plan Apply или human acceptance.

## Коррекция Estimate: исходная ошибка после Escape

Root и независимый preservation agent сверили frozen runner со stack attempt2. Строка 216 выполняла click и ожидала открытия; **217:54 ожидала закрытия после Escape**. Open oracle прошёл. Следовательно, фактическая ошибка — Estimate не закрылся после Escape, а прежнее предположение о timeout открытия неверно. Старый journal и исходные artifacts не переписываются.

Новый compact вариант не чинит product popover, не пропускает Escape и не ослабляет native gate. На исходном baseline эта ошибка остаётся до отдельного causal fix. Пассивные diagnostic trace/PNG сохраняются; результат native run может быть FAILED при успешно снятых initial frames. Проверки, расположенные после упавшего Escape, не объявляются выполненными.
