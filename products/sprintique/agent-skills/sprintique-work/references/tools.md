# Инструменты и доступ

Используй инструменты, объявленные подключённым Sprintique MCP. Если требуемого инструмента нет, явно сообщи ограничение; не заменяй его произвольным HTTP, SQL или remote execute.

Подтверждённые имена для карточки:

- `get_work_card {projectId, task}` → `schema: bridge/1`, `revision`, `card`.
- `put_work_card {projectId, task, baseRevision, card, idempotencyKey}` → `workPlan.revision`.

Карточка импортируется в черновик. Этот инструмент не подменяет действия по активному плану: изменение шагов, checkpoint, аренда, вопрос и передача выполняются соответствующими типизированными инструментами сервера. Их JSON schema и фактические разрешения определяет `tools/list`; не угадывай аргументы.

Текущий рабочий набор: `get_work_plan`, `get_work_brief`, `list_work_agents`, `list_work_skills`, `get_work_skill`; изменяющие — `change_work_lease`, `save_work_checkpoint`, `create_work_question`, `change_work_step`, `change_work_session`, `handoff_work`.

Изменяющие команды, кроме карточки, имеют оболочку `{projectId, task, input, idempotencyKey}`; шаг и сессия дополнительно получают `elementId`. Внутри `input` передаются текущая `baseRevision` и поля JSON schema инструмента. Для аренды: `{baseRevision, action: "claim"|"release", leaseToken?, seconds?}`; для контрольной точки: `{baseRevision, leaseToken, summary, nextStep, sessionId?}`. После команды прочитай возвращённую ревизию; перед новым действием сверяй актуальное состояние. Не выполняй изменение критерия или шага, которого нет в поручении.

Для вопросов используй исходный `threadId` из входящих и задачу из `get_task`. Для ответа используй предоставленный сервером инструмент обсуждения. `list_inbox` и `mark_inbox_read {ids}` обслуживают адресные входящие. Не применяй массовый `upTo`, если не обработал каждый элемент.

На изменяющем действии используй уникальный idempotency key. После неизвестного сетевого исхода повторяй точную команду с тем же ключом. После конфликта ревизии читай актуальный план, а не повторяй запись с новой ревизией автоматически. Отозванный доступ не обходи сменой аккаунта.

Авторизацию модели и Sprintique разделяй. Вход по подписке выполняет клиент Codex/Claude Code. OAuth Sprintique предназначен только его MCP audience. API-модель внутри Sprintique использует отдельное подключение провайдера. Не копируй credentials клиента или провайдера в карточку, конфигурацию навыка и исходники.
