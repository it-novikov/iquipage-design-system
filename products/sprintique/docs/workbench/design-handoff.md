## 2. Итоговые решения (включая ответы владельца)

1. **Возраст причины — отдельный факт.** В причине нет « · »: «Мария просит проверить» + `<span class="dsk-age">2 дня назад</span>` (на телефоне — своя линия). Составные причины через запятую или двоеточие: «Назначено вам, работа начата», «Вы следите: срок перенесён с 02.10 на 09.10». Принцип DS №4 соблюдён.
2. **«Назначено мне: бэклог N»** остаётся действием в шапке «Текущей работы» (вход в `Фильтры → Назначено мне`); бэклог не заполняет первый экран.
3. **«Отметить решённым» доступно из меню строки и из drawer.** Для пути из строки — тост `tone-success` с «Отменить», фокус клавиатуры переходит на следующую строку; сервер повторно проверяет адресата и ревизию источника, при расхождении — состояние «Уже решено».
4. **Пространство показывается только при коллизии имён проектов** (`workspaceDisplayName` в DTO приходит только тогда).
5. **Глобальная шапка на Рабочем столе без переключателя пространства/проекта:** «SPRINTIQUE», `.iq-work-navigation` («Рабочий стол» current, «Проекты»), поиск, настройки, тема, аватар.
6. **Snooze запроса/утверждения с `neededBy` — только до `neededBy`;** просроченный запрос возвращается в «Нужно действие» автоматически; отложенные доступны отдельным списком («Отложенные: N» в шапке секции).
7. **Токены DS vnext.21+:** `iq-warning-bg`/`iq-success-bg` — бледные тинты. Пока DS-артефакт не пересобран, в прототипе стоит override (DS-GAP-1); в продукте override не нужен — библиотека уже vnext.22.
8. Фильтр ≠ навигация: «Проекты: все ▾» — `.iq-btn.secondary.sm` с `aria-label="Проекты в выдаче"`; «Открыть проект ↗» — только действие меню строки и шапки drawer; имя проекта в строке — текст, не ссылка.
9. Один сильный маркер на строку — тон факта «Когда» (`data-tone="danger|warning"`); названия всегда `iq-ink`, бейджей статуса в строках нет.
10. Дедупликация видна: задача с запросом + `Жду` + follow — одна строка в «Нужно действие», остальное в «Ещё N причин» (доступный disclosure, не tooltip).
11. Live-обновление: одна плашка `role="status"` «Появились изменения: N новых. Обновить», строки не переставляются.
12. Точный счёт для «Нужно действие», `99+` для «Изменилось»; обновления сгруппированы по задаче («3 изменения»).

## 3. Композиции и классы для реализации

Продуктовый CSS уровня `ui/planning/src/planning.css`; префикс `dsk-` (`wb-` занят whiteboard-модулем DS). Исходник композиции: `workbench.css` в артефакте (`project/workbench.css`), генератор и файлы — в scratchpad сессии дизайна.

**Переиспользовать из DS / PR #19 без изменений**

- `.iq-page-heading` → `.iq-page-heading-copy` (h1 «Рабочий стол», `p.dsk-scope`) + `.iq-page-heading-tools` (`.iq-segmented` режимов, `.iq-btn.primary.sm` «+ Задача»).
- `.iq-work-toolbar` → `.iq-work-toolbar-group` (фильтр проектов, «Фильтры» `.iq-btn.ghost.sm` с `list-filter`), `.dsk-toolbar-end` («Обновлено в HH:MM» + `.iq-btn.icon.ghost.sm` refresh).
- Секции: `section.iq-section.dsk-section` → `.iq-section-head` (иконка 16px, **h2**, `.iq-section-count`, `.iq-section-actions` с одним `.iq-btn.ghost.sm`). Группы: `.dsk-group-head` (**h3** + `.iq-section-count` + пояснение).

- Состояния строки: `data-state="snoozed|pending|done|focused"`.
- Меню строки: `iq-menu` → `.iq-popup.iq-menu-popup` с `.iq-menu-section` «Лично».
- `.iq-empty.compact` для пустых секций и нулевого фильтра; `.iq-empty` для «нет проектов»; `.iq-loading` + `.iq-skeleton.iq-skeleton-line` в `.dsk-skel-row` (5 колонок, 52px); `.iq-alert.danger|warning` с `.message-emblem`/`.message-copy`; `.iq-toast.tone-success` с `.iq-toast-icon`; `.iq-badge.soft.*` только в drawer-связях и чипе фильтров; `ui.personAvatar` (`.iq-avatar.xs`).
- Drawer: существующий task drawer (`iq-dialog kind="drawer"`, 664px, `.iq-dialog-head/-inner/-footer`), внутри `.iq-property-strip`, `.iq-section` (Жду результат, Связи, Описание, Обсуждения), `.iq-switch`, `.iq-date-trigger`.
- Телефон: та же таблица, `.dsk-phone` переводит `tr` в grid (title / meta / actions), скрывает `thead`, ID уходит в `.dsk-cell-meta`; цели 44px; лист фильтров `.dsk-sheet` (заголовок, тело, футер «Отмена / Применить»).

**Новые продуктовые композиции (без новых DS-примитивов)**

`.dsk-header` (глобальная шапка), `.dsk-scope`, `.dsk-refresh` (плашка обновления), `.dsk-group-head`, `.dsk-reason/.dsk-age/.dsk-more/.dsk-reasons`, `.dsk-when`, `.dsk-actions/.dsk-rank`, `.dsk-request` (карточка адресного запроса), `.dsk-facts/.dsk-toggles` (личное отношение), `.dsk-relation`, `.dsk-offer` (предложение «Следить за результатом»), `.dsk-inline-state[data-tone]` («Уже решено», ожидание офлайн, доступ отозван), `.dsk-banner` (офлайн), `.dsk-chips/.dsk-chip` (активные фильтры), `.dsk-day/.dsk-kind` (План), `.dsk-sheet` (телефон).

Доступность: секции — настоящие h2/h3 и `table`; причина видима и связана через `aria-describedby`; ссылка строки, disclosure и меню — отдельные focusable контролы; ранг — кнопки; disclosure `aria-expanded/aria-controls`; плашка обновления и тосты — `role="status"`; скелетон — `aria-busy`; ошибки — `role="alert"`.

## 4. DS-пробелы

- **DS-GAP-1.** DS-артефакт (vnext.20): `iq-warning-bg`/`iq-success-bg` равны плотным заливкам — мягкие бейджи нечитаемы в тёмной теме. Библиотека vnext.21+ уже исправлена (`#FFF3DF`/`#E6F6EF`, dark `#302310`/`#10271F`); override в `workbench.css` прототипа убрать после пересборки DS-артефакта.
- **DS-GAP-2.** Нет глифов `arrow-down`/`chevron-up`: «Ниже» — `arrowUp` с поворотом 180° (`.dsk-rot180`). Просить в DS `arrowDown`.
- **DS-GAP-3.** Нет `switch` с подписью-пояснением и `dl` фактов вне настроек (`.iq-settings-facts`) — композиции `.dsk-toggles`, `.dsk-facts`.
- **DS-GAP-4.** Нет карточки адресного запроса (адресат, `neededBy`, resolve) — `.dsk-request`; в DS есть только `.iq-thread[data-kind=question]` внутри обсуждений.
- **DS-GAP-5.** Нет чипа активного фильтра с удалением, inline-state и полноэкранного листа для телефона (DS drawer — только 664px справа).
- **DS-GAP-6.** DS-артефакт без JS-бандла и на телефоне прячет `.iq-work-list-id`; в Рабочем столе ID остаётся в meta-линии.

Новый DS-примитив (например, «строка внимания» или «чип фильтра») добавлять только при втором потребителе, как требует delivery plan §9.
