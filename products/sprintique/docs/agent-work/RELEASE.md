# Выпуск SPR-14

Владелец разрешил push и deploy в исходной постановке и подтвердил план P01–P12. Выпуск пока не выполнен. Эта запись отделяет проверенные условия от оставшихся действий.

## Подготовка

На 11 октября 2026 production работает на `sprintique-server:931e09d`. API и worker готовы, перезапусков нет. Коннектор Codex подключён через штатный OAuth к `https://api.iqui.page/mcp`; чтение SPR-14 и создание утверждённых подзадач проверены от сервисного аккаунта Codex.

Резервная копия до изменений сохранена на VPS в `/root/backups/sprintique-vnext/spr14-preparation-20261011/`. Custom-format `sprintique.dump`, настройки образа и запись текущих image digest доступны только root. Копия успешно восстановлена в отдельную базу `spr14_restore_drill_20261011` с `pg_restore --exit-on-error`; проверено наличие 187 задач. Временная база после проверки удалена. Действующая база и сервисы не менялись. Перед фактической выкладкой нужна свежая копия.

## Условия выпуска

Выкладка допускается после полной проверки неизменного исходного дерева, независимого ревью исправленного результата без P0/P1, проверки браузерного сценария и точного архива IQUIPAGE. Для образа сохраняются полный Git SHA и digest. Миграция выполняется отдельным контейнером с миграционной ролью; API и worker не получают её credentials. После включения `agent_work` проверяются готовность, отсутствие перезапусков и рабочий сценарий от собственного аккаунта Codex.

## Наблюдение

После cutover — десятиминутное окно: внешняя готовность, exact image API/worker, рестарты, доступ через own OAuth и ошибки нового рабочего сценария. Условие отката: повторная неготовность API, неожиданный restart, нарушение доступа/сохранности или подтверждённый отказ основного маршрута. Одиночный неизвестный ответ сначала проверяется с тем же idempotency key; обход CAS и прав недопустим.

## Откат

Миграция 077 добавляет таблицы и право `work.write`. Старый образ `931e09d` не является совместимым откатом после её применения: он проверяет прежнюю историю миграций и не знает нового права. Подмена тега без восстановления базы запрещена.

Отключение `agent_work` возвращает прежнюю навигацию и закрывает новые маршруты, сохраняя данные. При необходимости остановить API-исполнителей отдельно устанавливается `SPRINTIQUE_AI_RUNNERS=0`. Это выключение функции, а не доказательство возможности откатить весь сервер. Оно должно быть проверено на изолированном стенде с новой схемой до выпуска.

При отказе самого сервера требуется совместимый проверенный образ либо восстановление базы и исходной конфигурации. Полное восстановление выполняется при остановленных API и worker; записи после резервной копии предварительно сохраняются и оцениваются, чтобы не потерять пользовательскую работу. Непроверенный старый образ не используется как быстрый обход.

## Проверенные контейнеры

На отдельной Docker-сети VPS восстановлена только собственная синтетическая база UI-приёмки. Оба образа прошли HTTP `/ready`, сессию fixture-пользователя, отказ анонимному клиенту, чтение прежней задачи на схеме 077, точный hash HTML, запуск UID 10001 с read-only FS и отсутствие рестартов. У основного образа work endpoint возвращает состояние; совместимый fallback закрывает этот endpoint. Сценарий не вызывал модель, отправку писем или production-команды. Временные контейнеры, volume и сеть удалены с проверкой принадлежности.

Основной manifest digest: `sha256:559c870e35a318d58c6f81590e063bfea0e26d95d9851a846840b35c4f5bee44`. Совместимый fallback: `sprintique-server:spr14-compatible-e7a2cffa3f27`, digest `sha256:405326405aae89d7c5605b12bffa04ac3221f3d0c51cf26772d3ad3fbb06b57d`. В fallback сохранены исходный UI и API с поддержкой нового ledger/права и wire-лимитов. Его HTTP-проверки: 39/39, integration 46/46. Для возврата на fallback сначала убирается `agent_work` из обоих private env, затем меняется image и пересоздаются API/worker. Данные work сохраняются.

Сценарий выпуска отдельно прошёл read-only review. Ошибка подготовки до миграции восстанавливает старую конфигурацию и сервисы. При ошибке миграции committed ledger выбирает прежний образ до 077 либо совместимый fallback после 077; readiness обязателен. При отказе новых сервисов после миграции используется только совместимый fallback. Автоматическое восстановление базы не выполняется.

## Полный гейт

Финальный immutable gate3 завершён: fingerprint `43ce480176fbfe4cc1c4d577d3e58d8311727bb492336ba8942fa316f55cdffb`, исходники stable. DS 456/456, продукт 473/473, отдельное извлечение продукта с clean install 473/473, skipped 0. Архив IQUIPAGE .39: `35c1246b5752ca8233bec2101b84be834dde2eb7ef8f662b812a2d30952462dc`. Gate2 не считается успешным: он обнаружил приватный импорт в одном тесте; финальный тест проверяет публичный HTTP roundtrip и включён в оба успешных прогона.

Реализация запушена коммитом `844bff9b4d70124b8b322b62be3dfc74e44d8cd8`, PR [#64](https://github.com/it-novikov/iquipage-design-system/pull/64). CI [38119788205](https://github.com/it-novikov/iquipage-design-system/actions/runs/38119788205) выполнил все продуктовые проверки и detached успешно, но завершился отказом source-stability: чистый Gradle создал служебные `.gradle/*.properties`, ошибочно включённые в fingerprint. Такой прогон не считается зелёным. Генерируемые `.gradle`/`.kotlin` исключены с regression-тестом; Kotlin, build.gradle.kts, wrapper properties и gradlew остаются build inputs. Отдельно квота аккаунта заблокировала upload artifact; workflow сохраняет полный сертификат в job log, optional upload не заменяет строгий gate. После исправления требуется новый полный гейт и CI.
