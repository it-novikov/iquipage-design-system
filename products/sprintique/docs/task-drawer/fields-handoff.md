# Поля задачи в drawer — design handoff

**Статус:** решения владельца по раундам 1–3 приняты; готово к реализации.  
**Артефакт (Claude Design, IQUIPAGE 0.6):** https://claude.ai/artifact/TSfXXCUDNee3etMbA3qRzn — приватный, доступ выдаёт владелец через Share. Итоговый ряд — «Итог: D „Сетка фактов“ без участников, одно личное „Участвую“» (артборды `Final-*`); раунды 1–2 сохранены выше для истории.  
**База:** `products/sprintique/ui/src/board/task-dialog.js` (блок `.task-editor-properties`), `board.css`, `catalog-picker.js`; DS `@iquipage/web` 0.6.0-vnext.21+. Доска и План открывают один drawer (`planning-host.js → openTaskDialog`), поэтому блок один для обоих контекстов.  
**Генератор макетов:** scratchpad сессии дизайна (`task-fields/gen.js`, `round2.js`, `round3.js`), композиция `tf-` — источник для продуктового CSS.

## 1. Решения владельца

1. Направление **D «Сетка фактов»** принято: плитки «подпись над значением», всё видно всегда, ни одной строки-на-поле, ни одного сворачивания («Ещё N полей» отклонено).
2. **Тип и Релиз** показываются всегда.
3. **План** (`plannedStart`/`plannedEnd`) редактируется в drawer полем интервала (DS-пробел, спецификация в §4).
4. **Ролей в задаче нет**, общего списка участников нет. Одно личное состояние **«Участвую»** — кнопка в шапке drawer с `aria-pressed`; это то же, что «слежу» и «держу в фокусе».
5. Автор задачи участвует автоматически; выход — один клик.
6. **«Жду»** — не отдельное понятие: я участвую в задаче, которую назначил другому; опционально — личная дата «Проверить».

## 2. Итоговая раскладка

Drawer 664px, содержимое 616px; сетка `repeat(3, minmax(0,1fr))`, колонка 194px, зазор 16px по горизонтали и 12px по вертикали; между главным рядом и остальными 16px; под блоком 24px, затем секция «Описание». Высота при однострочных значениях ≈ 200px.

| Ряд | Плитки | Триггер |
|---|---|---|
| Главный | **Статус** (пилюля) · **Исполнитель** (аватар 22px + имя) · **Срок** (дата с тоном) | 36px, вес 500 |
| 2 | Приоритет · Тип · Релиз (имя + мета «до 17.10», до 2 строк) | 32px |
| 3 | План (интервал) · Родитель (ключ моноширинным + название, до 2 строк, две колонки) | 32px |
| 4 | Теги во всю ширину: чипы 24px, «Ещё N» после второй строки, «+» в конце | 32px+ |

Порядок Tab = порядок в DOM = визуальный: Статус → Исполнитель → Срок → Приоритет → Тип → Релиз → План → Родитель → Теги.

### Плитка

- Подпись: `caption` 12px / 1.5, 400, `iq-muted`, отступ слева 8px (точно над текстом значения), одна строка с обрезкой.
- Значение: ghost-триггер, `interface` 14px, `iq-ink`, padding `0 8px`, граница прозрачная, радиус `iq-radius-sm`. Hover: фон `iq-hover`, граница `iq-line`. Открыт: граница `iq-control`, фон `iq-raised`. Фокус: `:focus-visible` кольцо 2px `iq-focus` с `outline-offset:-2px` (внутри границ). Шеврон 12px `iq-muted`, `opacity:0`, появляется на hover / фокусе / открытии (`iq-motion-fast`); на `hover:none` — виден всегда.
- Статус — `iq-select appearance="pill"`: 28–30px, `iq-radius-pill`, фон `iq-surface`, точка 8px в тоне колонки (`info` В работе / Готово к тестированию, `warning` Ревью / Тестирование, `success` Готово к релизу, без тона Готово к работе). **Единственная заливка в блоке.**
- Иконка только там, где она и есть значение: точка статуса, аватар исполнителя, глиф приоритета (`priority`, `critical`, `minus`, `low`), глиф типа (`checklist`, `bug`, `stack`). Даты, релиз, план, родитель — только текст.
- Тон текста: приоритет high / critical — `iq-task-high-text` / `iq-task-critical-text`; срок просрочен — `iq-danger`, сегодня / завтра — `iq-warning`; у задач в «Готово к релизу» и с принятым результатом тон не даётся. Никаких вторых заливок.
- Многострочные значения: релиз и родитель — до 2 строк (`-webkit-line-clamp:2`), строка сетки растёт; имя человека — одна строка с многоточием.

### Пустые значения — тихо, но на месте

| Поле | Текст | Стиль |
|---|---|---|
| Исполнитель | Не назначен | `iq-muted`, без аватара |
| Срок | Без срока | `iq-muted` |
| Релиз | Без релиза | `iq-muted` |
| План | Не запланировано | `iq-muted` |
| Родитель | Нет | `iq-muted` |
| Теги | Добавить тег | `iq-muted`, весь триггер кликабелен |

Приоритет и Тип пустыми не бывают («Обычный», «Задача»): значение `iq-ink`, глиф `iq-muted`.

### Редактирование

- Каждый триггер — `button role="combobox"` с `aria-haspopup`, `aria-expanded`, `aria-labelledby` на подпись. Enter / Space открывает, стрелки по опциям, Escape закрывает и возвращает фокус. Один клик от любого значения к его редактору; автосохранение как сейчас (`iq-change` → `schedule()`).
- Статус, Приоритет, Тип, Релиз — `iq-select` (релиз `searchable`, с опцией «Новый релиз» для admin); Исполнитель — `iq-combobox` с аватарами; Срок — `iq-date-field`; План — `iq-date-range-field` (§4); Родитель — `iq-select searchable` (переезжает из секции «Связи» в сетку; секция «Связи» остаётся с `iq-relation-map`); Теги — `iq-tag-picker appearance="inline"` (без плейсхолдера «Ещё тег», «+» в конце, «×» на чипе только на hover / фокусе).
- Ограничения базы объясняются словами в помощи попапа (см. §4), не блокировкой кнопок.

### Только чтение (результат принят, роль reader)

Те же плитки статичным текстом, над сеткой строка с замком 14px: «Только чтение: результат принят в релизе 2.4. Обсуждение и участие открыты». Никаких disabled-контролов (принцип DS 12). «Участвую» и обсуждение остаются активны.

### Телефон (≤ 640px, полноэкранный drawer)

Сетка `repeat(2, minmax(0,1fr))`, зазор 12px: Статус · Исполнитель / Срок · (пусто) / Приоритет · Тип / Релиз · План / Родитель (две колонки) / Теги (две колонки). Триггеры 40–44px (touch.css даёт 44 на грубом указателе). Кнопка «Участвую» в шапке — только иконка 44px с `aria-label`.

### Полноэкранный режим (≥ 900px)

В правой sticky-колонке 280px три плитки не помещаются, поэтому в полноэкранном режиме блок стоит **под названием на всю ширину колонки чтения** (до 720px), сетка та же. Sticky-колонка свойств из текущего `board.css` (`[data-fullscreen=true] .task-editor-layout`) убирается.

### Тёмная тема

Токены DS без переопределений: пилюля `iq-surface`, hover `iq-hover`, попапы без границы с тенью DS, тона текста из `iq-task-*-text` (dark-значения 4.5:1 на `iq-raised`).

## 3. Кнопка «Участвую» — одно личное состояние

**Смысл.** Личное отношение к задаче, видимое только мне: задача на моём Рабочем столе и её значимые изменения в «Изменилось». Заменяет «В фокус» и «Следить» из WP0 (`design-handoff.md`, `.dsk-toggles`), ролей и общего списка участников нет.

**Где.** Шапка drawer, слева от действий окна (обложка, полноэкранный режим, закрыть), справа от ключа задачи. На телефоне — иконка.

> **2026-10-01, решение владельца:** переключатель называется «Наблюдаю» и сделан иконкой без текста: `button.iq-btn.ghost.icon.sm` с глифом `eye` 18px, `aria-pressed`, `aria-label` «Наблюдать за задачей» / «Наблюдаю — нажмите, чтобы перестать», подсказка `iq-tooltip heading`; стоит в ряду иконок шапки перед обложкой. Вкл. — штатное DS-состояние `.iq-btn[aria-pressed=true]` (акцентный глиф на `iq-accent-soft`). Разметка ниже — исходная спецификация.

**Разметка.** `button.iq-btn.ghost.sm` с `aria-pressed`, иконка `users` 16–17px, текст «Участвовать» / «Участвую» (на телефоне только `aria-label`). Композиция продукта `.tdr-join` (см. §5).

| Состояние | Вид |
|---|---|
| Выкл. | ghost, `iq-muted`, текст «Участвовать» |
| Вкл. | фон `iq-accent-soft`, текст «Участвую» `iq-ink` — единственная акцентная поверхность в шапке |
| Hover | `iq-hover` (выкл.) / без изменения (вкл.) |
| Фокус | кольцо 2px `iq-focus`, `outline-offset:-2px` |
| Я исполнитель | вкл., не выключается; подсказка «Вы исполнитель: задача всегда в «В работе»»; не disabled-вид |
| Поручил другому («Жду») | вкл. + рядом ghost-триггер `iq-date-field` «Проверить 03.10» (пусто — «Проверить…»), личная дата; показывается только когда исполнитель не я и назначил его я; на телефоне — в секции под свойствами |

**Подсказка** (`iq-tooltip heading`, по hover и по фокусу с клавиатуры): выкл. — «Участвовать» / «Держать задачу на Рабочем столе и получать её изменения»; вкл. — «Вы участвуете» / «Задача на вашем Рабочем столе, изменения приходят в „Изменилось“. Нажмите, чтобы выйти».

**Поведение.** Сохраняется сразу, без подтверждения и тоста (состояние кнопки — и есть подтверждение); поля задачи не меняются, коллеги ничего не видят. Автор участвует с момента создания; адресат запроса и тот, кому назначили, участвуют автоматически; выход — тот же клик. Исполнитель не может выйти, пока он исполнитель.

**Рабочий стол.** «В фокусе» → **«Участвую»** (участвую, не исполнитель); «В работе» — исполнитель в активном статусе; **«Жду»** — участвую в задаче, которую назначил другому (подгруппа сохраняется, строка показывает «Вы поручили Анне» и дату «проверить», если задана); «Изменилось» — значимые события задач, где я участвую (статус, исполнитель, срок / план, блокер, вопрос, принятие результата; прочее группируется «N изменений»; собственные правки не считаются). Причины: «Вы участвуете», «Вы поручили Анне, проверить в пятницу». Личный ранг ↑↓ остаётся.

**Данные.** Одна личная таблица вместо focus/follow/waiting:

```sql
CREATE TABLE app.task_participation (
  project_id text NOT NULL, task_id text NOT NULL, principal_id text NOT NULL REFERENCES auth.principals,
  source text NOT NULL CHECK(source IN ('manual','author','assignee','assigned_by','request')),
  check_back_at date,            -- личная дата «проверить», только для assigned_by
  rank double precision,         -- личный порядок на Рабочем столе
  added_at timestamptz NOT NULL DEFAULT clock_timestamp(),
  PRIMARY KEY(project_id, task_id, principal_id),
  FOREIGN KEY(project_id, task_id) REFERENCES app.tasks(project_id, id)
);
-- RLS как у app.thread_reads: только свои строки, только внутри доступных проектов.
```

Контракты: `Task.me = {participating, source, checkBackAt, rank}`; команды `participate`, `leave`, `setCheckBack`, идемпотентные по `(task, principal)`. Outbox `task.changed` раздаётся по строкам участия. Миграция: `owner_id` → строка `assignee`; `created_by` (если есть в audit) → `author`; прототипные focus/follow → `manual`.

## 4. Поле интервала дат — `iq-date-range-field` (DS-пробел)

- **Атрибуты:** `label`, `start`, `end` (`YYYY-MM-DD`), `min`, `max`, `deadline` (дата срока: отмечается в календаре и участвует в помощи), `placeholder` («Не запланировано»), `disabled`, `readonly`, `name`. **События:** `iq-change {start, end}`. **Методы:** `open()`, `close(restore)`.
- **Закрытое состояние:** тот же `.iq-date-trigger`, что у `iq-date-field`; значение через `formatDateRange`: «29.09 – 10.10» в текущем году, «29.09.2026 – 10.10.2026» иначе; один день — одна дата; пусто — плейсхолдер `iq-muted`.
- **Попап** (`.iq-date-popup`, 352px): заголовок-подпись «План: начало и конец»; два поля «Начало / Конец» с вводом с клавиатуры (маска дд.мм.гггг, Tab между ними); один месячный `iq-calendar` (неделя с понедельника, дни 34px): клик 1 — начало, клик 2 — конец, обратный порядок меняет местами, стрелки — по дням, Enter — зафиксировать; пресеты `.iq-btn.ghost.sm` «Неделя», «2 недели», «До срока 04.10» (последний — только при `deadline`); строка помощи; футер «Очистить» слева, «Отмена», «Применить» (`primary sm`).
- **Токены:** интервал — фон `iq-accent-soft`; концы — `iq-accent-fill` / `iq-on-accent`, радиус 9px по внешним краям; срок — подчёркивание 2px `iq-danger`; сегодня — 600 + подчёркивание; дни другого месяца — `iq-faint`.
- **Правила словами:** `planned_start ≤ due` — «Начало не позже срока 04.10» (предупреждение с иконкой `warning`; «Применить» доступна, сервер вернёт ошибку словами); начало без конца — «Конец не задан: план на один день»; норма — «12 дней. Срок задачи 04.10 отмечен на календаре».
- **Где:** свойства задачи (План), диалог расписания в Плане (`time-dialogs.js`, вместо двух `iq-date-field`), позже — релизы.

## 6. Проверка перед сдачей

- Порядок Tab и `aria-labelledby` на всех девяти триггерах; Escape возвращает фокус.
- Контраст `iq-muted` на `iq-raised` ≥ 4.5:1 в обеих темах; тон срока / приоритета — только текстом, статус — единственная заливка.
- 664 / 720 (полноэкранный) / 390: без горизонтальной прокрутки, длинные релиз и родитель в две строки, имя — с многоточием.
- Пустая задача: шесть тихих плейсхолдеров на своих местах, ничего не скрыто.
- «Участвую»: автор, назначенный и адресат запроса — включено с момента события; исполнитель не выключает; выход в один клик; изменения появляются в «Изменилось» без собственных правок.
- Reduced motion: шеврон и попапы без анимации.

## 7. Реализация (ветка `feature/task-drawer-fields`)

Сделано по §2 и §4, кроме «Участвую» (§3, ветка `feature/workbench`). Отступления, вызванные границей DS (стиль продукта не трогает внутренности компонентов, `check:styles`):

- Подписи плиток — размер подписи свойств DS (13px), а не caption 12px; главный ряд — 32px с весом 500, пилюля статуса 28px (DS).
- Исполнитель — `iq-select searchable` с аватарами (закрытое поле — значение, поиск в открытом списке), не `iq-combobox`: у combobox в пустом состоянии остаётся лупа.
- Релиз и родитель — одна строка с многоточием, мета релиза («до 17.10») всегда видна (DS-GAP-J); ключ родителя не моноширинный.
- Теги — все, с переносом; «Ещё тег» и отсутствие «Ещё N» — поведение DS (DS-GAP-L).
- У «Срока» и «Плана» остаётся глиф календаря DS (DS-GAP-M); релиз и родитель — только текст.
- Правило `planned_start ≤ due` снято на сервере миграцией `V20260927000006` («поздний план должен сохраняться»), поэтому в попапе это предупреждение словами, «Применить» доступна. Добавлено второе предупреждение — «Конец позже срока»: сервер помечает такой план риском срока, и тогда перед сохранением открывается диалог проверки планирования с этим риском. План в пределах срока сохраняется сразу после «Применить» (preview → commit, тот же журнал идемпотентности).
- Только чтение: строка с замком говорит «Обсуждение открыто» — «участие» появится вместе с кнопкой «Участвую».


## 8. Направление A «Список» (раунд 4, решение владельца 2026-10-01; ветка `feature/task-fields-list`, DS 0.6.0-vnext.27)

Сетка фактов (§2) заменена одним спокойным списком. Ревизия раунда 3 и правила системы верха ящика — в артефакте раунда 4 («Поля задачи»); здесь — то, что реализовано.

- **Список.** Одна `.iq-properties[data-label=wide]`: десять строк по 36 px — Статус, Исполнитель, Срок, Приоритет, Тип, Релиз, План, Родитель, Теги, Автор. Подпись 120 px (136 в полноэкранном режиме), 13/400 muted; значения 14/400. Порядок Tab = DOM = визуальный.
