# ADR 0010: план и история агентской работы по задаче

Статус: принятый владельцем SPR-14 план P01–P12; этот документ описывает реализацию и её границы. Проверки выпуска фиксируются отдельно в RELEASE.md. Исторические карточки моста не являются разрешением на действия или доказательством работающего кода.

## Решение и данные

Задача остаётся основной сущностью. `task_work_plan` хранит ограниченный документ bridge/1 и монотонную версию; шаги, критерии, контрольная точка, вопросы и решения входят в один согласуемый документ. `task_work_session` связывает поручение человека, сервисный аккаунт, задачу, обсуждение и, только для provider_api, настоящий `ai_agent_runs`. Внешний подписочный клиент имеет режим external и начинает с awaiting_agent: сервер не запускает его локальный процесс. Каталог показывает действующие сервисные аккаунты проекта; старые grant-агенты не переименованы в сервисные аккаунты.

`task_work_request` связывает упоминание/сообщение и поручение. `task_work_event` — неизменяемая, постраничная история значимых действий с коротким текстом для человека. Технический журнал модели остаётся в существующем AI контуре. История читателя не содержит ключей подключения, токенов учётных данных или полный текст вызова провайдера.

`agent_skill_version` — неизменяемая версия текста, digest и список требуемых типизированных инструментов. Профиль назначает конкретные версии; сессия фиксирует их снимок при постановке. API исполнитель получает ограниченный контекст этих версий, помеченный недоверенным. Навык не повышает права и не разрешает произвольный execute. Внешний клиент читает те же версии через MCP/REST.

## Права и согласование

Чтение требует tasks.read; работа с планом требует work.write. Назначение дополнительно требует tasks.write и интерактивного человека. Решение вопроса, новое принятое решение и утверждение результата требуют approvals.decide и интерактивного человека. Автор результата не утверждает собственный результат; утверждение связано с точным результатом, доказательствами, критериями и текущей версией. Агент обновляет выполнение, но не подменяет текст человеческого критерия. Следующего агента выбирает человек.

Сохраняется пересечение OAuth scopes, прав аккаунта проекта, прав владельца и инициатора API запуска. MCP audience не принимается REST. Новое work.write добавляется существующим администраторам и неизменённым редакторским/сервисным пресетам; вручную изменённые пресеты не получают скрытого расширения.

RLS включён и принудителен на новых таблицах. Обычный runtime не является владельцем и не получает BYPASSRLS. Служебная проекция AI lifecycle использует существующие SECURITY DEFINER queue/finish функции и узкие owner-only политики с временной границей конкретного проекта. Отдельного универсального SQL/execute метода нет. Триггеры обновляют только связанные с NEW run сессии и историю. Блокировки завершения/истечения берутся в порядке проект → запуск, как при человеческой отмене, чтобы не инвертировать порядок команды плана.

## Конкурентность и повтор

Каждое изменение получает baseRevision и Idempotency-Key. Под проектной блокировкой проверяется CAS, затем эффект, версия, audit, outbox и человекочитаемое событие записываются атомарно. Проигравший первоначальный insert не создаёт второй план. Повтор обязан иметь тот же вход.

Квитанция сохраняет исходную применённую версию, а не позднейшее состояние. Повтор возвращает ограниченный ACK с requiresReload; UI перечитывает состояние, CLI не может принять более новую чужую версию как основание своей старой карточки. Командная идемпотентность не обещает ровно один запрос провайдеру или ровно одно списание после неопределённого сетевого исхода.

Аренда ограничена по времени и несёт случайный fence token. Изменения агента требуют совпадения владельца, живого токена и CAS. GET не раскрывает текущий токен: его возвращает только собственная команда claim и её исходная квитанция. Завершённое/отменённое поручение запрещает агенту новые изменения и повторный claim до нового человеческого поручения. Начальное предложение плана без прежней сессии остаётся допустимым для аккаунта с work.write.

Отмена внешнего поручения фиксирует конечное состояние и освобождает его аренду. API отмена использует настоящий запуск и отзывает runtime credential; завершение/ошибка/истечение проецируются из реального runtime. Завершение снимает аренду только совпадающего аккаунта при отсутствии другого живого поручения этого аккаунта. Передача сохраняет checkpoint и прекращает исходное поручение; новый агент заново захватывает аренду. Человек может передать без знания чужого fence token.

## Ограничения и перенос

Документ ограничен 160000 байтами, карточка — 100000 символами, шаги/критерии — 50, версии навыков проекта — 200. Текст навыка ограничен 16000 символами; суммарный контекст API ограничен 16000. Контрольные точки и сообщения ограничены контрактами; схемы Kotlin и TypeScript экспортируются в public-schemas.json. Секретоподобные строки не принимаются в рабочий документ.

Импортированная карточка хранится в исходных байтах до содержательного изменения; неизвестные разделы сохраняются. Заголовки внутри fenced blocks не становятся разделами или шагами. Состояние bridge active соответствует doing. После изменения сервер экспортирует каноническую карточку; неизменность байтов уже не обещается. Метаданные внешнего редактора в известных разделах, которые не имеют серверной модели, не следует считать исполнимыми полями.

## Альтернативы и выпуск

Отдельный универсальный графовый workflow engine и произвольный execute отвергнуты: существующих typed tools и небольшой модели задачи достаточно. Хранить только Markdown отвергнуто: невозможно надёжно проверять CAS, критерии и человеческое согласование. Делать подписочный клиент серверным API runtime отвергнуто: у них разные ключи, стоимость, жизненный цикл и область исполнения.

Миграция 77 добавляет сущности без удаления legacy истории и переносит существующие API запуски в общие сессии; исторические версии навыков не выдумываются. agent_work выключает все новые рабочие HTTP/MCP операции и выдачу инструментов API агенту; старые задачи и AI hooks остаются совместимыми. Feature-off — операционный откат поведения на новой схеме. Строгий ledger не допускает старый образ без миграции 77; чтение work.write старым Permission enum также несовместимо. Полный откат требует восстановления проверенной резервной БД и старого образа либо отдельно проверенного совместимого rollback образа. Не удалять историю ради отключения функции.

Приёмка: конкурирующий CAS; исходная квитанция после чужого изменения; утрата доступа и cross-project 404; запрет подмены критерия/самоутверждения; lease token недоступен GET; отмена против нового claim; настоящий app.ai_run_finish без actor под runtime NOBYPASSRLS; конечная сессия перестаёт блокировать новое поручение; полный обход истории; bridge roundtrip; feature-off на новой схеме. Provider/external endpoints и интерфейс проверяются раздельно.
