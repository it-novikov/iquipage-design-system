# 0006. Личные уведомления и доставка в Telegram

- **Статус:** proposed
- **Дата:** 2026-10-01
- **Владелец:** it-novikov
- **Основание:** карточка `.bridge/tasks/20261001-notifications-telegram`; схема пилота (`notifications`, `notification_preferences`, `telegram_*`); [W1](../adr/W1-exact-recipient-requests.md), [W2](../adr/W2-private-state-boundary.md), [W3](../adr/W3-field-revisions-and-watermark.md)

## Контекст

В пилоте человек узнавал о назначении, упоминании и сроке из колокольчика и Telegram. В vNext есть «Изменилось» Рабочего стола (W3) — новости задач, в которых человек участвует, — но нет личного сигнала «от вас ждут действия» вне Рабочего стола и нет доставки вне продукта. Упоминаний в обсуждениях нет: редактор — Markdown без выбора людей.

## Решение

1. **Четыре вида, все — личное действие:** `assigned` (задачу назначил кто-то другой), `mention` (`@Имя` в сообщении), `request` (адресный запрос W1, в том числе переданный), `deadline` (срок своей задачи). «Изменилось» остаётся новостями отслеживаемых задач; уведомления его не дублируют.
2. **Создаются в транзакции причины.** Назначение и запрос — триггер на `app.task_activity` (события W3 пишут доска, планирование, агенты и Рабочий стол одинаково). Упоминание — команда обсуждения: имена сравниваются в Kotlin (база может работать без локали, где `lower()` не сворачивает кириллицу), база проверяет автора сообщения и право получателя читать задачу. Срок — функция воркера раз в пять минут, от 09:00 дня накануне до конца дня срока, в часовом поясе человека из Рабочего стола, иначе проекта.
3. **Правила:** не уведомлять о своём действии (и о действии своего агента — инициатор); одно уведомление на причину и человека (`UNIQUE(recipient_id, dedupe_key)`); только включённые люди с правом читать задачи проекта, никогда сервисные аккаунты и агенты. В строке нет текста — только коды, даты и id; строка «Анна К. назначил(а) вам «…»» собирается из задачи при показе, переименование видно сразу.
4. **Личное по W2:** без аудита, outbox и журнала повторов; политика «свои и пока виден проект»; уйти из проекта — уведомления скрыты, не удалены. API-роль не пишет уведомления напрямую (только функции владельца таблиц) и меняет только `read_at`.
5. **Упоминания без выбора людей:** полное отображаемое имя или имя, если оно в проекте одно; без учёта регистра, имя стоит отдельно; `@` внутри слова и в коде не считается; не больше 20 человек на сообщение. Автодополнение `@` в редакторе — следующий шаг DS.
6. **Колокольчик** — в шапке проекта среди личных инструментов, на DS-меню; число только больше нуля, чернилами, не тревожным цветом. Шапку Рабочего стола сейчас меняет PR #38, поэтому колокольчик там появится после него (компонент `web/notifications.js` подключается одной строкой).
7. **Telegram** — необязательно; без `SPRINTIQUE_TELEGRAM_BOT_TOKEN`, `…_BOT_USERNAME`, `…_WEBHOOK_SECRET` его нет (настройки молчат, команды — 404); частичная конфигурация не запускается. Привязка — одноразовый токен (хранится SHA-256, 15 минут) в `t.me/<bot>?start=`, вебхук с секретом в заголовке, идемпотентный по `update_id`, ответ в чат — методом Bot API в ответе вебхука. Один чат — один человек.
8. **Переключатель проекта включён по умолчанию** (в пилоте был выключен). Причина: человек сам подключает Telegram и выбирает виды; выключенный по умолчанию проект означал бы, что подключение «не работает», пока администратор каждого проекта не найдёт настройку. Право — «Настраивать проект» (`project.settings`), ближайшее в каталоге #31: это настройка проекта, не доступ.
9. **Доставка** — outbox `app.telegram_deliveries` в той же транзакции; воркер (роль только с функциями) берёт строку под арендой, перепроверяет от имени получателя (привязка, выбор, проект, доступ, причина ещё в силе, не прочитано в продукте, не старше суток) и шлёт `sendMessage` с кнопкой «Открыть задачу». 429 — ждать `retry_after`; иначе 10 с → 40 с → 160 с → 640 с; пятая неудача — `failed` с кодом; 403 — человек заблокировал бота, чат отвязывается.

## Альтернативы

- **Уведомления из outbox проекта (SSE).** Outbox виден всем участникам проекта — это раскрыло бы личное (W2). Отклонено.
- **Сообщение строится и хранится при создании.** Проще для доставки, но хранит заголовки задач в личной таблице дольше, чем человек видит проект, и устаревает при переименовании. Отклонено: текст собирается при показе и отправке.
- **Разбор упоминаний триггером в базе.** Один путь для всех источников, но без локали кириллица не сворачивается по регистру. Все сообщения проходят через две команды обсуждения, поэтому разбор — там.
- **Отдельный бот-процесс с long polling.** Не нужен: вебхук на том же процессе, nginx уже проксирует `/api/` интерфейсного имени.
