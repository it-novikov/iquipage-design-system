# 0014. Связанная задача поверх живой карты

Дата: 2026-10-12. Статус: proposed in PR; WP01 принятого плана, реализация явно поручена владельцем.

## Проблема

Maps передавала открытие связанной задачи оболочке, которая переключалась на Board и уничтожала MapsFeature. Положение, выделение, поиск и ввод инспектора принадлежат этому экземпляру. Замена ссылки «назад» не восстанавливает их.

## Решение

Maps host сохраняет экземпляр карты и открывает существующий полный Task dialog. Сохранение/dirty guard карты применяется при реальном уходе из раздела; просмотр Task сам по себе не закрывает инспектор. Task использует прежний close controller, capabilities и серверные команды.

Адрес `#maps/{mapId}/task/{taskKey}[/work]` хранит карту, задачу и вкладку внутри текущего project URL. Одна цепочка связанных Task занимает одну запись истории после карты. Back закрывает Task; Forward открывает её в той же карте. Отказ dirty-close восстанавливает запись истории. Прямой contextual URL закрывается к названной карте; hard reload восстанавливает identity, но не обещает persistence временных pan/selection/search.

Task dialog получает необязательные `initialSection`/`onSectionChange`; его controller предоставляет `setSection`. Необязательный `beforeOpen` выполняет guard замены после успешных начальных чтений следующей Task. До этого прежний drawer и его сообщения остаются доступны; успешная передача использует существующий `replace`, отказ сохраняет прежний drawer. Без этих параметров сохраняется прежнее поведение Board/Planning/Workbench. Копирование прямой ссылки по-прежнему использует canonical `taskURL`, независимо от contextual navigation.

Host отменяет предыдущий intent целиком: Task read, support loading и открытие другой карты через необязательный `signal` у MapsFeature.openMap. Проверки актуальности стоят до изменения текущей карты и после ожиданий в host. Возврат к уже видимой A также отменяет B, которая ещё загружается. Initial mount передаёт host последний адрес, сохраняя изменения hash, пришедшие во время его загрузки. Не найденная явно указанная карта не подменяется другой, более новой.

После отказа перехода shell берёт фактически оставшийся route у текущего владельца. Task могла уже принять закрытие, а карта — отказать в уходе; тогда адрес остаётся адресом карты, без ссылки на закрытый drawer. При отказе самой Task её drawer/адрес сохраняются.

Во время async mount локальный listener отменяет устаревший Task read/support; host сверяет актуальный hash и выполняет новую contextual цель перед передачей shell. Shell сохраняет последний native intent целиком — hash, history state и version — и применяет его после текущего перехода. Старый guard не может заменить этот intent своим восстановленным адресом. Canonical Task переходит к владельцу Board. После initial map error успешная повторная загрузка завершает сохранённый Task deep link на той же карте.

Reload не отключает dirty guard живой формы заранее. Ошибка чтения оставляет editable Task с доступным сообщением/повтором; новый комментарий по-прежнему требует подтверждения закрытия. Принятый `keepOpen` подтверждает конкретную попытку замены, не выставляя постоянный флаг discard у оставшейся формы: отменённая замена сохраняет защиту последующего ввода.

## Альтернативы и границы

- Восстанавливать карту после уничтожения: потребовалась бы отдельная сериализация transient состояния и восстановление фокуса/инспектора. Это сложнее сохранения нынешнего владельца.
- Менять только обратный URL: не исправляет lifecycle и вкладки, которые сами меняют адрес.
- Новый общий router или новый просмотрщик Task: расширяют изменение без необходимости.

DS, backend, права, schemas, зависимости и сохранение задач не меняются. Общие пробелы Task/Planning из исследования остаются отдельными пакетами.

## Проверка и откат

Actual controller tests проверяют историю, latest-intent, guards, identity и fallback. Короткий synthetic browser путь должен использовать две карты, явно связанную Task, настоящий host/dialog и exact vendor. Визуальная непрерывность, native Back/Forward и фокус не объявляются проверенными только по unit tests. Evidence и ограничения — в `.bridge/tasks/20261012-maps-task-context`.

Миграций нет. Откат — revert PR. После будущего deploy владельцем проверить Map→Task→Close/Back/Forward и отказ dirty-close; утрата контекста или обход сохранения — условие отката.
