# Материалы задачи

Решение для SPR-16: ссылки на макеты и документы хранятся отдельными ресурсами задачи. Описание, вложения и собственная ревизия задачи не меняются при сохранении материала. Публичные контракты находятся в `contracts/task-materials.ts`, HTTP-команды — в `TaskMaterialController`.

Чтение использует TASKS_READ, запись — TASKS_WRITE, в том числе у сервисных аккаунтов. Права текущего владельца или инициатора перепроверяются; служебный PAT с read не может писать. Существующее правило PAT write включает read. Старому агентскому grant только с tasks:write возвращается минимальная квитанция его команды, без чужого содержания. Принятый результат задачи блокирует новые изменения материалов, но повтор уже применённой команды возвращает прежний результат.

Идентификатор материала и привязка к задаче неизменны. Категории design и documentation, название до 200 знаков, адрес до 2048 байт UTF-8. Адрес хранится после trim без переписывания query, fragment, Unicode и IDN. Только абсолютный HTTP(S), без credentials, пробелов, управляющих знаков и неверного порта. Сервер проверяет адрес, но не обращается к нему. Повтором считается точное совпадение сохранённого адреса в одной категории одной задачи; архивированные записи не занимают активный адрес. Это не попытка установить эквивалентность разных URL.

Активных материалов не больше 100. Лимит и дубликаты проверяются под блокировкой проекта вместе с CAS, сохранением, аудитом и событием. Архивирование обратимо; прямое чтение архивированной записи позволяет сравнить конфликт и восстановить её. Восстановление повторно проверяет активный лимит и дубликаты. Ревизии ограничены точными безопасными целыми JavaScript; предел не допускает переполнения следующей записью.

Создание задачи с материалами состоит из создания задачи один раз и отдельных повторяемых команд материалов. При частичном отказе сохранённые материалы остаются, несохранённые черновики видны в форме; повтор не создаёт вторую задачу. Атомарный общий endpoint не нужен для этого сценария и усложнил бы существующее создание задачи.

Миграция078 аддитивна, с FORCE RLS и внешним ключом задачи. Прежний ledger077 строгого сервера не совместим с078. Откат интерфейса должен использовать заранее проверенный сервер с ledger078 и прежним web-пакетом; база и новые материалы сохраняются. Перед production нужны свежая резервная копия, доказательство перехода077→078 и совместимого отката, полный gate и два независимых ревью. Окно наблюдения — пять минут. Ошибки readiness, несовпадение образа или web-пакета, перезапуски либо повторяющиеся ошибки требуют возврата совместимого образа; обратное удаление таблицы не применяется.

Альтернатива со ссылками в описании не даёт отдельного редактирования, категории, архива и CAS материала. Новые сущности вики не смешиваются с внешними ссылками: документация проекта реализуется в SPR-17.
