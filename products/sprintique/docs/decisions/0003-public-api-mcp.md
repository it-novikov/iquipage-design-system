# 0003. Публичный API и удалённый MCP-сервер

- **Статус:** proposed
- **Дата:** 2026-09-29
- **Владелец:** it-novikov
- **Основание:** карточка `.bridge/tasks/20260929-public-api-mcp`, [план агентов](../agent-bridge.md), [вход](0002-sign-in.md)

## Контекст

Люди хотят работать с Sprintique программно: скриптом с токеном и через ИИ-ассистентов (Claude как custom connector, другие MCP-клиенты). Сейчас есть только два вида учётных данных: cookie-сессия браузера и токен агента одного проекта. Сессию нельзя отдать скрипту или стороннему клиенту, а токен агента — это отдельный принципал с правами проекта, а не человек.

Интерфейс живёт на `https://sprintique.iqui.page`, API для программ — на `https://api.iqui.page`. Оба имени ведут в один процесс: nginx проксирует на API-хосте только `/api/…`, `/mcp…` и `/.well-known/oauth-*`, остальное — 404.

## Решение

### Делегированные учётные данные человека

Два новых вида записей в `auth.credentials`, оба принадлежат человеку и действуют **только его правами** (членство, роль, RLS — те же, что в интерфейсе):

| Вид | Префикс | Откуда | Срок |
|---|---|---|---|
| `personal` — персональный токен | `spp_` | настройки, показывается один раз | 1–365 дней |
| `oauth` — токен доступа OAuth | `spo_` | `/api/oauth/token` | 1 час |

Refresh-токены (`spf_`), коды авторизации (`spc_`) и секреты клиентов (`sps_`) хранятся в своих таблицах. Все секреты — 256 случайных бит, в базе только SHA-256.

- **Скоупы:** `read` и `write`. Запрос с `read` без `write` может только читать: на REST — только `GET`, в MCP — только инструменты чтения. Проверка есть в транспорте и в `ProjectAccess` для всех прав записи.
- **Аудитория (RFC 8707):** токен выдаётся для одного ресурса: `https://api.iqui.page/mcp` (MCP) или `https://api.iqui.page` (весь API). MCP принимает обе, REST — только вторую. Персональный токен выдаётся для всего API.
- **Только интерактивная сессия:** выдача и отзыв доступа агентам, участники и приглашения, профиль проекта, фоновые операции, управление пространством, решения по предложениям агентов, принятие приглашений, управление токенами и подключёнными приложениями. Делегированный токен не может выпустить себе замену или обойти одобрение человека: `SESSION_REQUIRED`, 403.
- **Cookie на API-хосте не принимаются**: запрос с `Host` = API-хост без `Authorization` получает 401. CSRF и Origin по-прежнему обязательны для cookie-сессии; bearer-запрос не несёт окружающих учётных данных, поэтому CSRF к нему не применяется. CORS нет: браузерная страница не прочитает ответ.
- **Отзыв:** отключение человека (`disabled_at`) закрывает все его токены при следующем запросе; потеря членства закрывает проект сразу (RLS); отзыв приложения закрывает его токены доступа и refresh-токены в одной транзакции.

### Сервер авторизации OAuth 2.1

Эмитент — API-origin. Метаданные: `/.well-known/oauth-authorization-server` (RFC 8414) и `/.well-known/oauth-protected-resource[/mcp]` (RFC 9728). `WWW-Authenticate` на 401 от `/mcp` указывает `resource_metadata`.

- **Регистрация (RFC 7591), открытая:** `redirect_uris` — только `https://…` или `http://` на loopback (`127.0.0.1`, `[::1]`, `localhost`), без фрагмента и userinfo, до 10 (у loopback-адреса в запросе может отличаться только порт, RFC 8252 §7.3); `grant_types` ⊆ {authorization_code, refresh_token}; `response_types` ⊆ {code}; методы аутентификации `none`, `client_secret_post`, `client_secret_basic`. Незнакомые поля игнорируются, **никакой URL клиента не загружается** (нет SSRF, нет CIMD); из имени удаляются управляющие и невидимые символы форматирования. Лимит — бюджет входа на адрес, общего потолка нет (иначе поток с нескольких адресов закрыл бы регистрацию всем); клиенты без единого гранта удаляются через 7 дней.
- **Authorize:** `https://sprintique.iqui.page/oauth/authorize` — страница интерфейса. Человек входит как обычно, видит имя клиента (как **заявлено клиентом**), хост `redirect_uri`, запрошенные права и снимает `write`, если не хочет его давать. `redirect_uri` сверяется с зарегистрированным **точным совпадением строки**; при неверном клиенте или адресе редиректа нет. Только `response_type=code`, только PKCE `S256`. Код живёт 5 минут, одноразовый, привязан к клиенту, адресу, verifier, скоупам и ресурсу; в ответе есть `iss` (RFC 9207). Решение — POST сессии с CSRF и Origin. Страница не встраивается в рамки (`frame-ancestors 'none'`, `X-Frame-Options: DENY`).
- **Token:** `authorization_code` и `refresh_token`, нет implicit, password, client_credentials. Повтор кода отзывает выданный по нему грант. Refresh ротируется при каждом использовании; повтор уже заменённого refresh-токена в течение 60 секунд (потерянный ответ) выдаёт новую пару и отзывает предыдущую замену вместе с токенами доступа гранта, позже — отзывает весь грант. Refresh живёт 30 дней с последнего обновления. Повторное подключение того же клиента заменяет его прежний грант; грант без живых токенов не считается подключённым.
- **Revoke (RFC 7009)** и список подключённых приложений в настройках с отзывом.

Протокольные адреса — `/api/oauth/{register,token,revoke}`: их формат задают RFC (form-urlencoded, открытые метаданные), поэтому они вне версионированного `/api/v1` и его строгих Zod-контрактов. Интерфейсные адреса (`/api/v1/oauth/authorization`, `/api/v1/connected-apps`, `/api/v1/personal-tokens`) — обычные ресурсы `/api/v1` с контрактами.

### MCP

`POST https://api.iqui.page/mcp` — Streamable HTTP спецификации **2025-11-25** (принимается 2025-06-18; 2025-03-26 — нет, он требует пакетов JSON-RPC) в режиме без сессий: каждый POST — одно JSON-RPC сообщение, ответ — `application/json`; `GET` и `DELETE` — 405. Методы: `initialize`, `ping`, `tools/list`, `tools/call`, уведомления (тоже только с живым токеном). Заголовок `Origin`, если есть, должен совпадать с API-origin. Инструменты типизированы (`inputSchema`, строгий разбор, `annotations`), каждый вызов заново проходит аутентификацию и права человека в своей транзакции. Инструменты записи видны и доступны только со скоупом `write`; без него вызов получает 403 `insufficient_scope`. Текст задач, комментариев и карт возвращается как недоверенные данные с пометкой; команд из текста нет. Ресурсы и промпты не объявлены.

Инструменты: `list_projects`, `search_tasks`, `get_task` (с обсуждениями), `create_task`, `update_task` (CAS `baseRevision` + ключ идемпотентности), `change_task_status`, `add_task_comment` (с ключом идемпотентности), `list_releases`, `list_milestones`, `list_maps`.

### Аудит, лимиты, метрики

- В `app.audit_events` добавлены вид учётных данных и `client_id`: видно, кто и каким приложением изменил данные. События доступа (выдача и отзыв токена, подключение и отключение приложения, повтор кода или refresh) — в `auth.access_events`, без секретов и содержимого.
- Окно запросов на учётные данные: 600 в минуту на bearer-учётные данные (все токены доступа одного подключения делят окно), считается после того, как токен найден живым, — выдуманные токены не вытесняют настоящие. Запросы с bearer-токеном не тратят окно адреса: серверы ассистента несут токены многих людей с немногих адресов; отказанный токен (401) стоит адресу одного запроса, а адрес с исчерпанным окном получает отказ с любым токеном. Регистрация — в бюджете входа (20 в минуту на адрес), token и revoke — в общем окне адреса.
- Метрики MCP — по имени инструмента из фиксированного списка и исходу; логи — имя инструмента, исход, длительность, без аргументов и результатов.

## Альтернативы

| Вариант | Почему не выбран |
|---|---|
| Официальный Java SDK MCP 2.0.1 (`mcp-core` + `mcp-json-jackson3`, сервлетный stateless-транспорт) | Совместим со Spring Boot 4 и JDK 25, но: транспорт отдаёт клиенту и пишет в лог `e.getMessage()` (тексты разбора JSON с фрагментами тела, SQL-ошибки), что нарушает правила ошибок и логов; тянет Reactor и второй валидатор JSON Schema в блокирующий сервер «транзакция на запрос»; авторизацию и лимиты всё равно пришлось бы строить вокруг. Нужное подмножество (stateless, только инструменты) — около 400 строк. Совместимость проверяется официальным клиентом TypeScript SDK и MCP Inspector. |
| Сессии MCP и поток SSE (`GET /mcp`) | Серверу нечего слать клиенту без запроса; сессии добавили бы состояние процесса и мешали бы горизонтальному масштабированию. Спецификация допускает сервер без сессий. |
| Внешний сервер авторизации (Keycloak) | Второй источник личности, отдельная выкладка и хранилище. Вход уже живёт в сервере ([0002](0002-sign-in.md)); OAuth-сервер переиспользует ту же сессию, CSRF и аудит. |
| JWT вместо непрозрачных токенов | Отзыв сработал бы только по истечении; каждый запрос и так идёт в базу за правами и RLS, поэтому поиск по хэшу ничего не стоит. |
| Токены на проект, как у агентов | Человек работает во многих проектах; делегирование «как я» с `read`/`write` проще и не шире прав человека. Узкие токены на проект можно добавить отдельным скоупом. |
| Client ID Metadata Documents | Требуют загружать URL клиента, то есть исходящие запросы по адресу из запроса (SSRF). Claude и другие клиенты умеют DCR. |

## Проработка

1. **Сценарии и роли.** Скрипт с персональным токеном; Claude по OAuth; человек отзывает доступ; наблюдатель получает только чтение, потому что его роль не пишет; токен с `read` не пишет даже у администратора.
2. **Данные и доступ.** Делегированный токен = права человека ∩ скоуп; RLS тот же. Операции безопасности — только в сессии. Секреты — только хэши. Результаты инструментов не выходят за проекты человека.
3. **Ошибки, конкуренция, повторы.** Изменения задач — CAS `baseRevision` и журнал идемпотентности (ключ из инструмента или сгенерированный). Код и refresh одноразовые под блокировкой строки гранта; повтор распознаётся. Отзыв во время запроса перекрывает барьер записи `projectWriteFence`.
4. **Лимиты.** Тело 128 КиБ; поиск до 50 задач; обсуждение: до 20 тредов и 50 сообщений в каждом, текст до 4000 символов; 20 персональных токенов и 50 подключённых приложений на человека; 600 запросов в минуту на токен.
5. **Зависимости.** Новых библиотек нет. Без базы — 503, как везде.
6. **Миграция и откат.** Одна аддитивная миграция `V20260929000027` (новые таблицы, новые виды в `auth.credentials`, столбцы аудита). Откат: выключить API-хост в nginx и отозвать все делегированные записи (`UPDATE auth.credentials SET revoked_at=now() WHERE kind IN ('oauth','personal')`); образ предыдущей версии не стартует на новом ledger, поэтому откат кода — через резервную копию, как для любой миграции.
7. **Альтернативы** — выше.

## Последствия

- Claude подключается к `https://api.iqui.page/mcp` сам: регистрация, вход, согласие, токены.
- Каждый запрос с делегированным токеном стоит одного поиска по хэшу и, раз в пять минут, записи `last_used_at`.
- nginx API-хоста должен передавать `Host $host` и `X-Forwarded-For`; `SPRINTIQUE_API_ORIGIN` задаёт API-origin.
- Проверка: HTTP-тесты полного потока и правил безопасности, ручная проверка официальным MCP-клиентом.
- Отказ: удалить маршруты `/api/oauth`, `/mcp` и виды `oauth`/`personal`; данные остальных модулей не зависят от них.

## Условия пересмотра

- Нужны уведомления сервера клиенту (прогресс, подписки) — сессии MCP и SSE.
- Больше одного процесса API — общий лимитер вместо окна процесса.
- Официальный SDK перестанет раскрывать тексты ошибок и станет блокирующим — перейти на него.
