# W3. Независимые ревизии полей и водяной знак значимых событий

- **Статус:** accepted
- **Дата:** 2026-09-29
- **Основание:** delivery-plan §2.F, §3.2, §8

## Контекст

Отметка «просмотрено», перестановка фокуса и откладывание происходят в разных вкладках одновременно. Один CAS на всю строку превратил бы их в ложные конфликты. Ревизия задачи растёт от любой правки описания и не отвечает на вопрос «было ли что-то важное после моего просмотра». Аудит хранит только «task.updated» без того, что изменилось.

## Решение

1. **У каждого личного поля своя ревизия:** `follow_revision`, `focus_revision`, `seen_revision`, `snooze_revision` в `app.task_personal_state`; у «Жду» — `revision` в `app.task_wait_state`. Отсутствующая строка — ревизия 0.
2. **Команда на поле:** `PUT /api/v1/projects/:projectId/tasks/:taskId/personal/{follow|focus|seen|snooze}` с `baseRevision` этого поля и `Idempotency-Key`. Тело не принимает другие поля (строгий контракт). Устаревшая ревизия — `409 CONFLICT` только для этого поля.
3. **Фокус** — `action: add | remove | up | down`. Порядок — `focus_rank` (bigint с шагом 1 048 576; при исчерпании промежутка ранги человека перенумеровываются без смены ревизий соседей — порядок не их поле). Лимит фокуса 200.
4. **Значимые события — `app.task_activity`**, позиция `sequence` выделяется под блокировкой строки проекта (`projects.activity_sequence`), как `outbox.project_sequence`: порядок позиций равен порядку фиксации. Пишут триггеры в транзакции изменения, поэтому доска, планирование и агенты дают события одинаково:
   - задача: `status`, `completed`, `reopened`, `owner`, `due`, `planned`;
   - связь `depends`: `dependency` для обеих задач;
   - обсуждение: `thread` (новое сообщение), `resolution`;
   - запрос: `request` (создан, решён, отменён, переназначен, осиротел).
   В `detail` — только коды, даты и id людей; без названий и текста.
5. **Водяной знак** — `last_seen_sequence` задачи для человека. `seen` двигает его только вперёд и не дальше последнего события задачи. Он ставится на текущую позицию при начале отношения (подписка, «Жду», свой запрос), чтобы история до отношения не считалась новой.
6. **Свой шум подавлен:** события, где актор или инициатор (агент по гранту человека) — сам человек, не считаются. Одна задача — одна строка «Изменилось» с числом событий (до 99+) и последним событием как причиной.

## Последствия

- Две вкладки: «просмотрено» и перестановка фокуса не конфликтуют; тест проверяет независимость CAS.
- Старые миграции и будущие правки данных без актора событий не создают (триггер пропускает запись без `app.actor_id`).
