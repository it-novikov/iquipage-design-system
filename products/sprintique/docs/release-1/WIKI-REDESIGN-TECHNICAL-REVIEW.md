# Wiki redesign — независимое техническое ревью плана

2026-10-11. Проверены revision1 и revision2 плана с root-уточнениями, research, ADR0013, contracts/wiki.ts, текущие wiki.js/wiki-model.js и public DS46 tree/editor/viewer declarations. Reviewer не автор UI; runtime/DS/prototype не менялись. Это оценка реализуемости до реализации, не приёмка интерфейса или production.

## Вывод

Композиция реализуема на текущих API и существующих TASKS_READ/WRITE, включая сервисные аккаунты. Новые backend сущности, права, autosave и coediting не нужны. Метаданных ограниченного каталога достаточно для дерева, breadcrumbs и пяти последних изменений; история/search/backlinks остаются cursor pages. Выбранная двухколоночная история не требует другой модели данных.

Revision2 закрывает WTR-01 и определяет минимальный WTR-02 на уровне спецификации. План технически одобрен; public DS contract review/размер, реализация и affected regressions остаются последующими обязательными шагами. Это не закрытие дефектов старого runtime посредством документа.

## Findings

- **WTR-01 [P1] confirmed plan gap** `WIKI-REDESIGN-PLAN.md:61`, `web/wiki-model.js:14` — конфликт описан как сравнение title/body и архива, но PUT включает также parentId. Текущий review() обновляет baseRevision и сохраняет старое место draft. Сценарий: другая вкладка переносит документ; редактор получает409, просматривает новый текст и сохраняет свой. Запись полного прежнего объекта молча возвращает старого родителя. Решение: показать актуальное место/архив и определить политику полного объекта. Обычная правка текста сохраняет актуальные структурные поля; отличающийся перенос/restore draft требует явного отдельного решения. Повторный409 сбрасывает проверку. Regression: concurrent move→409→review→save own text сохраняет актуального родителя; concurrent archive показывает последствия и не восстанавливается незаметно. Статус: closed в revision2 specification (строка115): latest parentId/archived сохраняются, restore явный, repeat409 сбрасывает review. Runtime repair и указанный regression обязательны при реализации.

- **WTR-02 [P2] contract required before implementation** `WIKI-REDESIGN-PLAN.md:75` — public headings/focusHeading необходимы оглавлению, но минимальный контракт ещё открыт. Зафиксировать plain-text entries `{id,level,text}`, источник из того же безопасного Markdown разбора, deterministic unique IDs для одинаковых заголовков, bounded число/уровни, focus/scroll результат и invalid-id no-op. ID стабилен для неизменного source; это не обещание стабильности между произвольными правками. Оглавление не должно изменять `#wiki/page/...` или читать private DOM. Несколько viewer (current/history/conflict) не должны иметь конфликтующие anchors; обновление value сбрасывает устаревший selection без перехвата внешнего focus. Public types/docs/regressions и exact package обязательны. Статус: closed на plan level в revision2 (строка121): readonly headings, boolean focusHeading, deterministic suffix, iq-outline-change, no hash mutation. Final DS review до кода должен закрепить дополнительные edge tests ниже.

## Границы реализации и проверки

1. Draft отделён от page/route/catalog. Dirty guard применяется к tree intent, breadcrumb, search/history/archive, task backlink, project/section и browser back. iq-navigate отменяется синхронно, затем consumer решает переход; accepted transition не дублирует navigation через iq-change. «Остаться» сохраняет value/caret/route; events/refresh не пересоздают редактор во время IME. Сохранение, последующий GET и неизвестный результат записи — разные состояния; потерянный ответ повторяет исходный snapshot/key, не сообщает «сохранено» без API подтверждения.
2. Read-only и revoked права не раскрывают write controls;403 сохраняет текущий текст для копирования. Backend остаётся границей authorisation. Реальное прекращение сессии/уход не выдаётся за постоянный private draft: local persistence не обещана. Task→wiki links используют отдельный typed endpoint, CAS/архив и accepted-task guard; внешние материалы SPR16 не переписываются.
3. Version restore берёт title/body выбранной версии, оставляет текущее место и создаёт новую revision. Archive restore повторно проверяет активного родителя. Move excludes self/descendants, depth12 и archive-with-children подтверждаются сервером при каждом effect. Перенос пользователя не меняется посредством текстовой правки без осознанного решения.
4. Catalog1000 должен быть complete; превышение/ошибка не подменяются урезанным деревом. Search/history/backlinks50 загружаются дальше cursor без потери уже полученных элементов. Search state/query и page/history state разделены; aborted/superseded responses не рисуют другой режим. Архивная прямая ссылка остаётся узнаваемой. Path/excerpt показывают только доступный каталог и экранируются; HTML/Markdown stripping применяется лишь к presentation, не к сохранённому body.
5. DS-GAP01/02 разумно оформить тонкими public appearance/density и documented composition; lifecycle/API остаются в продукте. GAP03 определяется реальным existing editor, не заменой его собственным editor. Для mobile panel нужны именование, focus trap/Escape/return и dirty guard. Длинный путь/depth12 не вытесняет действия. Public46 API не содержит предлагаемого outline/variant: прототип не является доказательством существующего контракта. Для outline обязательны invalid-id=false/no-op, level1–6/plain text из одного безопасного разбора, уникальные anchors нескольких current/history/conflict viewer, value refresh без перехвата внешнего focus и проверка длинного body100000 без неограниченного DOM-вывода списка.
6. Запас Linux46 core531B/CSS576B мал. Реализуемость объёма новых DS функций пока не доказана размером: измерить exact следующий пакет на official Linux Node24.20, не повышать budgets и не удалять рабочее поведение. Если пакет не помещается, представить выбор владельцу до adoption. Проверить1000 deep/wide catalog: initial render, expansion/keyboard/navigation, refresh focus; фиксировать фактические measurements без выдуманного performance PASS.

## Не проверено

Новый runtime не реализован и не прогонялся этим reviewer. Кликабельный synthetic prototype не даёт CAS/rights/persistence proof. Самостоятельный browser/device usability, touch/IME/screen reader и новые Linux byte measurements не выполнялись. Внешние исследования прочитаны как входные данные; их сравнительные UX выводы не выдаются за собственное исследование или доказанное ускорение.

**Вердикт:** approve revision2 technical plan после targeted rereview двух исправлений. Открытых technical plan P1/P2 нет. Реализацию разрешает root после остальных независимых review; этот вывод не утверждает новый DS/runtime или доказанное улучшение UX.

## Отдельное pre-code ревью четырёх public DS контрактов

Проверен proposed minimum revision2 против существующих public46 declarations, tree-navigation.md, editor/work-layout source. **Одобрено для реализации при соблюдении следующих обязательных границ.** Это approve контрактного направления; перечисленные свойства должны войти в public docs/types и affected tests, а не оставаться устными допущениями.

Для04 не требуется публичный доступ к heading DOM, generic selector/execute или дополнительный Markdown parser в продукте. In-page anchors — presentation, не стабильные permalink IDs между произвольными правками документа. Event не является сигналом сохранения. При explicit переходе в heading фокус попадает в сам заголовок с visible focus; программное обновление оглавления этого не делает. Reduced motion применяется к прокрутке без обязательного smooth.

Release gate сохраняется: public docs/types → meaningful legacy/new regressions → exact pack/adoption → official Linux core/CSS budgets без повышения → product scenarios и независимое финальное review. Запас46 пока не доказывает, что все четыре расширения поместятся; при превышении сначала представить root стоимость/варианты. No runtime/DS source changes выполнены этим reviewer.
