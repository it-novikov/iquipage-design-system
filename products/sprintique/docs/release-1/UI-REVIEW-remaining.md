## Поставка DS

Недостающая возможность: несколько групп radio choices с управляемым раскрытием завершённых. Публичный `ui.choiceGroups` композиционно использует уже существующие native radio groups и details; поиск, выбранное значение, сортировка и запись принадлежат продукту. API, декларации, документация и тесты поставляются в пакете. Вопрос внутри `.iq-thread-content` разделяет рамку треда, без второй вложенной рамки.

Финальная поставка: `@iquipage/web@0.6.0-vnext.42`, `vendor/iquipage-web-0.6.0-vnext.42.tgz`.

SHA256: `277e03b1dfe39bd30eca8d0304c2f5147d4cea1cf60fefabc7d9a0bf83e96f53`.

JS, CSS и declarations установленного пакета побайтово совпали с итоговой DS сборкой. Промежуточные .40 и .41 удалены из product vendor; ранее принятый .39 сохранён. .41 исправил README с устаревшей политикой toast; .42 закрывает findings первой приёмки. Использованные архивы не перезаписывались.

## Findings первой приёмки

R1-focus (P2): перерисовка кнопки ответа теряла фокус; старый механизм восстанавливал только обычные thread actions по threadId. Новый `thread-focus.js` сохраняет точный атрибут и questionId, удерживает фокус на треде во время disabled pending и переводит его на доступный контрол либо заголовок сохранённого вопроса. Черновик и положение каретки переживают refresh; уход пользователя за пределы треда не вызывает захват фокуса назад. Пять regression tests прошли. Визуальная проверка клавиатурой остаётся у координатора.

R1-heading: раскрытые завершённые задачи повторяли заголовок summary в legend. В .42 summary остаётся видимым названием; legend visually hidden, но доступен screen reader. Публичный `radioGroup` получил документированный `legendHidden`; choiceGroups применяет его для раскрываемых групп. Regression проверяет обе структуры.

R1-size: .41 CSS после финального build превысил прежний лимит на 37 B gzip. Ранний PASS DS тестов был получен до этой финальной сборки и не закрывает размер .41. В .42 объединены одинаковые правила рамки и удалён избыточный селектор byline; бюджет не изменялся. Итоговый порядок build → tests → pack выполнен, затем тесты повторены по упакованной сборке. CSS: 101608 B при лимите 101612; core closure: 185053 B при лимите 185291; icons: 56097 B при лимите 57218. Все 459 DS tests проходят на итоговой .42 сборке.

Статический сигнал broken-image в существующей обложке карточки исследован: `cover-loader.js` получает авторизованный blob, назначает `img.src` и backdrop.src при попадании в viewport; при ошибке показывает fallback. Отсутствие src в исходной HTML-строке намеренное, не новый дефект SPR-24.

## Обязательный runtime handoff

SPR-4: открыть задачу с linked question; выбрать вариант, добавить комментарий, подтвердить, проверить единственный ответ в исходном треде и сохранённое решение после reload. Проверить read-only и запрет `canAnswer`. Во время набора внести competing work revision: черновик и фокус сохраняются, отправка требует просмотра новой версии через «Вопрос проверен». Если другой человек уже решил вопрос, неотправленный текст остаётся видимым с явным удалением черновика. Открыть и закрыть историю обсуждения клавиатурой. Проверить обычные question/comment/reply/resolve без агентского вопроса.

SPR-8: success, error и action toast исчезают через 3,5 секунды, если пользователь их не удерживает фокусом или указателем; undo остаётся рабочим до исчезновения. Состояние offline остаётся до восстановления соединения.

SPR-20/23: board, planning, maps overview и canvas, finance, agents, settings, workspace и Workbench, затем search overlay. Проверить единый верхний navigation, active route, переход к настройкам и профилю, выбор project/workspace, сохранение contextual actions, отсутствие loader под готовым контентом. Светлая/тёмная темы, 390 px и desktop, keyboard, Back/Forward. Отдельно проверить horizontal overflow длинных имён; source review не закрывает этот пункт.

SPR-21: task→bug→epic на новой и существующей задаче с пустым/неизменённым шаблоном; затем свой текст, отмена и подтверждение замены; сохранение и reload. Убедиться, что собственный текст не исчез, а нетронутый шаблон новой задачи по SPR-12 не сохраняется как описание.

SPR-22: same-release, inherited-release и explicit no-release targets; текущий/другой release при поиске по номеру и названию; completed секция изначально закрыта, открывается клавиатурой; выбранный target остаётся выбранным при изменении запроса. Проверить draft release context и существующую проверку циклического родителя.

SPR-24: незавершённый блокер вне текущей доски, несколько блокеров, завершение/архивация блокера, удаление/смена направления связи и unrelated link. Сигнал должен следовать серверной проекции после event reload. Неподдерживаемая историческая проекция не показывает ложное «разблокировано».

Review-only SPR-5/6/7/9/10/12/13: вставка Markdown-ссылки; mention сервисного аккаунта; assignee сервиса; раскрытие обычного обсуждения; углы доски; удаление нетронутого шаблона; release switcher. Принятые реализации не переписывались, кроме связанной с SPR-21 обработки типа и согласованной общей политики toast.

Код UI/DS заморожен после указанных проверок. Дальнейшие правки — только по конкретным результатам приёмки. Коммит, push, deploy и production writes автор UI не выполнял.
