## Основной экран

Один пункт «Документация» в существующей проектной навигации, рядом с задачами, планированием и картами. Сохраняются workspace/project switchers, профиль, поиск и активный маршрут. Не создавать отдельный shell или вторую верхнюю панель. После переноса первой волны использовать общий pageHeader adapter и публичный iq-work-header title/back/actions/context из DS .45; в текущем wiki checkout принят exact DS .46 и общий adapter.

На широком экране под общим header — две колонки: навигация по страницам примерно260px и читаемый документ с максимальной длиной строки около76ch. Ширина навигации — предлагаемый ориентир, проверяется на длинных названиях. Слева поле «Найти страницу», дерево и тихий переход «Архив». Справа заголовок текущей страницы, одна основная кнопка «Изменить», меню дополнительных действий и текст. «Создать страницу» находится у дерева; действие «Создать вложенную» — в меню текущей страницы. Название проекта не дублируется в каждой области. Автор и время изменения помещаются одной вторичной строкой под заголовком.

Корневой маршрут без выбранной страницы показывает дерево и короткое пустое/начальное состояние справа: «Выберите страницу» либо «В проекте пока нет документации» с «Создать страницу» для редактора. Не открывать случайный документ автоматически. На390px показывается одна рабочая область: каталог либо документ; «К страницам» возвращает дерево с прежним поиском, раскрытием и прокруткой. Это переключение представления внутри маршрута, не постоянно открытый overlay поверх текста. На планшете переход в одну колонку определяется доступной шириной, а не уменьшением масштаба.

Предлагаемые маршруты: `#wiki`, `#wiki/<id>`, `#wiki/<id>/edit`, `#wiki/<id>/history`, `#wiki/<id>/history/<revision>`, `#wiki/archive`. ID стабилен, переименование не меняет ссылку. Deep link и browser back восстанавливают выбранную страницу; редактор не теряет текст при смене области дерева. Переход из задачи хранит внутренний return context и показывает «К задаче SPR-…» в публичном back slot. Произвольный внешний return URL не принимается.

## Дерево и поиск

Каждый узел — самостоятельная страница, даже если у неё есть дети. Нажатие на название открывает страницу; отдельное раскрытие показывает детей. Выбранный узел отличается от клавиатурного фокуса. Deep link раскрывает предков; обновление списка сохраняет доступные раскрытые ветки и фокус. Перемещение делается командой «Переместить» с выбором родителя и корневым вариантом «В корень документации». Drag-and-drop не обязателен для первого рабочего выпуска и не заменяет доступную команду.

Поиск ищет по названию и тексту внутри текущего проекта; выдача заменяет дерево плоским списком, а очистка восстанавливает прежнее дерево. В результате: название, короткая выдержка и путь родителей, когда он помогает отличить одинаковые названия. HTML-подсветка с сервера не исполняется. Запрос задерживается примерно250мс, старый запрос отменяется; поздняя выдача другого текста не применяется. Enter открывает выбранный результат, Escape очищает поиск без неожиданного ухода со страницы. «Показать ещё» добавляет следующую страницу результатов, курсор привязан к запросу. Архив по умолчанию не примешивается к активным страницам.

## Чтение и редактирование

Чтение использует iq-markdown-viewer, headingLevel=2: заголовок страницы остаётся единственным h1. Ссылки и код доступны стандартной клавиатурой. Поддерживается фактическое безопасное Markdown-подмножество DS; картинки, вложения wiki, таблицы или иные расширения нельзя обещать по одному наличию редактора. В первом контракте нет удалённой загрузки превью, iframe, публичных страниц и совместного редактирования текста в реальном времени.

«Изменить» открывает редактор в той же контентной колонке: поле названия и iq-markdown-editor, без модального окна для длинного текста. В заголовке действия «Сохранить» и «Отмена»; рядом короткий статус только при изменениях/записи/ошибке. Сохранение явное, Ctrl/⌘+Enter выполняет ту же команду вне IME composition. Первый ввод переводит форму в dirty; во время записи повтор команды блокируется. «Сохранено» относится к подтверждённой revision. Повтор потерянного ответа не даёт оснований затереть чужую следующую правку.

Навигация в другую страницу, проект или раздел проходит общий readyToLeave guard: сохранить, остаться либо явно уйти без сохранения. Закрытие вкладки использует beforeunload для dirty/pending. Серверное событие об изменении не заменяет поля открытого редактора. При409: «Страницу изменили в другом месте. Ваш текст остался в редакторе», затем отдельное чтение актуальной версии для сравнения. Новая запись допустима лишь после явного решения и с проверенной revision; не устраивать цикл автоматической перезаписи. При403 поля остаются доступными для копирования, сообщение «Сейчас у вас нет права менять эту страницу» не обещает повтор без восстановления доступа.

## История, архив и связи

История открывается из меню в контентной области, сохраняя дерево и страницу. Список версий постраничный: время, автор, краткая причина, действие просмотра. Выбранная версия показывается тем же viewer с явной подписью «Версия N» и возвратом к текущей. «Восстановить эту версию» доступно только редактору и только после просмотра полного текста; подтверждение сообщает, что появится новая версия, а история сохранится. Если текущая страница изменилась за время просмотра,409 требует повторного решения. Визуальный diff не является обязательным для первой версии; нельзя обозначать обычный просмотр как сравнение различий.

Архив — отдельный список с поиском и постраничной загрузкой. Открытая архивная страница остаётся читаемой по прямой ссылке и из задачи, имеет спокойную подпись «В архиве» и действие «Вернуть из архива». Удаление привязки к задаче не архивирует страницу. Поведение архива родителя с дочерними страницами должен определить backend-контракт до runtime: UI показывает точный scope команды и количество затронутых страниц, не обещая автоматически архивировать/вернуть всю ветку. Восстановление исторического текста по умолчанию предлагается отделить от перемещения и архива; точный набор полей должен быть согласован с root.

Под документом — компактное «Связанные задачи (N)» только при наличии связей; первые несколько задач и раскрытие остатка, без второй копии полного описания. В задаче SPR-16 «Добавить документ» получает понятный выбор «Страница проекта» / «Внешняя ссылка», default определяется контекстом. Для wiki target нужен стабильный pageId, не маскировка под task→task relation и не сохранение абсолютного URL вместо типизированной цели. Выбор показывает название/путь/архивный статус; удаляется лишь связь. Контракт расширения materials и backlink pagination делает root отдельно.

## DS fit и подтверждённый gap

Существующих публичных средств достаточно для общего header, кнопок/меню/dialog, Markdown editor/viewer, полей, выбора родителя через remote-combobox, skeleton, feedback и обычных ссылок. Две колонки и мобильный выбор области — прикладная геометрия, не новый визуальный язык. iq-work-layout не является master/detail shell: его navigation slot расположен над контентом; не менять его private grid ради вики. iq-settings-layout привязан к сценарию настроек, поэтому не подменять им весь новый раздел автоматически.

**DS-GAP-WIKI-NAV-01, confirmed по source:** iq-tree в `src/modules/structured.js` открывает только лист. Нажатие/Enter на узле с children выполняет toggle, поэтому страницу-родителя прочитать нельзя. Его header/search/status имеют фиксированные подписи «Рабочие разделы», «Найти раздел», «Выбран раздел»; отдельного публичного контроля раскрытых узлов и host navigation guard нет. Чтение этих внутренних узлов или CSS-скрытие запрещено.

Предлагается расширить публичный iq-tree совместимым navigation mode. В нём название любого узла активирует страницу, disclosure меняет только раскрытие; Arrow keys/Home/End управляют деревом, Enter активирует и родителя. Требуются публичные expandedIds:string[], текущая value, настраиваемые accessible labels и компактный вариант без встроенного header/search/status для host-owned server search. Запрос навигации должен быть отменяемым до применения selection, чтобы dirty editor мог оставить прежнюю страницу. Реальные href нужны для открытия ссылки в новой вкладке, при этом main-click проходит navigation guard; unsafe protocols запрещены. Setter items/value не должен рвать фокус или сбрасывать раскрытие, программная синхронизация не порождает команду сохранения.

Default/checkable поведение сохраняется. Не использовать leaf-фиктивный дочерний узел «Открыть страницу» как обход — это лишний клик и ложная структура. Новый контракт требует types/docs, regression на branch activation/cancel/expanded/focus/keyboard, exact version/tar adoption и прежние budgets. Если итоговый API выбирает отдельный navigation-tree вместо mode, те же инварианты обязательны; решение принимается перед кодом. Иных доказанных DS gaps пока нет; long Markdown performance и mobile toolbar должны пройти runtime-проверку на фактическом согласованном максимуме текста.

## Потребности к API и интеграции

Root фиксирует typed list/read/save, history/version/restore, archive/restore и search. Для дерева нужна вся ограниченная метаиерархия без body: id,parentId,title,revision,archivedAt и предки выбранной страницы. Если выдача постраничная, UI должен знать complete/cursor и не называть частично полученное дерево полным. Нужны заданный порядок соседей, archive-parent policy, restore-version field scope, limits и actor display name/kind для авторства сервиса. Нельзя выводить скрытые owner data вместо действительного автора. Realtime events должны нести projectId/pageId/revision; resync может идти без pageId.

Пути внедрения после переноса первой волны: `web/main.js` — lazy section, routes, project switch/readyToLeave; `ui/planning/src/project-navigation.js` — единый пункт/active; `web/search.js` — kind wiki и открытие результата при наличии server support; новый `web/wiki-host.js` и `ui/wiki/` — controller/model/view/styles; `ui/src/loading.js` — документ и дерево; `ui/src/page-header.js` — reuse без fork; SPR-16 `ui/src/board/task-materials.js` — typed wiki target только после API. Backend/repository/contracts принадлежат root. DS gap — `structured.js`, public core types/docs/tests и новый exact tar; private selectors продукта не добавляются.

## DS implementation status, 2026-10-11

Public iq-tree navigation gap is implemented in vnext.46; contract and ADR are in libraries/iquipage/docs/tree-navigation.md. The consumer listens to cancelable iq-navigate, synchronously cancels if there is an unsaved editor, and applies value after the user decision. Expansion persists separately through expandedIds/iq-expand. Empty heading and hide-search let the page own full-content search. The server depth policy (12 levels including root) fits the existing DS bounded tree. Standalone wiki page runtime is implemented; browser acceptance remains pending.
