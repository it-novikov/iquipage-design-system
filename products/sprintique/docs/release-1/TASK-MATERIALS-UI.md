# SPR-16: материалы задачи — предлагаемая композиция

2026-10-11. Только UI-спецификация, без runtime-реализации и без изменения прав. Исходник: worktree `wiki`, публичная DS в package.json — 0.6.0-vnext.43. После слияния первой волны исполнителю нужно заново проверить фактически принятый exact package. WIKI-RESEARCH.md прочитан как предложение; его модель wiki, лимиты и права не считаются утверждёнными этим документом.

## Задача и границы

Человек открывает задачу и быстро находит нужный макет или документ, не просматривая весь текст описания и историю обсуждения. Материал — именованная HTTP(S)-ссылка одной из двух категорий: «Дизайн» или «Документация». Несколько материалов одной категории допустимы. Файлы остаются в существующем разделе «Файлы», связи задач — в «Связях». Новые wiki-цели появятся только после отдельного решения о правах SPR-17.

Чтение наследует доступ к задаче; изменение — её фактическое canEdit, включая запрет редактирования принятого результата. Не появляются новые разрешения, публичность или автоматическое расширение прав сервисных аккаунтов. Скрытие пустого раздела — способ сократить экран, а не проверка доступа.

## Композиция drawer

Материалы находятся на вкладке «Задача», сразу после описания и перед связями/файлами. Заголовок задачи, вкладки и принятые отступы не меняются. Новая вкладка, отдельная страница управления и две большие пустые карточки не нужны.

Когда обе категории пусты, редактор видит одну компактную строку действий: «Добавить макет» и «Добавить документ». Нажатие сразу открывает форму ссылки с уже выбранной категорией. Заголовков пустых групп, счётчиков «0», рамок и пояснительных абзацев нет. В режиме чтения пустая строка скрыта полностью.

Когда категория заполнена, она получает небольшой заголовок «Дизайн» или «Документация», число материалов и доступное редактору действие «Добавить». Под ним сразу видны первые три ссылки в порядке добавления. Название — настоящая ссылка; рядом небольшой знак внешнего перехода, под названием приглушённый hostname. Полный URL доступен в стандартном контекстном меню ссылки и в редактировании, но длинные query-параметры не занимают экран. Фавиконки, remote previews, большие иконки и декоративные карточки не загружаются.

Если ссылок больше трёх, ниже идёт native disclosure «Ещё 4 материала». Раскрывается только остаток; первые три не дублируются. Состояние раскрытия сохраняется при обновлении данных и редактировании в открытом drawer. Новый успешно добавленный материал всегда виден: при необходимости остаток раскрывается. Категория без материалов остаётся коротким действием «Добавить макет/документ» после заполненной группы. Категории идут в постоянном порядке: дизайн, документация.

Это предложенный порог компактности, а не серверный лимит: три видимые ссылки на категорию. На телефоне структура та же, в одну колонку; длинное название переносится максимум на две строки в свернутой группе, полное доступное имя ссылки сохраняется. Ссылки и меню имеют отдельные области нажатия, не вложенные interactive elements. Название и hostname не раздвигают viewport.

## Добавление и изменение

Один прямой переход из строки или заголовка открывает компактный dialog поверх задачи: «Добавить макет» либо «Добавить документ». Первый фокус — поле «Ссылка», затем «Название». Оба значения обязательны; URL — HTTP или HTTPS. После вставки можно предложить hostname как редактируемое начальное название, но не запрашивать внешнюю страницу и не выдавать hostname за извлечённый заголовок.

Основная кнопка — «Добавить». Для последовательного ввода нескольких материалов рядом есть «Добавить и ещё»: сохраняет ровно текущую ссылку, после успеха очищает поля и ставит фокус в «Ссылка», сохраняя категорию. Это не массовая атомарная операция: уже добавленные материалы видны в задаче; неуспешный следующий остаётся в форме. Не закрываем и не открываем несколько уровней выбора источника.

У каждой строки редактор видит небольшую кнопку меню с accessible name «Действия материала: …». В меню только «Изменить» и «Убрать из задачи». Изменение открывает ту же форму с названием, URL и полем «Раздел» для переноса между дизайном и документацией; основные кнопки — «Сохранить» и «Отмена». В обычном чтении поле категории не повторяется в каждой строке.

«Убрать из задачи» удаляет только привязку, не внешний документ. Предпочтительно обратимое удаление с «Вернуть», если backend предоставляет восстановление. До подтверждения этого контракта — короткий dialog «Убрать ссылку из задачи?» / «Сам материал останется доступен по прежнему адресу», кнопка «Убрать ссылку». Нельзя обещать undo без серверной команды.

## Состояния и тексты

| Состояние | Поведение и microcopy |
|---|---|
| Пусто, можно менять | Только «Добавить макет» / «Добавить документ». Одна кнопка сразу ведёт к форме. |
| Пусто, только чтение | Блок отсутствует; не предлагаем недоступные действия. |
| Заполнено | Именованные ссылки, hostname, число и первые три строки; «Ещё N материалов». |
| Первое чтение | Небольшие outlines строк материалов; не показывать пустое приглашение до успешного ответа. Если данные приходят вместе с задачей, отдельный loader не нужен. |
| Обновление списка | Прежние ссылки остаются; существующий черновик и фокус не перерисовываются. |
| Ошибка чтения | «Не удалось загрузить материалы» и «Повторить». Не выдавать ошибку за отсутствие ссылок. |
| Неверный URL | Ошибка у поля: «Введите ссылку с http:// или https://». Credentials, control chars и прочие схемы отвергаются сервером и клиентом. |
| Пустое название | «Введите название материала». |
| Повтор URL в той же категории | Предложение: «Эта ссылка уже добавлена» и переход к существующей строке; правило нормализации уточняется в контракте. |
| Запись | Поля и черновик остаются. Кнопка показывает pending; повторная отправка той же операции блокируется. Отказ оставляет данные и позволяет повтор. |
| Успех | Список обновлён по ответу/GET, новая строка видна. Достаточно локального «Ссылка добавлена» в role=status; без дублирующего toast. |
| Сетевой отказ | «Не удалось сохранить ссылку. Попробуйте ещё раз». Черновик остаётся. Потеря ответа использует прежний idempotency key. |
| Конфликт | «Материал уже изменён. Ваш текст сохранён в форме». Получить актуальную версию и дать сравнить перед новой записью; не перезаписывать автоматически. |
| Право отозвано | «Сейчас у вас нет права менять материалы этой задачи». Введённое не стирать, повторную запись не обещать; копирование своего текста остаётся доступным. |
| Только чтение | Ссылки и раскрытие остатка работают; кнопки добавления и меню редактирования отсутствуют. |
| Внешняя ссылка недоступна | Не делать фоновую проверку сайта и не присваивать непроверенный статус «не работает». HTTP-доступность решается при переходе во внешнем приложении. |

Все операции во внешние сайты — обычное открытие ссылки в новой вкладке с noopener/noreferrer, без iframe. Название экранируется; URL не исполняет JavaScript. Явное сообщение о новой вкладке входит в доступное имя/скрытый текст, а не повторяется видимым абзацем у каждой строки.

## Клавиатура, отмена и новая задача

Tab идёт по ссылке, её меню, следующей строке, раскрытию и добавлению. Enter открывает ссылку; Enter/Space раскрывает native details. Меню и dialog используют публичный DS. После закрытия формы фокус возвращается в кнопку открытия; после добавления — на новую ссылку; после удаления — на соседнюю строку либо кнопку добавления. Закрытие формы с изменёнными полями использует существующий guard несохранённых данных. Escape не закрывает задачу вслед за вложенным dialog.

У новой задачи материалы сначала локально подготовлены вместе с черновиком. «Создать задачу» создаёт задачу один раз, затем сохраняет привязки повторяемыми командами. Если привязка не сохранилась, drawer остаётся открытым: «Задача создана, но ссылка не сохранена» и повтор только неуспешной операции. Не выдумывать task ID на сервере отдельно от существующего createTaskOnce и не создавать дубликаты после потери ответа. Уход/смена вкладки не теряет подготовленные материалы; guard задачи учитывает их. Финальный вариант зависит от согласованного API: если task create поддержит материалы атомарно, промежуточное состояние не требуется.

## Публичная DS и необходимые контракты

Существующих публичных средств достаточно для предложенной композиции: `.iq-section`, `.iq-section-head`, `.iq-section-count`, `.iq-section-actions`; native anchor; `ui.btn`, `ui.menu`; `iq-input`, `iq-select` и продуктовый dialog/input adapter; native details с публичной `.iq-work-details`; `.iq-helper`, role=status/alert; `.iq-skeleton` через продуктовый loadingMarkup. Продуктовая обвязка отвечает только за flow, порядок и геометрию строк. Не читать и не стилизовать внутренние DOM-узлы компонентов DS. Для ссылки нужен обычный anchor, не карточка агента/файла с неподходящими действиями.

Подтверждённого DS gap нет. До кода проверить реальные exports/classes exact релиза после merge, touch target disclosure/menu и подходящие размеры input/dialog. Если понадобятся новое общее поведение компонента или его внутренний override, сначала отдельный публичный DS gap/release, а не локальный обход.

От backend нужны: стабильный id привязки, taskId/projectId, категория, название, нормализованный URL, revision и устойчивый порядок; read плюс create/update/remove с CAS/idempotency. Не утверждены лимиты, duplicate policy, механизм восстановления и атомарность создания задачи с материалами. Предложенные в WIKI-RESEARCH.md 50 материалов — не принятый UI-лимит. Список не должен молча обрезаться: при серверной пагинации disclosure подгружает остаток и явно сохраняет ошибку повтора. Wiki target, поиск страниц и их права в этот этап не входят.

## Карта будущих изменений и приёмка

Точка композиции — `ui/src/board/task-dialog.js` после description, до task-editor-supplements. Предлагаемый отдельный consumer — `ui/src/board/task-materials.js`: список, формы, локальные черновики и controller lifecycle. HTTP methods — существующий product repository после контракта root. Новые UI-тесты проверят create/reload, частичный отказ, duplicate retry, CAS и фокус; визуальная приёмка — настоящий synthetic backend, обе темы, drawer/fullscreen,390px, long labels,0/1/3/4/many ссылок и readonly. Не менять Markdown описания, связи зависимостей и вложения задачи ради материалов.

Готовность к реализации: согласовать эту композицию и API-решения выше после первой merge. Acceptance: открыть любую из первых трёх ссылок одним действием; добавить из пустой группы без промежуточного меню; сохранить несколько материалов и увидеть их после reload; не потерять черновик при ошибке/отмене; убрать только привязку; не показывать права записи читателю; не получить внешний overflow или потерю фокуса на390px. Проверка URL/XSS/прав и устойчивость команды входят в реальную backend-приёмку, а не заменяются UI-валидацией.

Источники: корневые AGENTS.md и START-HERE.md, products/sprintique/AGENTS.md; iquipage-discovery и его constitution/execution-contract; `WIKI-RESEARCH.md` как предложение; существующие task-dialog.js, task-create.js, description-view.js, публичные types/core.d.ts и src/styles/work-story.css принятой ветки. Runtime и screenshots для этой спецификации не выполнялись.
