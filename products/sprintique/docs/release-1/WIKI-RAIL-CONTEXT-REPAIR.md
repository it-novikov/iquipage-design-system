# WFR1-2: отдельная прокрутка каталога и истории

Причина: app-owned `.wiki-catalog` использовался для дерева страниц и списка версий, поэтому scrollTop длинной истории переходил к более короткому каталогу и ограничивался его концом. После версии 1 выбранный документ оказывался вне видимой области.

Исправление ограничено `web/wiki.js` и `web/wiki-model.js`. Позиции хранятся отдельно для каталога и истории каждой страницы. Перед заменой содержимого сохраняется видимая готовая поверхность; загрузочные и скрытые мобильные состояния не перезаписывают позицию. После готового содержимого и открытия мобильного диалога восстанавливается соответствующая позиция. Существующий reveal выбранной версии продолжает работать. Expanded IDs, query, маршруты и DS .50 не изменены.

Модельные регрессии воспроизводят каталог с позициями 0 и 612 → историю 5816 → загрузочный placeholder → версию → возврат к каталогу; отдельно проверяют другую страницу истории и скрытую мобильную поверхность. Targeted UI 38/38, build, boundaries и diff check PASS. Логи `output/wiki-redesign/logs/rail-context-*.log`.

Реальная Chromium-проверка synthetic localhost:4318: 1280×720, светлая тема, каталог 0 → «История» → «Ранние версии» → «Версия 1» (5816) → «К странице» возвращает 0, выбранный документ y184 совпадает с верхом rail y184. Вручную прокрученный каталог после завершения scroll-анимации: 720 → тот же цикл → 720. При 390×844 диалог каталога открывается на720; история открывается с выбранной версией1 в видимой области; «К страницам» и повторное открытие каталога восстанавливают720. document.scrollWidth=390. Сохранений документов или задач не выполнялось.
