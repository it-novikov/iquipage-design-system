# Board B2 — документ задачи и проектные справочники
База: f4c165c, PR #2, feature/board-production. B1 и его поставка неизменны.
Разрешение: продолжение утверждённого плана пользователя; без production deploy.

## Вертикальные сценарии текущего этапа
1. Настройки → создать/переименовать/архивировать тег и релиз → выбрать в задаче → фильтр доски.
2. Новая задача → шаблон base+type → два чек-листа → сохранить → открыть после reload.
3. Сохранённая задача → обычный комментарий и тред с решением → ответ → решить → открыть повторно.
4. Изменение текста задачи параллельно с ответом в треде: независимые версии, оба результата сохранены.
5. Потеря ответа сети → повтор того же message ID: не более одного сообщения.
6. Задача → зависимости/обычные связи → обратное отображение; циклы и чужой проект отклоняются.
7. IndexedDB B1 → upgrade B2: старые карты, задачи, связи и версии остаются.
8. Смена типа не перезаписывает пользовательский текст; применение нового шаблона явно подтверждается.

## Архитектура
Task.checklists — независимые списки со стабильными ID, без переписывания Markdown.
Task.releaseId/tagIds ссылаются на проектные коллекции. Архив справочника не удаляет прошлые связи.
TaskSettings — одна версия базового шаблона и переопределений типов на проект.
Thread — отдельная версия от Task, append-only сообщения с ID и автором, resolution отдельно.
TaskLink — отдельное ребро depends/related с проверкой графа в транзакции.
Все хранилища выполняют одинаковую валидацию на снимке транзакции. Сервер остаётся локальным reference.
Права UI инъектируются; реальная auth/ACL платформы не заявляется готовой.

## Приёмка до реализации
Дубли имён без учёта регистра; неверные цвета/даты/ID; чужие и архивные ссылки.
Повтор message ID с другим текстом; устаревшая версия; удаление/подмена старых сообщений.
Независимые checkbox при одинаковых заголовках; шаблоны inherit/append/replace/exclude.
Теги any/all и AND между условиями; child matching не зависит от collapsed parent.
Браузер: create/edit/reload/error/readonly, светлая/тёмная/узкая ширина, сохранность черновиков.
Файлы требуют отдельного blob transport и проверки безопасности; не заменять их base64 в task JSON.
