# DS-E02 — повторное подключение Markdown-редактора при перестановке тредов

Обнаружено браузерным сценарием browser-thread-pages.mjs: после публикации ответа
и перемещения обсуждения в начало пустое поле ответа становилось снова непустым.
Закрытие задачи ошибочно запрашивало отказ от уже опубликованного черновика.

Причина подтверждена в исходной IQUIPAGE 05.7: IqElement.connectedCallback()
повторяет mount(), а IqMarkdownEditor.mount() берёт textContent существующей
панели инструментов, когда атрибут value пуст. Обычный insertBefore инициирует
этот жизненный цикл также при переносе предка редактора в том же документе.

Исправление отдельного кандидата 0.6.0-board.2, не оригинального design-system/:
синхронный перенос в той же форме сохраняет DOM, историю и значение редактора.
Реальное удаление освобождает слушатели/наблюдатели после текущей микрозадачи.
Для поддерживающих браузеров используется state-preserving moveBefore и
connectedMoveCallback. Fallback insertBefore проходит тот же контракт сохранности.
Переход в другую форму повторно связывает обработчики с новым владельцем.

Приёмка: пустое значение не подменяется текстом toolbar; черновик, выделение,
Undo/Redo и preview переживают изменение порядка; composition не теряет текст;
после закрытия нет действующих обработчиков; существующие проверки B1/B2 сохранены.
Выполняется self-review, не независимое ревью дизайн-системы.
