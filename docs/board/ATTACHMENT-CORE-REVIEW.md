# Состояние файлового слоя перед ревью

Этот документ заменяет фактическую точку остановки FILES-STORAGE-CHECKPOINT.md.
Пользователь разрешил завершение обложек и подготовку PR в main.

## Применено
- В task write включена проверка принадлежности вложений задаче, проекту и автору staging.
- Task, attachmentIds, coverAttachmentId и состояния attachments сохраняются совместно.
- Это подключено к MemoryRepository, BrowserRepository и FileRepository.
- Браузерное хранилище обновлено до версии 3: metadata и Blob хранятся раздельно.
- Есть BrowserAttachmentAdapter, HttpAttachmentAdapter и обработчик бинарного HTTP.
- Загрузка в IndexedDB, повтор, чтение, отмена и очистка проверяются отдельным контрактом.
- Добавлены регрессии атомарной фиксации, конфликта версии и отказа диска.

## Не подключено
- attachmentRoutes не включён в server/app.mjs; capability attachments не объявляется.
- task-files-view.js не создан; управление файлами и обложками в задаче отсутствует.
- cover-loader.js — предварительный адаптер отображения, не включённый в доску.
- HTTP-адаптер и роутер прошли только проверку синтаксиса, не сквозную HTTP-приёмку.

## Блокировка инструмента
Исходные запросы подключения server/app.mjs и создания task-files-view.js отклонены
с текстом «не смогли определить статус безопасности запроса». Повторные отправки
тех же запросов не применили изменения. Другие инструменты для их обхода не использовались.

## Граница приёмки
Проверки хранилища и регрессии B1/B2 не подтверждают работающий UI обложки.
PR остаётся Draft. Готовой HTML-поставкой с обложками этот снимок не является.
Исходная design-system/ не менялась. Производственные ACL, AV/CDR, provider automation
и real-device/performance acceptance по-прежнему не закрыты.
