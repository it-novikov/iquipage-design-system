# UX R2 — рабочий план, DS-границы и приёмка

Статус всех новых пользовательских сценариев: **NOT_RUN**. Успех проверок Frontend R1 не является результатом UX R2. Оценки времени/кадров ниже — предлагаемые цели, которые фиксируются до нового прогона.

## 1. Последовательность поставок
| Этап / задачи | Что считается законченным результатом | Граница |
|---|---|---|
| UX-0: актуальный walkthrough и scope | Воспроизведены конкретные жесты карты, проверен настоящий host shell; открытые симптомы получают finding IDs | Исходные жалобы не отменяются из-за отсутствия репродукции |
| UX-1: общая оболочка и композиция | Переключатель workspace/project, профиль, согласованные оси, новый компактный список показаны на реальных DS-компонентах в обеих темах | Прототип сохраняет реальные данные/действия через адаптер; новое композиционное решение принимается до распространения |
| UX-2: рабочий список | Inline-поля/создание, дети, выбор, drag, сортировка, фильтры и возврат из задачи проходят старые и новые сценарии | Не меняются правила релизов ради упрощения рендера |
| UX-3: обычная карта | Видимый поиск, содержание, единое редактирование/отмена и простое добавление объектов | Без подключения платного LLM и исполнения из нарисованной стрелки |
| UX-4: процесс команды | Прототип шагов/проверок, одна карточка на карте, понятное отличие draft/published/run, backend-handoff принят владельцем сервера | Это ещё не настоящий внешний запуск |
| AG-1: один внешний исполнитель | Один сквозной task→agent→artifact→CI→human-review на согласованном провайдере и мандате | Оплата, credentials и включение внешнего доступа — отдельное явное разрешение |
| AG-2: события и параллельность | Проверенные GitHub/GitLab triggers, dedup/recovery, ограниченный reviewer/parallel stage | Не реализуется до evidence пользы AG-1 |
| QA/DEL | Актуальные E2E, визуальная/доступная приёмка, измерения, полная поставка, PR на конечном SHA | Нельзя заменять фактическую приёмку количеством тестов |

Ближайшая разработка — UX-1/UX-2, затем UX-3. Спекулятивный agent runtime не должен тормозить исправление ежедневного интерфейса. Все готовые этапы фиксируются в одной ветке `feature/vnext-planning-ui`, PR #3, если он ещё открыт. После его слияния — новая ветка/PR от свежего main по отдельному решению, без force push истории. Старые поставки сохраняются.

## 2. Роли и ответственность
| Роль | Артефакт / проверка |
|---|---|
| Product owner + специалист по task trackers | Сценарии, границы релиза/спринта/задачи, приоритет и предотвращение n8n-scope |
| Арт-директор | Сравнение двух композиций на одинаковых данных, плотность, ритм, иерархия, light/dark |
| UX/UI + researcher | Контракт жестов, прототип, задания без подсказок; реальные наблюдения отделены от экспертного мнения |
| Frontend + владелец DS | Публичные compositions/lifecycle, scoped data adapters, отсутствие private DOM patches |
| Системный аналитик + backend-агент | Общие identity, process/run/proposal/approval, версии и атомарность |
| QA/accessibility | Негативные сценарии, IME, keyboard/pointer parity, focus и регрессии всех затронутых поверхностей |
| Performance + security | Кадры/память на целевых устройствах, права контекста, budget/retry и работа внешних исполнителей |

Это распределение работ, а не утверждение, что независимая команда уже запущена. В текущем проходе выполнено самоисследование по этим перспективам.

Поставленная DS уже имеет многие primitives; новая composition и отсутствующие capabilities оформляются явным запросом. Pinned 05.7 и SHA не меняются задним числом. Изменения source-owned библиотеки имеют собственные типы, тесты и pack/install consumer. Визуальное «похоже на DS» не заменяет публичный контракт.

## 6. Motion, performance и сохранность
Motion использует DS 120/180/280/360 ms и её easing. Движение показывает причину/результат, а не оживляет каждую строку бесконечно. Анимация прерывается новым действием; reduced motion отключает пространственное движение без задержки результата. Ввод и переход к редактору не ждут завершения декоративной анимации.
Тестовый профиль: 10 000 задач, 200 групп релизов, длинные имена, глубокая иерархия; карта с 1000 объектами; процесс до 100 шагов. Это профили теста, не лимиты пользовательского продукта. Нужны отдельные измерения на 60/120 Hz и среднем мобильном устройстве; бюджет кадра зависит от дисплея. Замеры headless отмечаются отдельно и не выдаются за реальную частоту кадров.
Листы и карты рендерят необходимое окно/детализацию; focus/IME-редактор не демонтируются. Перемещение обновляется через requestAnimationFrame с пакетированием геометрических чтений, без сериализации всего документа на каждом движении. Не анимируются одновременно layout/paint всех строк. Canvas zoom не подменяет document zoom в проверке доступности.
Стриминг агента не вызывает полный ререндер карты или перестановку редактируемой строки. Превью медиа, редакторы, журнал и агентные панели загружаются по запросу. Проверяются 30 последовательных смен контекста/открытий, отсутствие растущих listener/Blob/cache и поздних callback после destroy. Поиск и счётчики scoped на проект/права.
Обязательны возврат в список с прежним scroll/focus, refresh после commit, revoke, конфликт revision, потеря ACK, ошибки хранилища и отсутствие backend. Новая сборка не получает старый отчёт: source/build/DS fingerprints и CI относятся к конечному SHA.

## 7. Исследование с людьми и критерий завершения
Предлагается 6–8 качественных сессий: самостоятельные создатели, небольшие команды и участники команд среднего размера. Это не статистическая репрезентативность. Задания без подсказок: распределить задачи между двумя релизами; изменить исполнителя; найти и отредактировать функциональный объект карты; переключить проект с черновиком; понять, агент завершил работу или результат уже принят. Сравнить R1 и два прототипа на одинаковых данных с переменным порядком показа.
Фиксируются успех без помощи, ошибочные переходы, время до нахождения действия, сохранность текста и правильность объяснения последствий пользователем. Предлагаемый gate: ни одной потери данных/неожиданного запуска, все критические сценарии решаются без обучения скрытым жестам, оставшиеся затруднения оформлены findings. Параметры времени не подгоняются после теста. Продуктовый owner принимает композицию отдельно от технического QA.
