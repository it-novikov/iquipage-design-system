## Минимальный словарь пользователя
**Пространство** — доступ и команда. **Проект** — работа в конкретном контексте. **Участник** — человек либо агент. **Задача** — работа, баг или эпик с той же иерархией. **Релиз** — пакет работы; спринт — его формат. **Карта** — представление/заметки и ссылки на объекты. **Сроки** — Гант/календарь по тем же объектам. **Автоматизация** — правила выполнения повторяемых действий. Отдельного «поручения» как второго task document нет: это запуск в существующей задаче.
Не создаём отдельные сущности AI-task, roadmap-card, sprint, material, team-process, scheduler-event и agent-user-copy. Файлы, треды, чек-листы и ссылки входят в тот же документ задачи; один attachment asset может иметь разные presentation links без копирования байтов.
Локальные договорённости на старой карте не удаляются и не превращаются автоматически в серверные задачи. Явное «Создать задачу» делает каноническую задачу с idempotency key и записывает ссылку обратно. Повтор не создаёт дубль. Отказ второй части оставляет восстанавливаемую связь, не теряет созданную задачу.

## Что нельзя сокращать ради числа сущностей
Run, proposal, approval, mandate и receipt — разные факты. Run completed ≠ результат accepted ≠ изменение committed. Роль агента ≠ ACL. UI-конфигурация ≠ секрет подключения. Комментарий с просьбой ≠ разрешение на внешний эффект. История релиза ≠ копия живой задачи. У этих объектов могут быть общие storage/transport механизмы, но не общий неопределённый статус.
Аудит и outbox сохраняются с изменением. Доставка at-least-once; exactly-once для внешних систем не обещается. На зависимостях/тегах/родителях проверяются обе стороны scope. Видимость карты не даёт доступ к приватной задаче, на которую она ссылается.

## Сквозные контракты
1. `TaskRef{taskId,projectId,revision}` и разрешённая карточная проекция одинаковы в списке, доске, карте, Ганте, поиске, сообщениях и агентном контексте. Открытие вызывает один host callback; возврат сохраняет позицию и выбор.
2. Изменить безопасное поле → одна команда с revision/idempotency → подтверждённое состояние + error/recovery. Активный состав, массовый перенос и внешние эффекты → preview/approval. Не весь UI обязан показывать две модалки, но правила сервера всегда одни.
3. `Context{workspaceId,projectId,principalId,permissionsVersion}` принадлежит shell/SDK. Смена отменяет старые reads и подписки; token не передаётся внешним URL. Старый ответ не может заполнить новый экран. Commit без результата не отменяется простым AbortSignal.
4. Вкладка задачи показывает вопросы, результат агента и принятие в существующих тредах/артефактах. Не добавляем отдельный несвязанный AI-чат, откуда пользователь копирует ответ вручную.
5. Правила читают подтверждённые доменные события. Переименование роли, изменение масштаба, расположение объекта и показ карточки не являются триггерами запуска LLM.
