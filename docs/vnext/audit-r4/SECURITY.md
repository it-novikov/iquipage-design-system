### Изменения поведения, которые стоит знать

- Grant только на запись (`tasks:write` без `tasks:read`, `threads:write` без `threads:read`) получает компактную квитанцию `{"receipt":"task"|"thread", ...}` вместо полного объекта, а `POST /planning/previews` для него отвечает `403 FORBIDDEN`. Превью по своей природе — чтение графа проекта. Человек-участник получает прежний полный ответ.
- Квитанция повтора записи обсуждения хранит идентификаторы; ответ на повтор восстанавливается из канонического состояния. Повторный запрос с тем же ключом по-прежнему не выполняет второй эффект.
- `POST /planning/previews` может ответить `429 PREVIEW_QUOTA`, если у участника или проекта слишком много неприменённых превью. Применённые планы не считаются. Истёкшие и неприменённые планы собираются ограниченными порциями; для этого runtime-роли выдан `DELETE` только на `app.planning_plans` (UPDATE остаётся отозванным).
- Канонический документ карты отклоняет более 40 объектов-изображений, полностью совпадающие по геометрии связи и более 16 связей между одной парой объектов. Уже сохранённая карта с такими связями останется читаемой, но при следующем сохранении потребует убрать дубликаты.
- `/ready` больше не проверяет зависимости на каждый параллельный запрос: одновременные запросы делят одну проверку, и маршрут учитывается в пооадресном окне. Кэша результата нет — следующий запрос снова проверяет зависимости, поэтому поведение остаётся fail-closed.

## Границы

- Покрытие сканирования ограничено фазой discovery. Собственные фазы валидации, построения цепочек атак и отчёта не выполнялись.
- Это не penetration test, не проверка провайдера аутентификации, не аудит ОС контейнера и не анализ неизвестных уязвимостей зависимостей. `npm audit` по точному lockfile продукта: 0 известных advisories на дату аудита.
- SEC-R4-08 закрыт частично: сервер и контракт ограничивают дублирующие и параллельные связи, но общий бюджет работы маршрутизации внутри публичного whiteboard-модуля не переписан.
- SEC-R4-14 исправлен в `scripts/backup-drill.mjs` и проверен чтением кода; сам drill в этой сессии не запускался, поэтому доказательства выполнения нет.
- Приватные cookie, credentials, infra-конфигурация, пользовательские базы и backup-файлы в отчёт и PR не включены.
