### Спор решений

| Вариант | Пользовательская и инженерная цена | Решение для следующего среза |
| --- | --- | --- |
| Закрывать editor при сужении контейнера | Прерывается поиск, выбор даты или чтение вариантов; фокус требует нового действия | Отклонено как основное поведение |
| Возвратить обрезку и фиксированные строки | Редактор может случайно оказаться рядом, но исходная потеря смысла подписей возвращается | Отклонено |
| Позиционировать открытый editor при изменении размера trigger | Сохраняет текущий ввод; можно ограничить наблюдение временем открытия и отменять запланированный кадр при закрытии | Предпочтительное ограниченное направление, точная реализация ещё не принята |
| Постоянно опрашивать положение всех контролов через rAF | Обновляется даже неподвижный закрытый UI; усложняется жизненный цикл | Не выбрано без конкретной необходимости |
| Вводить новую библиотеку позиционирования | Может покрыть более широкие сценарии; меняет зависимость и интеграцию двух зрелых controls | Нужна отдельная доказанная выгода; сейчас не выбрано |
| Всегда вертикальный layout B | Может сделать группы проще, увеличивает высоту и не гарантирует tracking popup | Остаётся дизайнерской альтернативой; этот прогон B не рендерил |

Общее направление — обновлять **открытый** editor через существующий расчёт позиции, сохраняя query, selection, caret/focus и identity; очищать observers/listeners и отменять отложенную работу при close/disconnect. Наблюдение размера trigger не является обещанием отслеживать position-only shifts и CSS transform. Эти условия надо задать отдельно, до реализации. Ограничение наблюдения размера описано в [ResizeObserver](https://developer.mozilla.org/en-US/docs/Web/API/ResizeObserver); разделение resize, layout shift и animation-frame tracking показано в первичной документации [Floating UI autoUpdate](https://floating-ui.com/docs/autoupdate).

Минимальная приёмка следующей JS-коррекции: реальное сужение/расширение контейнера с открытым owner и due; отсутствие ручного window resize; правильное положение после paint; сохранение поиска/выбора и фокуса; Escape возвращает focus и ничего не записывает; закрытие и повторное открытие не оставляют активную отложенную работу. Viewport capture и прежние отрицательные наблюдения сохраняются как контроль.
