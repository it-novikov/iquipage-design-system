# @iquipage/web

Independent, source-owned Web Components library. Build with Node 24: `npm run build`; package with `npm pack`. No Sprintique imports, domain models, credentials or product build steps are permitted here.

Consumers import `@iquipage/web/core`, `/advanced`, `/whiteboard` and `/styles.css`. The core entry does not eagerly register advanced components. Tokens and types are part of the package. Source version 0.6.0-vnext.0 includes the approved compact editor, decision action, cover crop and board UX extensions. The historical 0.5.7 snapshot remains untouched elsewhere in the repository.

`products/sprintique` consumes a packed release, not this source directory. Updating the library requires rebuilding and explicitly replacing that release and lockfile. Publishing to an external registry is a separate owner-approved operation. Package remains private until distribution/licensing is settled.

## Authentication screen

`iq-auth-screen` is a provider-neutral, responsive authentication composition in
`@iquipage/web/core` (0.6.0-vnext.5). It uses the catalog's existing semantic colors,
type scale, mark and buttons. See [integration and design contract](docs/authentication.md)
and [interactive example](examples/authentication.html) after `npm run build`.

For actual credential entry use `iq-auth-dialog` (0.6.0-vnext.10). The interactive authentication
example demonstrates the form, not just a provider redirect. The Keycloak login theme that
shipped from vnext.9 to vnext.20 was removed in vnext.21: no product uses an external
identity provider's form any more.

## Mentions (0.6.0-vnext.29)

- A mention is stored in Markdown as `@[Имя](user:<id>)`: the id names the member and survives renames, the label is what the author saw. `mentionToken({id, name})` writes it (one-line label up to 80 characters without brackets; an id of `A–Z a–z 0–9 _ -` up to 100, anything else throws), `parseMentions(source)` finds tokens outside code, `mentionPlainText(source, members)` and `mentionsHTML(source, members)` turn them into «@Имя» text or escaped pills for one-line previews. An older renderer shows a token as the plain name.
- `safeMarkdown(source, {mentions})`, `iq-markdown-viewer.mentions` and the editor's preview render a token as `.md-mention` (accent text on `--iq-accent-soft`, weight 500, never broken inside a name). `mentions` is an array of `{id, name, kind?}` or a lookup `id → {name, kind?} | name | null`; with it a pill shows the member's current name and a token naming anyone else is its label alone as plain text; without it every token is «@label» plain text, so a pill always means a known member. Labels drop brackets, backticks, `* _ ~ |` and line breaks.
- `iq-markdown-editor.mentions = [{id, name, kind?: 'human'|'service', description?, image?}]` turns on the @ list (null turns it off). The field never shows a token: picking writes «@Имя» and the editor keeps a map of the picked ranges; `value` (and `iq-change`, `iq-submit`) carries the Markdown with tokens, and a value set with tokens shows names again. Editing inside a name, or typing letters against it, drops that mention and the text becomes an ordinary typed one; Backspace right after a mention removes it whole; pasting a plain name is typed text too. `mentionsFromMarkdown` / `mentionsToMarkdown` do the same for any field. `MentionAutocomplete` / `attachMentionAutocomplete(textarea, {members})` does the same for any textarea. «@» at a word start opens the list under the caret; typing filters it (case-insensitive, «ё» as «е»; name prefix, word prefix, then substring); people come first, then service accounts under a sentence-case «Сервисные аккаунты» label with their `description` (e.g. the owner) and the square bot avatar; ↑↓ move, Enter or Tab insert the token and a space through `insertText` (one undo step), Escape closes, a click picks without taking focus. The textarea fires `input` and `iq-mention` {id, name}. The list is the calm select list of vnext.27 (34px rows, one hover fill, the active row in accent), sits next to the textarea (reachable inside a modal dialog) and opens in the top layer; the textarea keeps its textbox role with `aria-activedescendant` and a polite count.

## Planning tree (0.6.0-vnext.28)

- **Columns (T1).** A container with `.tree-columns` sets the right column tracks in `--tree-columns` (default `88px 116px 60px 64px`) and their gap in `--tree-column-gap` (16px). A `.tree-row.has-columns` is a grid of `.tree-row-main` (disclosure, `.tree-node-icon`, `.tree-node-label` with optional `.tree-node-crumb` and `.tree-node-aside`) and `.tree-cell`s; only the main part carries the 21px-per-level indent, so cells line up across levels. Rows are 40px with radius 8 and a transparent 1px block border clipped from the fill, so adjacent selected rows keep a 2px gap. Cells: `.is-end`, `.is-strong`, `.is-warning`, `.is-faint`; a value edited in place is a `button.tree-cell-button.is-editable` with a dotted underline on row hover. `.is-branch` sets the label to 500; `data-tone=critical|high` takes the task text tones; `.is-selected` is the accent-soft fill with accent text.
- **Status glyph (T2).** `statusGlyph(status, {label, size})` and `STATUS_GLYPHS` draw a board column as a 15px glyph: ring (neutral, ready), half (info, in progress; warning, review and testing), ring with a dot (planned, ready for testing), check (success, ready for release). `.iq-status-word` is the grey word shown only where the glyph does not tell statuses apart.
- **Hold-to-drag (T3).** `bindTreeDrag({root, rowSelector, containerSelector, holdMs, slop, items, preview, canDrop, onDrop, …})`: no handle; a press held 200 ms or moved 6 px lifts the row (or the ids the host names) into a ghost in the top layer with an optional badge; the zone under the pointer gets an inset 1.5px accent outline and an insertion line between root rows (`aria-level` 1); Escape or a release outside every zone cancels; a short click stays a click and the click after a drag is swallowed; the nearest scroller auto-scrolls; a polite live region speaks. `onDrop` may return `{undo, message}` for an «Отменить» toast. `treeDropPosition()` is the same position math for keyboard moves. The library never moves data.
- **Done (T4).** `.tree-divider` is the 36px «Готово · N · сумма» rule (12/500 faint text and a 1px line); `.tree-row.is-muted` mutes the label and cells and drops the priority tone, while the status glyph keeps its shape and tone.

## Property list (0.6.0-vnext.27)

- `.iq-properties[data-label=wide]` is one calm list of an object's facts: 36px rows, a 120px label column (a host may set `--iq-properties-label`, e.g. 136px in a wide reading column) with 13/400 muted labels, and 14/400 values. The values use the ghost grammar of `.iq-properties[data-columns]` (text at rest on the column edge, the `hover` fill bleeding 8px left and a 12px chevron on hover or focus, one click opens the editor); in this list a date trigger shows no calendar glyph and an option's `meta` stays in the open list. `iq-select appearance="pill"` is 26px with a 7px dot and no chevron.

A host's own trigger (`.iq-select-trigger`, `.iq-date-trigger`) placed in a row is a ghost value too.
- `iq-select`: `trigger-icon="none"` keeps an option's glyph in the open list and shows only the word on the closed control; an option may carry `key` (a mono task key before the label, also found by the search); `avatar: {kind: 'bot', label?}` draws a service account's square avatar with the bot glyph and speaks its role after the name.
- `ui.personAvatar({…, kind: 'service'})` is the same square bot avatar; the Lucide `bot` glyph is in the icon set.
- `iq-date-field deadline`: the value is a due date. Overdue, today and tomorrow are written beside it («28.09.2026 · просрочен», «· сегодня», «· завтра») and toned through the trigger's `data-deadline` (critical text for overdue, high text for today and tomorrow); remove the attribute for finished work.
- **Calm select lists** (owner's feedback): the open `iq-select` list has no uppercase caption; its search is a filled 32px field with a soft 1px `line` ring on focus; options are 34px with a 9px radius; hover and the keyboard's row share one `hover` fill (never a frame), the selected option is accent text with a check; meta is muted on the right; a separated row (a group heading or an action such as «Новый релиз») is set apart by 6px of space, not a rule, and reads muted; a list opened from a short value is at least 280px wide. Options with `avatar` show it in the list too. In a property list an open value keeps its ghost look (the `hover` fill), never a bordered pill. The tag picker's list uses the same surface, radius and row fill.
- **Avatar initials at 20px** (`.iq-avatar.xs`, the list's select avatar): 8/600 with caps tracking (owner's feedback «буквы слишком крупные»); the bot glyph is 11px. Initials are a mark, not reading text, so they sit below the 12px floor for words.
- `iq-tag-picker appearance="ghost"`: a value of a property list. Chips at rest, the hover fill and chevron of the other ghost triggers, a click anywhere opens the search; «Нет тегов» when empty, the «Найти тег» hint only while typing, no «+» button (an unmatched search offers «Создать тег» when `creatable`).

An empty side collapses, so a single blocker gets the whole width.

## Pasted links and toasts that leave (0.6.0-vnext.25)

- **A pasted link becomes a link.** In `iq-markdown-editor` (every variant) and the map's inline text editor, pasting a single `http(s)://` or `mailto:` URL with nothing selected inserts the autolink `<url>`; pasting it over a selection wraps the selection as `[selection](url)` (brackets and parentheses escaped). Ordinary text, anything else and a paste inside code, a link destination, over a URL or across paragraphs stays a plain paste. The edit goes through the browser's `insertText`, so one undo (Ctrl/⌘ Z or the toolbar) reverts it. Pasting inside an existing link, a link destination, an autolink or code, and over a selection that spans lines or holds link or code syntax, stays a plain paste, so an existing link keeps its structure. The rules live in the internal helper `markdownPasteLink` (`src/modules/markdown.js`); it is not a public export.
- **Plain http and mail links render.** `safeMarkdownURL` accepts `http:` next to `https:` (still no credentials, whitespace or backslashes) and `mailto:` with real addresses; a mail link opens without `target=_blank`. Nothing is loaded from either.
- **Toasts leave by themselves.** `notify()` shows a toast for 5 s (info, success), 8 s (warning), 10 s (danger) and 10 s when it carries a shortcut action such as «Открыть». An action with `undo: true` («Отменить») keeps the toast until it is dismissed (A11Y-01). `duration: 0` keeps a toast; a malformed duration falls back to the default. Hover (once the pointer moves over the toast: a toast that appears under a resting pointer still leaves), focus inside and a hidden tab pause the countdown; after a pause at least 1.5 s remain. Escape inside a toast closes that toast only, and focus that entered the toast returns where it came from. `notify()` returns the dismiss function; `toast.dataset.duration` shows the chosen time.

## Wave 1 «Основания»: theme on roles, motion tokens, rem type scale (0.6.0-vnext.24)

### Colour and theme on roles

- **The dark theme is a token set, not a patch list.** The 45 `--iq-fixed-*` tokens are gone; their uses became per-theme roles (`scrim`, `story-surface/-ink/-muted/-subtle/-line`, `secondary-fill/-hover-fill`, `document-bed`, `media-chip`, `shadow-color-*`, `on-white`, …). Thirteen colour-only `[data-theme=dark]` patches and the empty dark block left `foundation.css`; twelve dead colour tokens were deleted. Cards, popups, task cards and calendars keep a 1px `--iq-raised-edge` in the dark theme, and `--iq-shadow-1/2/3` are heavier there (COL-08, COL-09, COL-13).
- **Accents come from `semantic.json`.** `accents.violet` and `accents.green` generate `:root[data-accent=…]` and the dark variants into `tokens.css`; the dark accent fills are 3:1 on raised surfaces with white text 4.5:1, and every accent has a distinct hover fill (COL-03, COL-10).
- **System theme and boot.** `tokens.css` carries `@media (prefers-color-scheme: dark)` for documents without `data-theme` and `@media (prefers-contrast: more)`; `dist/theme-boot.js` (exported as `./theme-boot.js`, inlined in the catalogs) applies the stored `iq-theme`, `iq-accent`, `iq-density` and `iq-motion` before first paint (COL-11, COL-12, ENG-14).
- **Status without colour alone.** Success, danger and warning badges carry a glyph by default (`ui.badge(text, tone, withIcon)`), chart series have distinct marker shapes and the palette runs blue, orange, green, purple; `planned` moved toward magenta so it separates from `info` under protanopia (COL-06).
- **Disabled and focus.** `--iq-disabled-ink` and `--iq-disabled-fill` replace opacity on buttons, selects, options and checks; the focus ring has a canvas-coloured 4px halo so it stays visible on accent and ink surfaces (COL-16, COL-22). The critical task label meets 5:1 on its lit field (COL-07).

### Motion

- Every duration and easing in `src/styles` is a token (`--iq-motion-instant/fast/standard/enter/layout/scene`, `--iq-ease`, `--iq-ease-spring`, `--iq-ease-out`); the `duration-raw` ratchet is 0. `scripts/codemods/motion-tokens.mjs` is replayable and idempotent and also generates `src/styles/motion.css`.
- Reduced motion: `@media (prefers-reduced-motion: reduce)` and `<html data-motion="reduced">` both zero the motion tokens; the blanket `*{animation:none!important}` resets are gone, so component overrides and the 180 ms `.iq-loading` anti-flicker delay (`--iq-loading-delay`) work again. `motionReduced()` is the only check in JS.
- New core helpers: `motionMs(name)`, `motionEase(name)`, `scrollBehavior()`, `withoutTransitions(fn)` (theme switch without colour ripple, CSS `:root[data-theme-switching]`), `bindLoading(el)` (`.iq-loading-slow` + status note after 5 s).
- Enter/exit pairs are symmetrical: dialog fade standard/standard, drawer slide enter/enter, menu fade fast/fast, toast standard/standard. `iq-dialog.close()` returns focus and emits `iq-close` immediately, keeps the dialog `inert` during the exit and ignores a second close.
- `.iq-progress` animates `transform` (the `--progress` percentage API is unchanged); the editor no longer animates `height`; the hover lift applies only to `.iq-btn.primary/.secondary`; `.wb-world` gets `will-change` only while gesturing; `.iq-skeleton` breathes three times and rests faint. See docs/INTEGRATION.md «Движение» and «Загрузка».

### Typography

- **Type scale in rem.** Every `--iq-type-*-size` is rem at a 16px root (`html{font-size:100%}` in the new `src/styles/text.css`): display 4rem, heading1 2.75rem, heading2 2rem, heading3 1.375rem, lead 1.25rem, title 1.125rem, body 1rem, interface .875rem (the body stays visually 14px), label .8125rem, caption .75rem. The browser's font-size preference now scales text; spacing, controls and radii stay in px. `--iq-type-meta-size` is `.75rem`: the 12px floor of the system (TYP-03, TYP-04).
- **One replayable codemod.** `node scripts/codemods/type-scale.mjs` rewrites `src/styles/*.css` and is idempotent (a second run reports 0 changes; `tests/wave1-type.test.cjs` proves the tree is in normal form). px font sizes on a scale step become `var(--iq-type-*-size)`, off-scale sizes become rem literals (15px → .9375rem), component text below 12px is raised to the meta token, catalog selectors (`.home- .landing- .proof- .narrative- .sample- .demo- .story- .catalog- .edition- .feature- .cover-`) keep their size as rem. Inside `@media (max-width…)` a font size smaller than the selector's base size is removed when that base is below 24px: media queries change composition, never shrink small text; display sizes (base ≥ 24px, e.g. `.type-hero`, `.landing-intro h1`, `.task-drawer-title`) keep their responsive value, converted like any other size (TYP-05). Rerun it after merging other CSS changes.
- **Cyrillic line height and tracking.** Tokens: display line-height 1.1, heading2 1.2 (h1 1.15, h3 1.3 unchanged); a tracking scale `--iq-tracking-display -0.028em, -h1 -0.024em, -h2 -0.018em, -h3 -0.012em, -body 0, -caps .06em`, which the `type-*-letterSpacing` tokens reference. The codemod replaced all 145 tracking literals and 27 heading line heights below the minimum (TYP-07, TYP-08).
- **heading1 and lead are kept and wired**, not deleted: the codemod maps 44px → `heading1`, 20px → `lead`, and `text.css` adds the missing utilities `.type-heading1`, `.type-heading3`, `.type-lead`, `.type-title`, `.type-meta` (the uppercase kicker role). Every `--iq-type-*` and `--iq-tracking-*` token now has a consumer (TYP-06).
- **Weights.** 750 → 700 (the shipped axis ends at 700); 450/550/650 stay, InterVariable renders them (TYP-10).
- **Text handling.** `text.css`: `text-size-adjust:100%`, `hyphens:auto` with `hyphenate-limit-chars:6 3 3` for Russian documents, cards, messages and headings, `.md-document` at the body step with a 68ch measure; prose selectors use `overflow-wrap:break-word` while table cells, titles, code and tags keep `anywhere`; the standard `line-clamp` sits next to every `-webkit-line-clamp` (TYP-09, TYP-14, TYP-18, TYP-19).
- **Kickers.** `.sample-overline`, `.iq-pro-eyebrow`, `.wb-library-eyebrow`, `.narrative-toolbar>span`, `.eyebrow`, `.wb-panel-kicker`, `.iq-work-header-eyebrow` are `text-transform:uppercase` at the meta size with caps tracking; the 76 all-caps Russian literals in the modules are sentence case («Рабочая задача», «SPRINTIQUE / Контекст»); brands and acronyms are untouched (TYP-16).
- **`typo(text)`** in core (`time.js`): U+00A0 after one- and two-letter words, before «—», between a number and its unit and after «№»; the catalog kickers and the navigation story go through it (TYP-15).

## Settings (0.6.0-vnext.15)

`registerCore()` registers `iq-settings-layout` and `iq-visual-choice`.
See [the interactive example](examples/settings.html) after building the library.

- `iq-settings-layout` fills the width of its container: the navigation column (264px, `--iq-settings-nav-width`) sits flush left and stays in view while the content scrolls; the content is one left-aligned column up to `--iq-settings-measure` (1120px). Slots: `navigation`, `heading` and default content. At 760px and below the host sets `view="index"` (only the navigation) or `view="section"` (only the content). It does not own routing, API requests or form persistence. Set `--iq-app-header-height` when a product header sits above it.
- `settingsNavigation(groups, activeId)` returns the grouped links drawn with the DS side navigation (`.product-nav-link`, neutral current item, quiet group labels with `role=group`). Items have `id`, `label`, optional `icon`, and optional `count` with `countLabel` for things that need a decision. Put the `.iq-settings-title` and a `.product-nav-search.iq-settings-search` field above it; the host owns search, the `#settings/:id` routes and permission filtering.
- `.iq-page-heading` is the shared page heading: `.iq-page-heading-copy` (h1 in a 48px row and `.iq-page-heading-lead`) and `.iq-page-heading-tools` for the section's primary action. `.iq-page-heading-back` appears on phones.
- Compositions: `.iq-settings-stack` (40px rhythm), `.iq-settings-group` (h2, description, actions, count), `.iq-settings-panel` with `.iq-settings-row` (media, copy with title and meta, aside for a value, badge or select, actions with at most one visible button and an `iq-menu`; `a`/`button` rows are a single action with a chevron; `data-state="muted"`), `.iq-settings-field-row` (label left, control right), `dl.iq-settings-facts` (read-only values), `.iq-settings-lock` (read-only notice), `.iq-settings-savebar` (sticky, hidden until the form changes), `.iq-empty.compact`, `.iq-secret` (a value shown once, with copy), `.iq-choice-list` (radios with descriptions), `.iq-choice-grid` (a permissions matrix) and `.iq-settings-skeleton`.
- People who cannot change a setting see facts and a lock notice, never a disabled form.
- `iq-visual-choice` takes an `options` property of `{value, label, description?, preview?}`. Supported previews: `light`, `dark`, `system`, `comfortable`, `compact`. Set its `label` attribute for the accessible group name. Native radios support Tab and arrow keys. The `value` attribute/property and `disabled` attribute are reactive. A user choice emits bubbling `iq-change` with `{value}`. The selected card gets an accent ring on the same surface.

Optional root attributes `data-accent="blue|violet|green"`, `data-density="comfortable|compact"`, and `data-motion="system|reduced"` apply token-backed preferences; the accent blocks are generated into `tokens.css` from the `accents` section of `tokens/semantic.json`. Without `data-theme` the stylesheet follows `prefers-color-scheme`; inline `dist/theme-boot.js` (`@iquipage/web/theme-boot.js`) in `<head>` to apply the stored `iq-theme|iq-accent|iq-density|iq-motion` keys before first paint (see docs/INTEGRATION.md, «Темизация»). Density changes library table cells and task cards; status tones stay semantic. Use `data-theme="light|dark"` for the resolved theme. The host should resolve the system preference, persist settings, and report storage failures. System reduced-motion is always respected. Do not persist user preferences inside these components.
