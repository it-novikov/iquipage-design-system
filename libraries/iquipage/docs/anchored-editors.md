# Всплывающий редактор внутри диалога

Человек открывает маленький редактор у свойства, меняет значение и отменяет ввод, оставаясь в исходном объекте. Видимое окно ещё не означает работоспособный редактор: оно должно принимать фокус и клавиши, сохранять контекст и завершать свой lifecycle вместе с владельцем.

Сначала используйте поставленный компонент: `iq-date-field`, `iq-select` или `iq-menu` со своим публичным контрактом. Этот рецепт относится к уже существующему прикладному адаптеру специфического редактора. Он не вводит новый `ui.popover` API и не разрешает заменять готовые контролы самодельными.

## Владение и фокус

Popover API выводит поверхность в верхний слой рисования. Это не отменяет область доступного фокуса modal dialog. По [HTML Standard](https://html.spec.whatwg.org/multipage/interaction.html#modal-dialogs-and-inert-subtrees), узлы вне активного modal и его потомков становятся inert. Поэтому всплывающий редактор под `document.body` может быть виден поверх диалога и при этом не получать ввод.

| Ситуация | Правило интеграции |
| --- | --- |
| Anchor внутри native dialog | Popup принадлежит этому dialog; его собственная форма располагается вне родительской формы объекта. Не создавайте вложенные формы. |
| Anchor на обычной странице | Допустим обычный host страницы; modal не создаётся ради маленького редактора. |
| Открытие | Реальный элемент ввода получает фокус без неожиданной прокрутки. Проверяется `document.activeElement`, а не только `:popover-open`. |
| Escape внутри редактора | Закрывается редактор; исходный dialog остаётся открыт. Фокус возвращается к доступному исходному anchor. |
| Закрытие владельца или удаление anchor | Popup и его слушатели/наблюдатели завершаются. На следующем экране не остаётся чужое всплывающее окно. |
| Отмена несохранённого ввода | Значение объекта остаётся прежним, команда сохранения не отправляется. |

Сохраняйте локальную обработку Escape в редакторе. Глобальный перехват клавиши или дополнительный focus trap не исправляет неверное владение и может вмешаться в соседние окна. Cleanup должен быть идемпотентным: закрытие владельца, удаление anchor и callback сохранения могут прийти рядом.

## Размер содержимого

Проверяйте внутренние элементы, а не только внешний прямоугольник popup. Автоматический минимум grid-колонки или flex-ряда может сделать форму шире видимого окна, даже когда сам popup помещается в viewport.

В прикладной композиции используйте сжимаемые grid-колонки (`minmax(0, 1fr)`), разрешённый перенос групп управления и команд, читаемые токены шрифта. Группа единиц сохраняет связность, подсказка переносится, ошибки не уходят за горизонтальную границу. Не уменьшайте текст и не прячьте overflow ради зелёной геометрии. Общий `.iq-popup` и готовый segmented-контрол не меняются ради одной неудачной формы.

## Что проверяет следующий агент

На точном поставленном пакете пройдите открытие → фактический focus → ввод → Escape → возврат к тому же объекту. Отдельно проверьте удаление владельца и обычный caller вне modal. Сохраните кадры и child geometry в узком варианте и с увеличенным текстом: все единицы, подсказка и команды должны быть доступны без горизонтальной прокрутки окна.

Проверка callback в синтетической fixture подтверждает границу frontend, а не запись в backend. Реальные Safari, Firefox, iOS touch и screen reader входят в отдельную предрелизную проверку. Новый универсальный компонент или расширение публичного API требуют собственной проработки, типов, версии пакета и consumer-приёмки.
