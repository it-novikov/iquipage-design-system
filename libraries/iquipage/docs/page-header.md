# Заголовок рабочей страницы

`iq-work-header` — один заголовок страницы под общей навигацией приложения. Название и контекст слева, действия справа; на узком экране действия переносятся ниже. Не помещайте вторую копию названия в toolbar или плавающий элемент холста.

`title`, `description`, `eyebrow`, `density="compact|comfortable"` — атрибуты. `slot="title"` позволяет передать собственный `h1`, в том числе с переключателем релиза или карты. При наличии этого слота компонент не добавляет второй h1. `slot="back"` размещает возврат над названием. `slot="actions"` содержит действия, `slot="context"` — дополнительную строку. Узлы переносятся без клонирования: обработчики и значения остаются на них. Пустые actions/context не требуют заглушек.

Публичные переменные `--iq-work-header-padding`, `--iq-work-header-border`, `--iq-work-header-title`, `--iq-work-header-gap`, `--iq-work-header-description-gap` задаются на host и сохраняют смысл на мобильном экране и внутри узкого work-layout. Не переопределяйте внутренние классы из приложения. Возврат остаётся обычной ссылкой либо кнопкой со своим прикладным обработчиком.

```html
<iq-work-header description="Текущий релиз">
  <h1 slot="title"><button type="button" class="iq-btn ghost">Выпуск 1.0</button></h1>
  <button slot="actions" type="button" class="iq-btn primary">Новая задача</button>
</iq-work-header>
```

`iq-banner` подходит для предложения, связанного с текущим полем. Текст кратко называет доступное изменение, кнопки показывают явное действие и возможность оставить текущее значение. На узком экране действия переносятся. Это постоянное предложение, а не toast об успешном сохранении.

Блокировка не является приоритетом. Для явно подтверждённой блокировки используйте публичный `iq-badge danger` со знаком замка и словом «Заблокирована»; он может сосуществовать с `taskEmphasis`. Не окрашивайте всю обычную задачу как critical и не показывайте «разблокирована», если сведения ещё не получены.
