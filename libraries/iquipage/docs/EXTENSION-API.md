# Контракты расширения IQUIPAGE 05.5

Эта документация описывает реализованный Web API, а не API сервера. Базовые компоненты 04.9 сохранены. `iq-roadmap` не заменяет `iq-plan` с дедлайнами; `iq-graph` не заменяет древовидную навигацию; `iq-data-chart` — единственный компонент каталожного раздела «Данные → Диаграмма», объединяющий согласованный визуальный стиль и настоящие числовые ряды. Старый маршрут `components/data-chart` перенаправляется в `components/chart`.

## Подключение

```html
<link rel="stylesheet" href="./dist/iquipage.css">
<iq-roadmap id="plan"></iq-roadmap>
<script type="module">
import { registerAdvanced } from './dist/advanced.js';
registerAdvanced(); // повторная регистрация безопасна
const plan = document.querySelector('#plan');
plan.data = {
  revision: 1,
  title: 'Выпуск',
  rows: [
    { id:'design', title:'Проверить прототип', start:'2026-09-01', end:'2026-09-04' },
    { id:'release', kind:'milestone', title:'Выпуск', start:'2026-09-05', end:'2026-09-05' }
  ],
  dependencies: [{ id:'d1', from:'design', to:'release', type:'FS', lagDays:0 }]
};
plan.range = {start:'2026-09-01', end:'2026-09-30'};
plan.today = '2026-09-07'; // календарная дата в часовом поясе приложения
</script>
```

Для production передавайте данные свойствами DOM-элемента, а не сериализуйте пользовательский JSON в строку HTML. JavaScript-экспорт — `dist/iquipage.js`; декларации нового API — `types/extensions.d.ts`. В package.json подмаршрут `@iquipage/web/advanced` загружает отдельный entry `dist/advanced.js`, который разделяет core-примитивы с остальными входами. Декларации относятся к расширению, а не ко всем старым экспортам.

В интеграции библиотека не регистрирует `iq-extension-demo` и не содержит демонстрационные модели. Никакого автоматического подключения React, API или маршрутизатора нет.

## 1. Общая транзакция: roadmap и graph

Свойства: `data`, `readonly`, `state`, `controlled`. Состояния: `ready`, `loading`, `empty`, `error`, `blocked`. `readonly` и `state` поддерживаются также атрибутами. Getter `data` возвращает копию текущего значения; если есть черновик — копию черновика. Мутация полученной копии сама по себе не меняет компонент.

`controlled=false` по умолчанию: после явного «Применить» значение принимается локально, отправляется `iq-change`. Это не серверное сохранение. Числовая revision увеличивается на один; для непронумерованной строковой версии локальный пример добавляет `*`.

Для приложения с сервером устанавливайте `controlled=true` и обрабатывайте запрос:

```js
plan.controlled = true;

plan.addEventListener('iq-change-request', async ({detail}) => {
  // detail: value, previous, baseRevision, operation, signal, accept(), reject()
  try {
    const canonical = await savePlan({
      value: detail.value,
      expectedRevision: detail.baseRevision,
      signal: detail.signal
    });
    detail.accept(canonical); // требуется полное корректное значение с revision сервера
  } catch (error) {
    if (!detail.signal.aborted) {
      detail.reject('Не удалось сохранить изменения. Черновик сохранён.');
    }
  }
});
```

`savePlan` — функция приложения. Компонент не знает URL, полномочия пользователя или формат серверной ошибки. Нельзя использовать публичный `accept()` элемента в обход обработчика для позднего ответа: безопасная проверка актуальности находится в `detail.accept()` конкретного запроса.

### События

| Событие | detail |
|---|---|
| `iq-selection` | `{kind:'row'|'dependency'|'node'|'edge', id}` или `null` при снятии выбора |
| `iq-preview` | `{value, baseRevision, operation}` |
| `iq-change-request` | `{value, previous, baseRevision, operation, signal, accept(value), reject(message)}`; отменяемое |
| `iq-change` | `{value, operation?}` после принятия |
| `iq-cancel` | отменён черновик или ожидание |
| `iq-conflict-resolved` | `{strategy:'reload'|'reapply', value}` |
| `iq-retry` | запрос повторной загрузки внешних данных |
| `iq-viewport` | только граф: `{x,y,zoom}` |

События всплывают и проходят границу Web Component. Полезно проверять `event.target`, если несколько компонентов вложены в один контейнер.

### Гарантии и ограничения принятия

`detail.accept()` / `reject()` возвращают boolean. Одна пара callbacks используется один раз. Ответ после отмены, отключения элемента или конфликтующей внешней версии возвращает `false`. AbortSignal позволяет адаптеру отменить запрос. Отказ сохраняет черновик и сообщает ошибку; повторное применение создаёт новый запрос.

Входная версия при наличии черновика не затирает его. Возможны два явных действия:

* **Загрузить новую** — отказаться от локальных правок и принять внешнее значение.
* **Перенести мои правки** — трёхстороннее сравнение base/local/remote. Неизменённые локально поля и внешние добавления сохраняются. Для поля, изменённого и локально, и извне, явно выбранные локальные правки побеждают.

Изменённый локально объект, удалённый или защищённый новой версией, не воскрешается и не разблокируется: перенос отклоняется. Структура после переноса повторно валидируется. Применение всё равно требует разрешения сервера. Это не CRDT, не автоматический merge на сервере и не замена проверке разрешений.

История локальной отмены ограничена 40 принятыми изменениями. При поступлении новой внешней базы старая история сбрасывается, чтобы отмена не возвращала данные другой версии.

## 2. `iq-roadmap` — интервалы, вехи и зависимости

`data = {revision?, title?, rows, dependencies?}`

Строка:
`{id, title, start, end, kind?:'task'|'milestone', progress?:0..100, status?, readonly?, blocked?}`.

* `start`, `end`: строгие календарные даты `YYYY-MM-DD`, обе **включительные**. Однодневная задача имеет одинаковые даты. Веха также требует одной даты.
* ID и заголовок непустые. `end` не раньше `start`.
* `progress`: конечное число от 0 до 100, необязательно.
* `status:'done'` меняет вид интервала; прочие прикладные статусы не превращаются в отдельную доменную модель.
* `blocked` и `readonly` запрещают изменение строки, не запрещая чтение.

Зависимость:
`{id, from, to, type?:'FS'|'SS'|'FF'|'SF', lagDays?:integer}`.

Для проверки конец трактуется как начало дня после включительного `end`. Поэтому обычная FS требует начало преемника не ранее следующего дня после конца предшественника. Отрицательный целый lag разрешён; дробный или NaN — нет. Дубликат пары from/to/type и цикл запрещены.

Изменение не двигает зависимые задачи автоматически. Нарушенная связь отмечается и блокирует «Применить», но черновик остаётся редактируемым. `roadmapConflicts(data)` возвращает список `{id,from,to,message}`; используйте его с предварительно валидированными данными.

### Диапазон и управление

* `range = {start,end}` — отображаемое окно до 731 дня включительно.
* `scale = 'fit' | 'day' | 'week' | 'month'` — реактивное свойство. `fit` показывает доступный диапазон в ширине поверхности; остальные режимы допускают внутреннюю прокрутку.
* `today` — реактивная дата. В приложении передайте её в нужном часовом поясе.
* Публичный выбор — `selection: {kind: 'row' | 'dependency', id} | null`. Setter проверяет существование объекта и не отправляет событие обратно. Слушайте `iq-selection` для действий пользователя; не изменяйте внутренний `selectedId`.

Перенос и край интервала дают предварительный результат; Escape отменяет текущий жест независимо от положения DOM-фокуса. Клавиатура: Left/Right — день; Shift — семь дней; Alt — конец интервала; Enter — применить черновик. Точные даты доступны в инспекторе через общий `iq-date-field`, без нативного календаря.

Для короткого интервала не искажается длительность ради текста: название и даты находятся в устойчивой колонке. Длинное название увеличивает реальную высоту строки; SVG-связи используют ту же геометрию. Вне диапазона показывается соответствующая подпись. На узкой поверхности — список **интервалов**, а не дедлайнов.

Границы: 500 строк, 1500 связей. Полноценное виртуализированное планирование, рабочие календари, праздники, критический путь, автоматическое выравнивание ресурсов и серверный ProjectRoadmap не входят в этот Web-компонент.

### Иерархия и работы без дат — 05.2

`RoadmapRow` дополнительно принимает `kind: 'goal' | 'epic' | 'task' | 'milestone'`, `parentId` и `blockReason`. Строки можно передать в несортированном порядке: компонент строит дерево, сохраняя порядок соседей из входных данных. Родитель должен существовать; циклы и дубликаты ID отклоняются. Иерархия не означает, что даты родителя автоматически суммируются из дат детей.

Для работы без дат **обе** границы отсутствуют либо равны `null`. Одна заполненная граница без второй — ошибка данных. Такая работа остаётся в дереве и мобильном списке; инспектор позволяет задать обе даты. Зависимость, требующая отсутствующей даты, объясняется как конфликт, а не рассчитывается из выдуманного дедлайна.

```js
plan.data = {
  revision: 1,
  rows: [
    {id:'task', parentId:'epic', kind:'task', title:'Проверить результат'},
    {id:'goal', kind:'goal', title:'Выпуск', start:'2026-09-01', end:'2026-09-30'},
    {id:'epic', parentId:'goal', kind:'epic', title:'Приглашение команды',
      start:'2026-09-05', end:'2026-09-16'}
  ], dependencies: []
};
plan.collapsedIds = ['epic'];
plan.selection = {kind:'row', id:'epic'};
plan.addEventListener('iq-collapse', ({detail}) => console.log(detail.ids));
plan.addEventListener('iq-open', ({detail}) => openEntity(detail.id));
```

`openEntity` принадлежит приложению: DS не меняет маршрут автоматически. `collapsedIds` — массив ID с копией при чтении. Вложенная свёртка сохраняется при закрытии и открытии родительской ветки. Визуальный отступ ограничен шестью уровнями для сохранения читабельности; это не удаляет глубокие элементы данных. Разделение диапазона и строк сохраняется и на мобильном. Конечная цель/эпик/задача могут иметь собственные сроки — это не планировщик ресурсов.

## 3. `iq-graph` — карта и процесс

`mode = 'map' | 'workflow'`, также атрибут. Оба режима используют один runtime и один визуальный набор.

`data = {revision?, title?, nodes, edges}`.

Узел:
`{id,kind,title,x,y,width,height,text?,items?,url?,alt?,parentId?,archived?,readonly?,status?}`

| kind | Содержание |
|---|---|
| `note` | заголовок и текст |
| `task` | задача с заголовком и содержанием |
| `checklist` | `items: [{label,checked}]`; собственный редактор пунктов |
| `media` | растровое изображение: HTTPS, локальный blob или разрешённый data URL, плюс alt |
| `group` | контейнер для узлов с `parentId` |

Координаты — конечные числа, модуль ≤100000; минимальный размер 180×100, максимальный 20000×20000. Неподдерживаемая модель отклоняется, а не молча урезается. Вложенность групп не может содержать цикл. Перенос группы перемещает всех потомков на ту же величину; resize группы не масштабирует содержимое. Если среди потомков есть защищённый объект, групповой перенос/архив недоступен.

Содержимое узла прокручивается внутри ограниченного размера и не перекрывает порты. Недоступная картинка получает текстовую замену. Вставка произвольного HTML не предусмотрена.

Связь:
`{id,source,target,kind?:'relates'|'depends'|'supports',label?,disabled?,status?}`.
Тип `depends` читается в направлении **source предшествует target**. `supports`: source подтверждает target. `relates`: source связан с target; направление видно в текстовом представлении.

Самоссылка и несуществующие концы запрещены. Ручное соединение через UI не добавляет повтор той же направленной пары. Циклический граф можно показывать; автоматическое размещение допускает только ациклический граф и не двигает защищённые объекты. Для авторазмещения используется реальная ширина и высота узлов, не одинаковая условная ячейка.

### Действия и альтернативы

Мышь: перенос за заголовок узла, resize за нижний угол выбранного узла, порты source→target. Панорамирование — по пустому месту/режиму обзора. Ctrl/Cmd + колесо масштабирует вокруг указателя. Панель обзора и миникарта дают альтернативный путь.

Клавиатура: Tab — объекты и действия; Enter — инспектор; стрелки — соседний объект; Alt + стрелки — координаты; Alt + Shift + стрелки — размер. Точные значения, связь и подпись редактируются формами. Escape отменяет жест/создание связи/черновик, затем закрывает расширенный режим.

На узкой поверхности есть список узлов и направленных отношений. Выбор объекта переводит пользователя к его инспектору с сохранением данных. Архив группы помнит, какие потомки были архивированы вместе с ней; ранее архивированные объекты не восстанавливаются случайно.

`presence = [{id,label,cursor?:{x,y},editingNodeId?}]` — только входное представление. Канал передачи, авторизация, блокировки и совместное редактирование реализуются приложением.

Границы: 400 узлов, 1200 связей. Не реализованы CRDT, произвольный видеоредактор, маршрутизация линий с глобальным избеганием всех пересечений и виртуализация бесконечного числа узлов. При большой сцене обзор намеренно уменьшает масштаб; для чтения есть увеличение и текстовый режим.

### Управляемый обзор и выделение — 05.2

```js
graph.data = model;
graph.viewport = {x:24, y:32, zoom:0.85};
graph.selection = {kind:'node', id:'task'};
graph.addEventListener('iq-viewport', ({detail}) => persistViewport(detail));
graph.addEventListener('iq-selection', ({detail}) => persistSelection(detail));
```

`persistViewport` / `persistSelection` — функции приложения. Координаты обзора задаются в экранных CSS-пикселях; координаты узла и присутствия — в пространстве карты. `zoom` от 0.25 до 2, все координаты конечны. Getter возвращает копию. Setter обзора и setter выбора работают **без обратного события**, не создавая цикл обновлений. Обзор, установленный до вставки элемента в DOM, не заменяется автоматическим fit. Вызов `fit()` явно возвращает обзор всей сцены.

`selection = null` снимает выбор. Допустимы `{kind:'node',id}` и `{kind:'edge',id}`; исчезнувшая из авторитетных данных связь снимается с выбора. Полученная новая версия при открытом черновике сначала попадает в состояние конфликта: она не стирает рабочий объект до решения пользователя.

В 05.2 интерфейс состоит из четырёх уровней: заголовок/представление, узкая панель инструментов, холст/список, свойства выбранного объекта. «Добавить объект» открывает библиотеку пяти типов. Инспектор сохраняет ещё не применённый ввод при открытии инструментов. Явное изменение самой модели делает данные приложения приоритетными. Порты показывают направление геометрически; в режиме соединения самоссылка и повтор уже существующей пары недоступны. Создание, перенос и редактирование остаются черновиками до применения.

Кривые выбирают горизонтальный или вертикальный выход по положению объектов. Это локальная геометрия, **не** глобальный маршрутизатор с гарантией отсутствия пересечений в произвольной сцене. Наличие режима `workflow` не означает исполнение процесса: компонент редактирует отношения, не запускает API или агентов.

## 4. `iq-remote-combobox`

Атрибуты: `label`, `placeholder`, `name`, `required`, `disabled`, `readonly`.
Свойства: `value`, `selectedOption`, `options`, `provider`, `debounce` (180ms по умолчанию), `controlled`, `disabled`, `readonly`.

Опция:
`{value:string,label:string,description?:string,disabled?:boolean}`.
Значение и label непустые, value уникален. Не более 10000 опций в одной поставке.

```js
const select = document.querySelector('iq-remote-combobox');
select.selectedOption = {value:'person-42',label:'Анна Волкова'};

select.provider = async ({query,cursor,signal}) => {
  const response = await fetch('/api/people?' + new URLSearchParams({
    query, cursor:cursor ?? ''
  }), {signal});
  if (!response.ok) throw new Error('Не удалось получить участников.');
  return response.json(); // {options, nextCursor:string|null}
};
```

Адрес, авторизация, timeout, пагинация и ответы API — ответственность адаптера приложения. При замене функции provider вызовите `request(false)`, если нужно сразу повторить текущий запрос. Компонент сам не делает сетевых запросов.

Вариант без provider: обработать `iq-query` (`query,cursor,requestId,signal`) и передать `setResult(result,requestId)` либо `setError(message,requestId)`. Эти методы отказываются от результата устаревшего запроса. Setter `options` заменяет список и отменяет незавершённый поиск; для paginated source следует использовать `setResult`, а не setter.

`selectedOption` сохраняется, даже если опции нет в текущей странице. Значение, установленное только через `value`, без известной опции отображается как этот ID; для понятного имени передавайте `selectedOption`.

Выбор отправляет отменяемое `iq-change-request` с `{value,option,previous}`. В обычном режиме затем обновляется значение и отправляется `iq-change`. При `controlled=true` приложение само устанавливает selectedOption/value. У этого события **нет accept/reject, как у транзакционных поверхностей**: не смешивайте два контракта.

Инпут и кнопки футера не пересоздаются при запросе. Ошибка следующей страницы сохраняет предыдущие опции и её cursor. Повтор не начинает выдачу заново. IME не инициирует запросы по промежуточным символам. Выбранное значение, активная клавиатурная опция и фокус — разные состояния.

ArrowUp/Down — опции; Enter — выбор; Escape — закрытие. Tab может перейти к очистке и кнопкам выдачи; Enter на «Загрузить ещё» работает без закрытия. Home/End оставлены редактированию текста, Alt + Home/End — начало/конец списка. Popup расположен в верхнем слое, если доступен Popover API, и ограничен viewport. Он не перекрывает собственное поле.

ElementInternals связывает значение с формой; required, reset и disabled fieldset поддержаны. Список системного автозаполнения браузера не подменяется имитацией.

## 5. `iq-tag-input`

Свойства: `value:string[]`, `controlled`, `disabled`, `readonly`.
Атрибуты: `label`, `name`, `required`, `max` (20), `maxlength` (40), disabled/readonly.

Пустой массив допустим. Setter заменяет значение и отменяет ожидающее принятие; никакие demo-теги не добавляются. Строки обрезаются по краям; дубликаты проверяются с учётом регистра, пустые и слишком длинные строки отклоняются. Значение выше max отклоняется, а не незаметно обрезается.

```js
const tags = document.querySelector('iq-tag-input');
tags.controlled = true;
tags.value = [];
tags.addEventListener('iq-change-request', ({detail}) => {
  // Синхронное принятие:
  tags.value = detail.value;
  // Либо асинхронно: detail.accept() / detail.reject('Пояснение').
});
```

detail: `{value,previous,operation,accept(),reject(message)}`. Отмена ожидания делает старые callbacks неактуальными. При отказе введённый текст остаётся. При принятии нового тега поле очищается. В read-only режиме нет вводящих в заблуждение кнопок удаления.

Enter/запятая добавляют один тег, Backspace в пустом поле удаляет последний. Обработка IME не перехватывает композицию. Форменное значение — JSON массива.

## 6. `iq-data-chart`

```js
chart.data = {
  title:'Работа по месяцам',
  description:'Одинаковая шкала для двух рядов.',
  unit:'Задачи', xLabel:'Месяц',
  labels:['Апр','Май','Июн'],
  series:[
    {id:'done',label:'Завершено',values:[31,49,null]},
    {id:'target',label:'Цель',values:[40,54,50]}
  ]
};
chart.type = 'line'; // 'bar' — сгруппированные столбцы
chart.state = 'ready'; // loading, empty, error
chart.formatValue = n => new Intl.NumberFormat('ru-RU').format(n);
// formatValue задавайте до data; при замене форматтера вызовите chart.render().
```

Ровно столько значений в ряду, сколько labels. До 1000 категорий и 12 рядов. Неконечные числа, нечисловые значения и null — пропуски, **не нули**; числовая 0 сохраняется. Отрицательные значения и экстремальные конечные масштабы не создают NaN/Infinity в SVG.

Видимые ряды строят общую шкалу; легенда может скрыть все ряды, после чего появляется «Показать все ряды». Фокус легенды сохраняется. Линии не соединяют разрыв. Цветов шесть; для большего числа рядов повторение сопровождается типом штриха.

Подсказка работает от указателя и клавиатуры. Left/Right выбирает следующий существующий период в ряду, Up/Down — ряд, пропуски пропускаются. `iq-point-select` передаёт `{index,label,seriesId,value}` при явном выборе. Таблица построена из исходных значений и содержит «Нет данных» в пропусках; DOM строк таблицы создаётся только при открытии.

При loading/error старая таблица и старая диаграмма вместе скрыты — устаревшие цифры не выдаются за свежий результат. `iq-retry` передаётся адаптеру. Вспомогательные функции: `normalizeChartData`, `validateRoadmap`, `roadmapConflicts`, `validateGraph`, `layoutGraph`.

## 7. `iq-image-crop` — ручное кадрирование профиля

Работающий Web-компонент, не автоматическая центральная обрезка. Выбор области задаётся в **пикселях оригинала**. Интерфейс показывает круглую маску аватара; экспортируемый файл квадратный, а круговое отображение выполняет компонент аватара.

```html
<iq-image-crop id="avatarCrop"></iq-image-crop>
```
```js
import {registerIquipage} from './dist/iquipage.js';
registerIquipage();
const crop = document.querySelector('#avatarCrop');
const loaded = await crop.load(file); // File или Blob, не произвольный URL
if (loaded) {
  crop.value = {x:0, y:0, width:200, height:200}; // пример допустимого квадрата
  const blob = await crop.export({size:512, type:'image/png'});
  // blob подготовлен локально. Загрузку в профиль выполняет приложение.
}
```

Перед назначением собственного `value` проверьте размеры исходного файла. Getter `value` возвращает `null`, пока изображение не декодировано. `source` — setter File/Blob или null; для ожидания результата используйте async `load(source)`. `load(null)` очищает источник и возвращает false. Ошибка файла доступна в `error`, `load()` возвращает false, компонент не зависает в загрузке.

Ограничения входа: PNG, JPEG или WebP, до 10 МБ, каждая сторона от 32 px, не более 40 мегапикселей. SVG и видео не принимаются. Изменение масштаба 1–4 от наибольшего вписанного квадрата; область не выходит за изображение. `cropRect(width,height,zoom,x,y)` — та же функция геометрии, `x/y` нормализованы от 0 до 1. Setter `value` принимает конечный квадрат внутри оригинала и допустимого масштаба, иначе выбрасывает TypeError/RangeError.

Управление: перетаскивание изображения; ползунки масштаба и положения; стрелки с фокусом на предпросмотре — 1 исходный пиксель, Shift — 10; Escape отменяет текущий перенос. Неактивная ось, по которой нет пространства для перемещения, блокируется. Есть возврат к центральному исходному кадру. `disabled`/`readonly` сохраняют просмотр и запрещают изменение.

`export({size=512,type='image/png',quality=.92})` возвращает Promise<Blob>. Допустимый размер 32–2048, целый; PNG/JPEG/WebP; quality 0–1. Браузер отвечает за поддержку выходного кодека: перед сохранением используйте фактический `blob.type`. Оригинал не изменяется. Для неподготовленного источника export отклоняет Promise. Чужой URL с неясными CORS/полномочиями не загружается компонентом.

### Принятие приложением

```js
crop.controlled = true;
crop.addEventListener('iq-crop-request', async ({detail}) => {
  // Не выдавайте локальное получение Blob за серверное сохранение.
  try {
    await uploadAvatar(detail.blob, {signal:detail.signal});
    detail.accept();
  } catch (error) {
    if (!detail.signal.aborted) detail.reject('Не удалось обновить фото. Кадр сохранён.');
  }
});
```

`uploadAvatar` — адаптер приложения. Событие отменяемое; `detail = {blob,crop,signal,accept(),reject(message)}`. `crop` фиксирует область в момент запроса. В controlled-режиме интерфейс ожидает решения; отмена, замена источника, новое внешнее значение, отключение или удаление элемента делают старый callback недействительным. Принятие и отказ одноразовые, возвращают boolean. При отказе область остаётся доступной для повторения.

События: `iq-crop-load {width,height}`, `iq-crop-change {crop}`, `iq-crop-request`, `iq-crop-result {blob,crop}`, `iq-crop-cancel`. Без controlled «Подготовить кадр» получает локальный Blob и отправляет `iq-crop-result`; серверная операция не имитируется. Созданный приложением ObjectURL для результата приложение обязано освободить самостоятельно. Внутренние URL, наблюдатели и pointer-обработчики компонент освобождает при замене источника и удалении.

## Ответственность приложения

Серверные адаптеры, React-обёртки, права доступа, security/изоляция черновиков, маршрутизация, timeout, хранение и миграции, разрешение конфликтов, коллаборация и реальные данные не входят в расширение DS. ## Дополнения публичного контракта 05.5

### Roadmap

`dependencyCapabilities = false` выключает создание, изменение и удаление календарных зависимостей, сохраняя доступное редактирование дат. Можно назначить объект `{create:false, update:true, delete:false}`; отсутствующие ключи сохраняют значение true по умолчанию. Ограничения проверяются не только при построении панели, но и перед применением. Если права изменились во время запроса, старое принятие не действует.

Родителем `task` может быть другая задача, а не только цель/эпик. Проверяются существование родителей, циклы и валидность общей иерархии. Ни переименование обычной задачи в эпик, ни преобразование `blocks/precedes/related/deliver_together` в календарные FS/SS/FF/SF не выполняются. Если приложение не хранит календарные связи, передайте `dependencies:[]` и выключите их редактирование; свои предметные отношения сохраняйте отдельно.

`iq-view-change` отправляется при выборе пользователем масштаба/переходе диапазона: `{scale, range:{start,end}, reason}`. Программные `scale`/`range` setters не создают event loop. Слушатель приложения может сохранять диапазон в deep link.

### Graph: виды, права и чтение

- `allowedKinds`: массив `note/task/checklist/media/group`; влияет на создание новых объектов, не удаляет существующие.
- `kindLabels`: подписи видов, например `{task:'Статус'}` для графа процесса.
- `permissions`: глобальные права; `nodePermissions`: объект по ID с независимыми правами объекта. `false` запрещает все операции.

Ключи прав: `read`, `create`, `move`, `resize`, `editContent`, `connect`, `editRelations`, `deleteRelations`, `archive`, `restore`, `open`, `discuss`. По умолчанию они разрешены, кроме `discuss`. Глобальный запрет нельзя отменить правом одного объекта. `fields:{title:false, text:true}` уточняет изменяемые поля. Приложение должно явно установить свои разрешения до предоставления действий.

`readonly` у предметного узла по умолчанию запрещает изменения. Явное `nodePermissions[id].move=true`/`resize=true` позволяет менять его геометрию без изменения содержания. Глобальный readonly компонента по-прежнему запрещает все пользовательские изменения.

`read:false` скрывает заголовок, текст, items, альтернативный текст и медиаисточник из DOM. Контент не появляется и в текстовом представлении/инспекторе/подписях связей с закрытым узлом. Это **защита представления, не серверная авторизация**: объект данных уже принадлежит приложению и доступен через getter. Не передавайте в браузер сведения, которые пользователь не вправе получить вообще.

Кнопка открытия отправляет `iq-open: {kind:'node',id,node}` и не меняет маршрутизатор. При `discuss:true` доступно `iq-discussion: {id}`. Компонент не хранит и не отправляет комментарии в API. Программный selection setter молчит; canvas, список и клавиатурный выбор отправляют одинаковый `iq-selection`, снятие выбора — `null`.

### Медиа и архив

`mediaSources = new Map([['id', blobOrHttpsUrl]])` отделяет временный источник от сериализуемого документа. Blob превращается в объектный URL внутри компонента; URL освобождается при смене источника, удалении объекта, отзыве чтения и отключении компонента. Источник HTTPS должен быть уже авторизован приложением; библиотека не принимает токены и не добавляет Authorization сама. Для запроса с заголовками сначала получите Blob в адаптере приложения. Не помещайте подписанные ссылки в `node.url` для объектов с ограниченным чтением.

`archiveClusters = [{id,title,nodeIds}]` описывает вычисленные приложением архивные агрегаты. Они не становятся изменяемыми visual group и не архивируют/восстанавливают свои элементы по нажатию. Открытие даёт `iq-open: {kind:'archive-cluster',id}`; предметное действие решает приложение.

### Координаты и presence

`viewport={x,y,zoom}`: x/y — смещение рабочей сцены относительно canvas в CSS px; узлы — в координатах сцены. `world=(client-canvasRect-viewportOffset)/zoom`. Изменение пользователем даёт `iq-viewport`; установка приложением не повторяет событие.

`iq-pointer` содержит `{inside:true,x,y,pointerType}` в world-координатах и `{inside:false}` при уходе. Оно ограничено одним отправлением за кадр. Приложение само выбирает частоту сетевых отправлений и канал realtime. Входные `presence` не означают существование сервера совместной работы.

### Контекст кадрирования

`content={eyebrow,title,subtitle,placeholder}` задаёт внутренние тексты; атрибуты с теми же именами также поддерживаются. По умолчанию формулировки нейтральные. Изменение только подписи не отменяет уже подготовленный crop-запрос. Смена исходного Blob и отзыв редактирования по-прежнему инвалидируют запоздавшие ответы. File/Blob, пиксельный rect и экспорт остаются прежним контрактом.

### Компактный рабочий заголовок

`iq-work-header` входит в core. Атрибуты: `title`, `description`, `eyebrow`, `density=compact|comfortable`. Дочерние элементы с `slot="actions"` и `slot="context"` переносятся в соответствующую область без клонирования. Настоящий h1 сохраняет семантику; toolbar roadmap/graph размещается ниже и не дублируется в заголовке. Смотрите INTEGRATION.md.
