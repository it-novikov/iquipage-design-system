# Дополнения IQUIPAGE для повседневной работы

07.09.2026. Поставка 05.2 не изменена. Эти два ограничения подтверждены на работающем Sprintique и дополняют прежние запросы по карте, roadmap, контрасту и motion. Изменять только CSS приложения или внутренний DOM Web Component для их обхода не следует.

## Компактный каркас рабочего экрана

Проблема: крупный заголовок проекта, описание, навигация, сводка, виды, поиск и страницы оставляют мало места самой работе. В наблюдаемом экране 1280×720 первая строка задач начиналась примерно на y=638. Для ежедневного инструмента это заставляет прокручивать ещё до выбора задачи.

Нужен публичный вариант плотности существующего рабочего шаблона: компактные заголовок, описание и расстояния между навигацией/toolbar/данными. Это должно быть общей настройкой DS, применимой к задачам, идеям, плану, релизам и административным спискам. Основное действие и текущий проект остаются видимыми; названия не обрезаются без доступного полного текста.

Приёмка: 1280×720 и 1440×900 показывают несколько рабочих строк без начальной прокрутки; на 390 px доступны название, основное действие и первый элемент. Светлая/тёмная темы, длинное название, 200% zoom, клавиатура. Конкретную геометрию согласовать на рабочих списках, сохранив исходную типографическую и интервальную шкалу DS.

## Markdown для чтения

Проблема: read-only отчёт агента отображается в редакторе с выключенными инструментами и подписью Markdown. На мобильном экране эта панель занимает значительную часть области чтения и создаёт впечатление доступного редактирования. Содержание сейчас отображается корректно; проблема в избыточном chrome.

Нужен публичный viewer либо режим отображения существующего компонента: тот же безопасный renderer и типографика, без toolbar/preview switch/footer редактирования. Контракт должен поддерживать заголовки, списки, ссылки, code blocks, таблицы, пустое значение, перенос длинных строк и семантические роли. Просмотр не должен допускать HTML injection, выполнение кода или автоматическую загрузку приватных внешних ресурсов.

Приёмка: одинаковый документ в редакторе preview и viewer; только разрешённые URL, клавиатурные ссылки, перенос/прокрутка широкого code/table внутри блока, обе темы/390 px/200% zoom. Viewer не должен давать впечатление, что просмотр принимает результат агента или меняет статус задачи.

Наблюдаемое доказательство: `output/playwright/human-first/final/agent-human-experience-acc-3e8d7-tay-readable-in-both-themes-webkit/report-dark-390.png`. Контракт имени/props выше — запрос на расширение, не существующий API библиотеки.
