# IQUIPAGE 05.6 — повседневная работа

Два дополнения из заявки от 07.09.2026: общий компактный рабочий каркас и Markdown для чтения. Публичные имена ниже введены в 05.6; их не следует считать API исходной 05.2.

## Подключение

```js
import {
  registerCore,
  registerWorkLayout,
  registerMarkdownViewer,
  safeMarkdown,
} from './dist/core.js';
// Подключите dist/iquipage.css один раз на странице.
registerCore(); // включает оба компонента, повторный вызов безопасен
```

`core` не загружает roadmap, graph, crop или whiteboard. Для отдельной регистрации доступны `registerWorkLayout()` и `registerMarkdownViewer()`. Существующий полный вход `dist/iquipage.js` совместим. Библиотека поставляется локально; публикация версии в npm не выполнялась.

## Компактный каркас рабочего экрана

### Разметка

```html
<main>
  <iq-work-layout density="compact" label="Проект">
    <iq-work-header
      slot="header"
      title="Выпуск 2.5"
      eyebrow="Sprintique / Команда продукта"
      description="Задачи следующего выпуска.">
      <button type="button" slot="actions" class="iq-btn primary sm">
        Новая задача
      </button>
    </iq-work-header>

    <nav slot="navigation" class="iq-work-navigation" aria-label="Разделы проекта">
      <a href="/project/tasks" aria-current="page">Задачи</a>
      <a href="/project/ideas">Идеи</a>
      <a href="/project/plan">План</a>
    </nav>
    <div slot="summary" class="iq-work-summary">12 задач, 4 участника</div>
    <div slot="toolbar" class="iq-work-toolbar">
      <!-- Существующие поиск, фильтры, выбор вида и действия DS. -->
    </div>
    <section class="iq-work-data" aria-label="Задачи">
      <!-- Существующий список, таблица или сложный компонент. -->
    </section>
    <div slot="footer" class="iq-work-footer">
      <!-- Счётчик и пагинация принадлежат данным, не заголовку. -->
    </div>
  </iq-work-layout>
</main>
```

### Контракт

| Свойство / атрибут | Поведение |
| --- | --- |
| `density` / `density="compact\|comfortable"` | По умолчанию `comfortable`. Setter принимает только два значения; неверное значение вызывает `TypeError`. Изменение — CSS-композиция, без перезаписи значений, перестройки slotted-данных и смены фокуса. |
| `label` | Необязательное доступное имя контейнера. Компонент не создаёт дополнительный `main`. |
| `sticky-header` | Опционально закрепляет только заголовок и основные действия в текущем прокручиваемом контейнере. При viewport ниже 500 CSS px закрепление отключается, чтобы не закрывать данные при увеличении. |
| `--iq-work-sticky-offset` | Публичный CSS-параметр верхнего смещения для закреплённой навигации приложения. По умолчанию `0px`. Это настройка контракта, а не патч внутреннего DOM. |

Названные slots: `header`, `navigation`, `summary`, `toolbar`, `footer`. Основные данные помещаются в **default slot**, не `slot="content"`. Отсутствующие slots не оставляют пустой полосы; элементы можно добавлять и удалять реактивно. Shadow DOM каркаса только размещает slots. Приложение не обращается к нему.

`iq-work-header` продолжает создавать настоящий `h1`. Весь текст названия переносится, а не обрезается. Actions и context этого компонента сохраняют прежний контракт. Для реальной страницы нужен один основной заголовок; обрамление самого каталога не следует переносить в продукт.

Плотность не загружает данные, не хранит выбор пользователя и не маршрутизирует приложение. При необходимости приложение сохраняет `layout.density` в собственной настройке. В примере каталога настройка сохраняется через прежний локальный механизм демонстрации.

### Плотность и масштаб

Существующие цветовые токены не изменены. Добавлены только роли компоновки:

| Роль | Compact | Comfortable |
| --- | --- | --- |
| `work-*-padding` | `space-6` / 24 px | `space-8` / 32 px |
| `work-*-gap` | `space-3` / 12 px | `space-6` / 24 px |
| `work-*-title` | 24 px | 30 px |
| `work-*-row` | минимум 56 px | минимум 72 px |

Контент может увеличить высоту строки: минимум не является фиксированной высотой. На узкой ширине используются отступы 16 px и заголовок 21 px, присутствовавшие в существующем рабочем header. Название и главное действие переходят в последовательный поток.

Навигация и краткая сводка располагаются на одной строке, пока помещаются. На узкой ширине — отдельными строками. Для вложенного `iq-roadmap` / `iq-graph` компактная композиция сокращает повторный заголовок инструмента, не изменяя геометрию интервалов, данных или предметный API. Диапазон и действия инструмента остаются доступны.

Публичные классы для композиции: `.iq-work-navigation`, `.iq-work-summary`, `.iq-work-toolbar`, `.iq-work-toolbar-group`, `.iq-work-data`, `.iq-work-footer`. `.iq-work-table` — необязательная простая таблица для таких списков. Это не универсальная data-grid с виртуализацией. Можно использовать уже поставленные таблицы, дерево, календарь и roadmap. Пример `workbench.html` содержит действующие поиск, фильтр, локальное добавление и открытие записи; вкладка «План» использует настоящий `iq-roadmap`.

## Markdown для чтения

```html
<iq-markdown-viewer label="Отчёт агента"></iq-markdown-viewer>
```

```js
const viewer = document.querySelector('iq-markdown-viewer');
viewer.value = '# Результат\n\nСодержание отчёта.';
viewer.headingLevel = 2;
```

| Контракт | Значение |
| --- | --- |
| `value: string` | Текст Markdown. Реактивное свойство либо экранированный атрибут `value`. Свойство предпочтительно для больших документов. `null`/`undefined` нормализуются в пустой текст. Данные можно задать до регистрации Custom Element. |
| `headingLevel` / `heading-level` | Уровень первого заголовка, 1–6, по умолчанию 2. Markdown `#` → `h2`, как в прежнем preview редактора. Уровни выше 6 ограничиваются `h6`. |
| `label` | Доступное имя внутреннего `article`; по умолчанию «Содержимое документа». |
| `empty-text` | Пустое состояние. По умолчанию «Пока нет содержимого.». Текст выводится через `textContent`. |
| `code-wrap` | Необязательный перенос длинных строк кода. Без него сохраняется исходное форматирование и локальная горизонтальная прокрутка. |

Нет toolbar, переключателя preview, footer, textarea, contenteditable, кнопок отправки и событий принятия/сохранения. Viewer **не меняет статус задачи и не принимает результат агента**. Он не загружает отчёт: права чтения, загрузку и состояние запроса обеспечивает приложение.

### Единый renderer

`safeMarkdown(source, {headingLevel: 2})` возвращает безопасный HTML-фрагмент. Эта же функция используется в **preview существующего `iq-markdown-editor`**, в viewer и там, где ранее использовался `editor.safeMarkdown`. Никаких двух независимых движков. Preview и viewer используют общую типографику `.md-document`; внешние отступы самого редактора и просмотрщика различаются намеренно.

Поддерживается документированный поднабор: заголовки 1–6, абзацы, полужирный/курсив/зачёркнутый текст, код в строке, fenced-блоки с обратными кавычками либо тильдами, списки и вложенные списки, нумерация, неинтерактивные чек-листы, цитаты, разделители, ссылки и pipe-таблицы с выравниванием колонок.

Это не заявление о полном CommonMark/GFM-паритете. Не поддерживаются выполняемые HTML, плагины, произвольные стили, footnotes, reference-style links, автозагрузка изображений и интерпретация программ из code blocks. HTML отображается буквально. Файл не преобразуется в PDF.

### URL и приватные ресурсы

`safeMarkdownURL()` допускает абсолютный HTTPS URL без credentials и локальный `#fragment`. Схемы HTTP, javascript, data, blob, file, vbscript, относительный внешний origin `//`, обратные слеши, пробельные и управляющие символы в URL отклоняются. Отклонённая ссылка остаётся текстом.

HTTPS-ссылки имеют `target="_blank"`, `rel="noopener noreferrer"`, `referrerpolicy="no-referrer"`. Переход — только явным действием человека. Это не проверка репутации назначения и не система авторизации.

Изображение Markdown становится **ссылкой с пояснением**, а не `img`. Renderer не создаёт сетевые resource-элементы, не использует `fetch` и не префетчит ссылки. Нового автоматического обращения к приватному изображению нет. Если приложению нужен разрешённый предпросмотр приватного файла, его следует показывать отдельным медиакомпонентом после проверки доступа, а не встраивать произвольный HTML в viewer.

### Границы и доступность

Максимальный документ — 1 000 000 знаков. Превышение возвращает явную ошибку renderer; viewer и preview показывают текст ошибки без потери исходного `.value`. Для больших отчётов рекомендуется секционирование.

Широкий код и таблицы ограничены собственными блоками с `tabindex="0"`, `role="region"` и доступным названием. Клавиатурные стрелки прокручивают их, не весь рабочий экран. Ссылки доступны через Tab/Enter. Текст вне этих областей переносится, включая длинные непрерывные последовательности.
