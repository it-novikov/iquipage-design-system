# IQUIPAGE 05.7 — handoff следующему агенту

## 1. Начать здесь

Это завершение ранее показанной **предварительной 05.7**, не новая смена визуального направления. Рабочая база — утверждённая 05.6 и изменения доски из предварительного HTML 05.7. Цвета, шкалы типографики и базовые интервалы не пересматриваются. `tokens/semantic.json`: группы `base`, `light`, `dark`, `primitives` совпадают с 05.6; отличается метаинформация версии.

Откройте `whiteboard.html` для доски, `index.html` для каталога, `workbench.html` для рабочего каркаса и чтения Markdown. Финальные результаты приведены в `evidence/verification-summary.json`. Проверяйте SHA файлов, а не только надпись «05.7»: пользователь уже получал предварительный HTML с тем же номером.

**Не выдавать эту поставку за внедрение в Sprintique или за результат тестирования с людьми.** Продуктовый сервер, React-адаптер, авторизация, совместное редактирование и production cutover здесь не изменялись. Разрешение на чтение исходников или локальную сборку не равно разрешению на push/deploy.

## 2. Последняя задача пользователя

Нужно было исправить связи, библиотеку объектов, нижние инструменты и подсказки, заменить массовый ввод «полотном» на отдельные мысли, переработать функциональную цепочку, расширить набор фигур. Запрошены полный архив, интерактивный макет и handoff.

Что находится в этой поставке:

| Область | Реализация и способ проверки |
|---|---|
| Библиотека | Слева поиск, три равные категории «Записи / Фигуры / Файлы». Компактные записи и сетка фигур. Размещение выбором и кликом по свободной области или drag из библиотеки. На узком экране библиотека открывается поверх холста и закрывается после выбора инструмента. |
| Инструменты | Нижний dock: объекты, выбор, панорамирование, соединение, undo/redo; масштаб отдельно. Иконки — SVG в фиксированном 20×20 боксе; области нажатия 42×42 desktop / 38×40 mobile. Есть roving tab index и стрелки. |
| Подсказки | Один DOM tooltip с `role=tooltip`, явной парой цветов и динамическим `aria-describedby`. Появляется от hover или клавиатурного фокуса, остаётся при переходе указателя на сам tooltip; Escape работает и когда фокус вне компонента. Закрывается при действии, прокрутке, resize, удалении компонента. Никаких параллельных `::after`-подсказок. |
| Массовый ввод | Диалог отдельных карточек. Enter — следующая мысль, Shift+Enter — строка внутри мысли. Перестановка/удаление, точная область назначения. Большой текст — отдельный импорт с выбором строк или абзацев. Одно добавление — один шаг истории. |
| Размещение | Область и соседняя заметка задают ширину/ось/цвет. До commit высота вычисляется по реальному Markdown renderer. Обновление ширины из текущего zoom запрещено. |
| Фигуры | 14 общих определений: лицо, размеры, внутренняя область текста, точки крепления. Это блоки схем, **не исполнение BPMN**. |
| Связи | Прямая, плавная, угловая; подпись, направление, пунктир, положение подписи и изгиб. Четыре стороны, привязка рядом с объектом, переподключение обоих концов. Программные и клавиатурные альтернативы не требуют drag. |
| Цепочка | Отдельные смысловые блоки, развилка и возврат на уточнение; нет внешней большой рамки. Пример не исполняет автоматизацию. |

Видимые «Список» и «Карандаш» отсутствуют, как просил пользователь. Старый `view='list'` оставлен **только как совместимый программный API**, а существующие `drawing` не уничтожаются при импорте. Не возвращать эти режимы в нижнюю панель без нового запроса.

## 3. Исправления, найденные при завершении

1. Подсказка по наведению не получала Escape, если фокус был в `body`. Обработчик теперь на `document`, активен только для видимой подсказки конкретной доски. Escape сначала закрывает tooltip, затем отдельное нажатие отменяет инструмент/закрывает окно.
2. При завершении редактора **без изменения текста** no-op commit не перерисовывал объект. Внутри оставался живой `textarea`. `finishEdit()` всегда восстанавливает представление объекта, даже когда истории менять нечего.
3. Размер ручек связи менялся с масштабом из-за stroke в CSS-трансформированном SVG. И радиус, и stroke нормируются по zoom. Видимый внешний диаметр — 18 экранных px; четыре кнопки-порта — 28 px.
4. У фигур со скошенными сторонами начало обхода могло оказаться внутри расширенной ограничивающей рамки собственной фигуры. Маршрутизатор сначала выводит ствол за endpoint bbox.
5. Расчёт размеров импортированных Markdown-мыслей был приблизительным. Теперь перед атомарным добавлением вызывается тот же renderer/measure, что при редактировании.
6. После удаления или блокировки области назначения нельзя молча добавить карточки на свободное место. При открытии несуществующее место сбрасывается; при подтверждении недоступное выбранное место вызывает понятную ошибку без частичного commit.
7. Выбранный объект библиотеки при одновременном hover получал тёмный текст на тёмном фоне. Hover обычного элемента теперь исключает selected; selected и keyboard focus задают согласованную пару и для подписи. Проверять обе темы и сочетания, а не состояния изолированно.
8. Поле одной мысли в массовом вводе автоматически растёт до 224px, далее получает собственную прокрутку. Короткий текст уменьшает высоту обратно; диалог и footer не растягиваются бесконечно.
9. Сигнатура препятствий рассчитывается один раз за обновление связей, а не отдельно для каждой связи; SVG-объекты и пути переиспользуются.

## 5. Контракты, которые нельзя сломать

- Координаты объекта, пути и insets — координаты документа. Экранная точка: `stage.left + viewport.x + object.x * viewport.zoom`, аналогично Y. Zoom не меняет ширину документа.
- Whiteboard хранит `objects/connections`, graph — `nodes/edges`. Это **разные модели**, не переименовывать поля автоматически.
- `selection` и `viewport` — публичные setters без обратного event-loop. Пользовательское действие создаёт события выбора/обзора.
- В uncontrolled-режиме `iq-change` сообщает новый документ. В controlled-режиме `iq-change-request` предлагает документ с `requestId/baseRevision/accept/reject`. Успешный рисунок не равен серверному сохранению.
- Отмена, unmount и новая внешняя версия делают старое принятие неактуальным. `accept`/`reject` могут вернуть `false`; приложение обязано учитывать это.
- Новые поля связи: `fromPort/toPort`, `arrow/arrowStart`, `style`, `dashed`, `color`, `labelPosition` (0.15–0.85), `bend` (-500–500). Они сохраняются после export/import. Выбор «Параметры» редактирует ту же связь.
- Новые фигуры требуют версии ≥05.7 у **всех потребителей документа**. Старые документы валидны, но старый валидатор может заменить незнакомый shape на rectangle. Согласовать обновление reader/writer до использования новых видов.
- `drawing` — чтение старых данных, не новый инструмент.
- Изображения в whiteboard — разрешённые data URL; никакого автоматического получения приватных ссылок. `iq-graph.mediaSources` — отдельный контракт.

## 6. Подключение

```html
<link rel="stylesheet" href="./dist/iquipage.css">
<iq-whiteboard id="board"></iq-whiteboard>
<script type="module">
import { registerWhiteboard } from './dist/whiteboard.js';
registerWhiteboard();
const board = document.querySelector('#board');
board.data = { revision: 1, title: 'Обсуждение', objects: [], connections: [] };
board.saveStatus = 'Локальная доска';
board.addEventListener('iq-change', ({ detail }) => {
  // Здесь приложение сохраняет detail.value. Сервер в примере отсутствует.
  console.log(detail.reason, detail.value);
});
</script>
```

ESM использует HTTP/HTTPS. Автономные HTML содержат код внутри и не требуют npm или сервера. Поведение localStorage для `file://` зависит от браузера: наличие экспорта JSON не отменяет необходимость проверить рабочее хранение приложения.

`core`, `advanced`, `whiteboard` — отдельные входы с общими модульными URL; `iquipage.js` — полный совместимый вход. Не смешивать CSS и JS разных версий. Не копировать `src/modules` напрямую в browser: это редактируемый CommonJS, сборка делает ESM.

## 8. Что проверять руками перед развитием

Брейншторм: заметка в «Что попробуем» → длинный Markdown → сохранить → снова открыть и нажать «Готово» без изменений. Затем несколько мыслей → сменить область → абзацы внутри первой мысли → переставить → добавить → undo/redo.

Схема: выбрать ромб → провести связь от стороны → поменять подпись и линию → переподключить **начало и конец** → отменить → экспортировать и загрузить снова. Повторить при другом zoom и в readonly. Проверить hover tooltip при фокусе вне доски, клавиатурную подсказку, переход курсора на неё, Escape и fullscreen.

На 320/390 px проверить категорию фигур, прокрутку списка фигур, поля диалога массового ввода и редактор. На широком экране — длинные подписи и открытый инспектор. Для forced colors и reduced motion нужны отдельные проверки, не только обычная тема.

## 9. Известные границы, не выдавать за исправленные

- Полная проверка в Safari/WebKit и Firefox, физические touch-устройства и реальные screen readers не проведена в этом завершении. Известный ранее запрос **WebKit tap календаря** остаётся отдельным внешним приёмочным пунктом; Chromium его не закрывает.
- Маршрутизатор учитывает до **40 ближайших препятствий**, расширенных по bbox. Непересечение любых плотно наложенных объектов не гарантируется. Прямая линия намеренно не обходит препятствия. Авторазведение всех подписей и пересечений связей друг с другом не реализовано. Нет ручных промежуточных waypoint-ручек; есть настройка изгиба.
- Нет полной виртуализации холста, серверного realtime, коллективного голосования, CRDT и исполнения функциональной цепочки.
- Это экспертная переработка и автоматизированная техническая проверка, не исследование удобства с независимыми участниками. Гипотезы о более понятном UX нужно проверять с людьми.
- Иконки dock поставлены как SVG. Остальной унаследованный набор SVG и исходная айдентика не подвергались очередному глобальному редизайну.
- Нельзя обещать конкретные FPS из одного JS-замера. Новые действия не запускают бесконечные анимации, но производительность реального приложения зависит от данных, устройства и интеграции.
