# Решения (ADR)

ADR фиксирует важное техническое решение: контекст, выбор, последствия. Он нужен, когда решение трудно отменить или его захотят пересмотреть без знания причин.

## Когда писать

- меняется публичный контракт, схема данных, граница модулей;
- добавляется технология или внешняя интеграция;
- меняется правило инженерной системы;
- принимается осознанное отступление от правила.

## Как

1. Скопируйте [TEMPLATE.md](TEMPLATE.md) в `NNNN-<kebab-описание>.md` со следующим номером.
2. Статус `proposed`. После согласования с владельцем — `accepted`.
3. Принятый ADR не переписывается. Изменение решения — новый ADR со ссылкой «Заменяет NNNN», у старого статус `superseded`.

Решения инженерной системы лежат здесь. Решения конкретного продукта — в `docs/decisions/` продукта.
