# 0005. Работа без количественного лимита PR

- **Статус:** accepted
- **Дата:** 2026-10-12
- **Владелец:** it-novikov
- **Заменяет:** [0003](0003-risk-tiered-workflow.md) только в части ограничения глубины стека PR и прежние количественные ограничения из [workflow §5](../workflow.md#5-правила-потока).

## Контекст

После публикации трёх промежуточных PR правило останавливало новые независимые задачи до слияния уже открытых изменений. Владелец явно поручил продолжать работу и убрать лимит количества PR для удобства разработки. Промежуточные результаты должны сохраняться в GitHub по мере готовности.

## Решение

- Количество открытых PR, глубина стека и число задач в `review` на владельца не имеют заранее установленного численного предела.
- Открытые PR сами по себе не блокируют новую разрешённую задачу. Независимые изменения начинаются от `main`; стек используется при фактической зависимости от ещё не слитого кода.
- Зависимости, проверенная ревизия, состояние проверок и следующий шаг явно записываются в карточке и PR. Каждый завершённый промежуточный результат сохраняется отдельным коммитом; самостоятельные изменения получают отдельные PR.
- Правила определения риска, независимого ревью, исправления P0/P1, обязательных проверок и одного держателя рабочей копии продолжают действовать. Разрешение на push и PR не заменяет разрешение на merge, автослияние или deploy.

## Альтернативы

| Вариант | Решение |
|---|---|
| Увеличить прежний численный предел | Сохраняет искусственную остановку; владелец попросил убрать ограничение |
| Объединять несвязанные изменения в крупный PR | Затрудняет проверку, откат и независимую поставку |
| Сохранять отдельные PR с явными зависимостями без квоты | Принято: работа продолжается, промежуточные результаты доступны для проверки |

## Последствия

Очередь PR может расти. Порядок проверки и слияния определяется реальными зависимостями и готовностью конкретных изменений, а не занятым числом мест. Исторические ADR, ревью и журналы сохраняют прежние решения как историю; актуальное правило находится в workflow и этом ADR.
