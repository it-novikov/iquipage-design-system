# 0003. Процесс поставки по уровням риска

- **Статус:** superseded в части ограничения глубины стека PR — [0005](0005-unrestricted-pr-flow.md); остальные решения остаются accepted
- **Дата:** 2026-09-27
- **Владелец:** it-novikov

## Контекст

Исходный процесс Jarnee требует для **каждого** изменения груминг, ADR и план, два независимых ревью с исправлениями и полный release gate. Для миграции прав доступа это оправдано. Для исправления опечатки или нового поля формы та же цепочка стоит дороже, чем риск ошибки: ревьюеры устают, реальные риски тонут в формальностях, изменения копятся в длинных стеках PR. В этом репозитории стек дошёл до шести PR, которые ждут слияния.

## Решение

[Рабочий процесс](../workflow.md) делит изменения на три уровня риска: `low`, `standard`, `high`. Глубина проработки, ревью и проверок зависит от уровня. Критерии уровня объективны: изменение миграций, политик доступа, OpenAPI или зависимостей автоматически даёт `high`.

Дополнительно:

- ревью получает пакет (карточка, diff, доказательства), а не историю автора;
- первое ревью уровня `high` можно разделить между двумя ревьюерами по аспектам и провести параллельно;
- стек PR не глубже трёх уровней;
- каждое P0/P1 из ревью проверяется на возможность автоматизации;
- дешёвая модель выполняет механические шаги, сильная — проработку и ревью.

## Альтернативы

| Вариант | Почему не выбран |
|---|---|
| Единый тяжёлый процесс для всех изменений | Стоимость без пропорциональной пользы, формальное выполнение |
| Одно ревью всегда | Недостаточно для изменений безопасности и данных |
| Уровень риска на усмотрение автора | Автор склонен занижать риск; поэтому признаки `high` объективны, а понизить уровень может только владелец |

## Последствия

- Изменения `low` и `standard` проходят быстрее. `high` остаётся строгим.
- Нужна дисциплина определения уровня; карточка моста хранит его в поле `risk`.
- Процесс проверяется по результатам: число P0/P1, найденных после слияния, должно не расти.

## Условия пересмотра

Дефект, прошедший процесс `standard`, который по признакам должен был быть `high`, — повод уточнить признаки.
