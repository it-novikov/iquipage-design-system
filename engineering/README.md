# Инженерная система IQUIPAGE

Общая основа для всех наших проектов: как мы выбираем технологии, строим архитектуру, называем вещи, тестируем, проверяем и поставляем изменения, и как агенты передают друг другу работу. Дизайн-система IQUIPAGE (`libraries/iquipage`) отвечает за интерфейс. Эта система отвечает за всё остальное.

Статус: **обязательна для новых проектов и для нового кода в существующих**. Старый код приводится к ней отдельными изменениями, без смешивания с функциональными.

## С чего начать

| Кто вы | Что прочитать |
|---|---|
| Агент, получивший задачу | [bridge/PROTOCOL.md](bridge/PROTOCOL.md), затем `engineering/bridge/bin/bridge brief` |
| Разработчик в новом проекте | [принципы](principles.md) → [стек](stack.md) → [архитектура](architecture.md) → [нейминг](conventions/naming.md) |
| Автор изменения | [рабочий процесс](workflow.md): определите уровень риска и следуйте ему |
| Ревьюер | [ревью](review.md) |
| Тот, кто меняет правила | [решения (ADR)](decisions/README.md) |

## Карта документов

```text
engineering/
├── principles.md            Десять принципов, из которых выводятся остальные правила
├── stack.md                 Базовый стек: что используем, что условно, что отложено
├── architecture.md          Модульный монолит, границы, данные, безопасность, API
├── conventions/
│   ├── naming.md            Имена: Kotlin, TypeScript, SQL, HTTP, конфигурация, git
│   └── code-quality.md      Форматирование и статический анализ, исключения
├── testing.md               Что и каким тестом проверяем
├── security.md              Обязательный минимум безопасности
├── workflow.md              Поставка изменения по уровням риска
├── review.md                Как проводить и оформлять ревью
├── decisions/               ADR: принятые решения и шаблон
└── bridge/                  Мост: формат задачи, протокол агентов, CLI, триггеры, статистика
```

## Как применить к новому проекту

1. Скопируйте `engineering/` целиком или подключите как git subtree. Документы не ссылаются на Sprintique, кроме примеров.
2. Заведите в проекте `AGENTS.md` по образцу из корня этого репозитория: три строки со ссылками на принципы, рабочий процесс и протокол моста.
3. Выберите из [стека](stack.md) только то, что нужно проекту сейчас. Каждое отклонение оформите ADR в `docs/decisions/` проекта.
4. Выполните `engineering/bridge/bin/bridge init` и создайте первую задачу: `bridge new <slug> --title "…"`. Подключите хуки Claude Code из `.claude/settings.json` этого репозитория.

## Как меняются правила

Правило меняется отдельным PR с ADR: что было, что стало, почему и как мигрировать существующий код. Изменения, которые делают процесс дешевле без потери качества, приветствуются. Правило, которое никто не выполняет, лучше удалить, чем держать.
