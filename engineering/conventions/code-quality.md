# Качество кода и автоматические проверки

Статус: **обязателен для нового кода**

Правила имён описаны в [naming.md](naming.md). Автоматика их дополняет, но не заменяет смысловую проверку на ревью.

## Уровни проверки

| Уровень | Kotlin | TypeScript / JavaScript / CSS |
|---|---|---|
| Единый формат в редакторе | `.editorconfig` | `.editorconfig` |
| Оформление кода | ktlint (официальный стиль Kotlin, строка 120 символов) | стиль проекта: однородность с окружающим кодом |
| Статический анализ | Detekt 2 без правил форматирования | `tsc --noEmit` в strict-режиме |
| Границы и архитектура | ArchUnit: слои и модули (в `./gradlew check`, не в хуке) | `check-boundaries`: только публичные импорты DS, нет импортов между продуктом и чужими каталогами |
| Стили | — | `check-styles`: токены вместо сырых цветов, нет inline-стилей в разметке, нет обращений к внутренностям DS |

Одна проблема проверяется одним инструментом: форматирование — ktlint, анализ — Detekt.

## Основные решения

- Любая найденная проблема роняет проверку. Baseline со «списком разрешённых нарушений» для нового кода не заводится.
- Wildcard-импорты запрещены.
- Автоформатирование запускается только явно (`./gradlew qualityFormat`). Хук ничего не меняет сам: содержимое коммита не должно меняться незаметно для автора.
- В TypeScript включены `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`. `any` и `@ts-ignore` требуют комментария с причиной.

## Команды Kotlin-проекта

```bash
./gradlew qualityCheck      # ktlint + detekt: быстро, запускается хуком
./gradlew qualityFormat     # исправить форматирование, затем посмотреть diff
./gradlew check             # qualityCheck + архитектурные, модульные и интеграционные тесты
```

## Git hook

Хук `pre-commit` запускает `qualityCheck` на **копии индекса git** (только то, что добавлено `git add`), а не на рабочем каталоге. Если среди staged-файлов нет кода или настроек сборки, хук пропускает запуск. Обход через `--no-verify` допустим только в аварийной ситуации. Та же команда должна выполняться в CI, когда CI появится в проекте; пока его нет, её запускает release gate.

## Исключения

Если правило даёт ложное срабатывание, сначала упростите код. Если это ухудшает код, подавите конкретное правило в минимальной области с причиной рядом:

```kotlin
@Suppress("LongParameterList") // Mirrors the public HTTP contract field by field.
```

Отключение правила для всего проекта оформляется ADR и записывается в этот документ.

## Версии

Версии живут в `gradle/libs.versions.toml` и lock-файлах Gradle. Kotlin, Detekt, Gradle и Spring Boot обновляются вместе одной веткой после полного `./gradlew check`.
