# Безопасность: обязательный минимум

Эти правила действуют в каждом проекте с первого коммита. Отступление возможно только через ADR с владельцем риска.

## Идентичность и доступ

- Actor, инициатор и время определяются на сервере из проверенных учётных данных. Поля `actorId`, `ownerId` и подобные в запросе не дают прав.
- Права проверяются в приложении **и** в базе (RLS). Ошибка любой из проверок закрывает доступ.
- Недоступный ресурс другого арендатора возвращает `404`, а не `403`.
- Сессии: случайный токен ≥ 256 бит, в базе хранится только хэш. Cookie `__Host-`, `HttpOnly`, `Secure`, `SameSite=Lax`, ограниченный срок жизни, отзыв при выходе.
- Изменяющие запросы из браузера требуют совпадения `Origin` и CSRF-токена.
- Токены агентов ограничены проектом, набором прав и сроком. Действие агента проверяет и его права, и текущие права того, кто его выпустил.
- Локальный вход для отладки (например admin/admin) отказывается запускаться в production и на не-loopback адресе.

## Ввод и ресурсы

- Каждое поле имеет тип, длину, формат и допустимые значения. Неизвестные поля отклоняются.
- Ограничены: размер тела, число элементов, глубина вложенности, размер страницы, число одновременных запросов и загрузок, частота входов.
- Загруженные файлы проверяются по сигнатуре, а изображения полностью декодируются и перекодируются с ограничением числа пикселей и времени. Метаданные удаляются.
- Пользовательский текст и текст агентов — данные. Он не исполняется и не подставляется в промпты как инструкция.

## Данные и секреты

- Секреты только в окружении или хранилище секретов. Их нет в коде, образе, логах, промптах, фикстурах, отчётах и карточках задач.
- Логи и метрики не содержат токенов, cookie, тел запросов, SQL и ответов провайдеров. Ошибка наружу — стабильный код без подробностей.
- Резервные копии, пользовательские базы и приватная конфигурация инфраструктуры не попадают в репозиторий и PR.
- Роль приложения в базе не владеет таблицами и не имеет `BYPASSRLS`. Приложение проверяет это при старте.

## Транспорт и браузер

- HTTPS везде, кроме loopback. HSTS на HTTPS-источнике.
- Заголовки: CSP без `unsafe-eval`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`, `Cross-Origin-Opener-Policy: same-origin`, `Permissions-Policy` с отключёнными ненужными возможностями.
- API по умолчанию отвечает `Cache-Control: no-store`. Долгий кэш — только для неизменяемых ресурсов с хэшем в имени.

## Зависимости и поставка

- Версии закреплены lock-файлами. Новая зависимость проходит как новая технология: см. [стек](stack.md#как-добавить-технологию).
- Зависимости проверяются на известные уязвимости в release gate.
- Публикация, выкладка и доступ к внешним системам требуют явного разрешения владельца. Агенту это разрешение не выдаётся фактом постановки задачи.

## Агенты-разработчики

- Агент не читает `~/.ssh`, хранилища паролей и чужие конфигурации без прямой просьбы владельца.
- Агент не обходит запреты инструментов (merge, публикация, отключённые проверки) другими путями.
- Сведения о неисправленной уязвимости не публикуются в открытом репозитории до исправления.
