# Формат моста, версия 1

Мост хранит работу над задачей в обычных Markdown-файлах. Их одинаково удобно читать человеку на GitHub и разбирать программе: заголовки, метки полей и статусы имеют фиксированную форму. `bridge check` проверяет эту форму.

## Расположение

```text
.bridge/
├── config.json                 Агенты, цепочка передачи, сигналы ошибок (в git)
├── tasks/
│   └── <id>/
│       ├── task.md             Карточка задачи — единственный источник правды (в git)
│       ├── journal.md          Журнал событий, только дописывается (в git)
│       └── reviews/R<n>.md     Отчёты ревью (в git)
└── runs/                       Аренды, логи запусков агентов, ожидающие передачи (не в git)
```

`id` — `YYYYMMDD-<kebab-slug>`, например `20260927-kotlin-backend`.

## Карточка `task.md`

### Заголовок (frontmatter)

```yaml
---
bridge: 1
id: 20260927-kotlin-backend
title: Перенос бэкенда Sprintique на Kotlin и Spring Boot
status: active
risk: high
owner: it-novikov
holder: claude-opus-5-5
lease: 2026-09-28T02:00:00Z
branch: feature/kotlin-backend
base: feature/engineering-system
created: 2026-09-27
updated: 2026-09-27T22:10:00Z
links:
  - https://github.com/owner/repo/pull/17
---
```

| Поле | Обязательно | Значения |
|---|---|---|
| `bridge` | да | версия формата, `1` |
| `id` | да | совпадает с именем каталога |
| `title` | да | коротко, что должно получиться |
| `status` | да | `draft` → `ready` → `active` ⇄ `blocked` → `review` → `done`; или `cancelled` |
| `risk` | да | `low`, `standard`, `high` — см. [рабочий процесс](../workflow.md#2-уровень-риска) |
| `owner` | да | человек, который принимает результат |
| `holder` | при `active` | кто сейчас работает: агент или человек; пусто, если задача свободна |
| `lease` | при `holder` | ISO-время, до которого держится аренда; просроченная аренда свободна |
| `branch`, `base` | нет | рабочая и базовая ветки |
| `created`, `updated` | да | дата создания, время последнего изменения |
| `links` | нет | список ссылок: PR, ADR, документы |

Значения — строка в одну строку или список строк через `- `. Вложенных структур нет.

### Тело

Разделы идут в этом порядке. Неизвестные разделы допускаются и сохраняются как есть.

```markdown
# <title>

## Цель
Какая проблема, у кого, какой проверяемый результат. 2–6 предложений.

## Рамки
- **Входит:** …
- **Не входит:** …
- **Ограничения:** …

## Передача
- **Состояние:** что верно прямо сейчас (факты, не история)
- **Сейчас:** S3 — что уже сделано внутри текущего шага
- **Дальше:** одно точное следующее действие
- **Незакоммичено:** файлы и их состояние, или «нет»
- **Ловушки:** неочевидное, на что уже потрачено время
- **Проверка:** команда, которая показывает, что всё в порядке
- **Причина:** почему была последняя передача

## План

### S1. Каркас Gradle-проекта [done]
- **Что:** …
- **Как:** …
- **Зачем:** …
- **Приёмка:**
  - [x] `./gradlew check` проходит
  - [x] …
- **Итог:** коммит abc1234; `./gradlew check` — 12 тестов

### S2. … [active]
…

## Решения
- **D1** (2026-09-27) Интеграционные тесты используют Testcontainers через явный Docker-контекст — так требует правило продукта не трогать VM по умолчанию.

## Вопросы
- **Q1** [open] Нужна ли совместимость со старыми сессиями? → владелец

## Контекст
- `products/sprintique/README.md` — как запускать продукт
- `./gradlew check` — полный набор проверок
```

### Поле

Поле — пункт списка вида `- **Метка:** значение`. Значение может продолжаться строками с отступом в два пробела: вложенными пунктами или текстом.

### Шаг плана

Заголовок `### S<n>. <название> [<статус>]`. Статусы шага: `todo`, `active`, `done`, `blocked`, `dropped`.

| Поле шага | Обязательно | Смысл |
|---|---|---|
| **Что** | да | Результат шага |
| **Как** | да | Подход и ключевые места в коде |
| **Зачем** | да | Какую часть цели закрывает |
| **Приёмка** | да | Проверяемые критерии, чекбоксы `- [ ]` / `- [x]` |
| **Итог** | при `done` и `dropped` | Доказательство: коммит, число тестов, команда; для `dropped` — причина |
| **Зависит от** | нет | `S1, S2` |
| **Модель** | нет | `strong` или `fast` — подсказка, какой агент нужен |

## Журнал `journal.md`

Только дописывается. Одна запись — одна строка:

```markdown
- 2026-09-27T22:10:05Z · claude-opus-5-5 · checkpoint · S3 · Контроллеры задач готовы, API-тесты 40/58.
```

Поля через ` · `: время UTC, кто, вид, ссылка (`S3`, `D2`, `Q1`, `R1` или `-`), текст. Виды: `create`, `claim`, `release`, `checkpoint`, `step`, `status`, `decision`, `question`, `answer`, `handoff`, `trigger`, `review`, `note`.

Журнал — история для разбора, а не контекст для работы. Агент читает его, только если карточки не хватает.

## Отчёт ревью `reviews/R<n>.md`

```markdown
---
bridge-review: 1
id: R1
task: 20260927-kotlin-backend
reviewer: codex
round: 1
base: 1a2b3c4
head: 5d6e7f8
created: 2026-09-28T10:00:00Z
verdict: changes-requested
---
# Ревью R1

## Замечания
- **F1** [P1] `server/src/main/kotlin/com/sprintique/task/api/TaskController.kt:42` — Позиция меняется без проверки ревизии.
  Сценарий: два пользователя двигают одну карточку, второй молча перезаписывает первого.
  Решение: [open]

## Итог
- **Вердикт:** changes-requested
- **Проверено:** …
- **Не проверено:** …
```

`verdict`: `pending`, `approve`, `changes-requested`. Решение замечания: `[open]`, `[fixed <commit>]`, `[deferred <задача>: причина]`, `[rejected: причина]`.

## Что проверяет `bridge check`

- Заголовок: обязательные поля, допустимые значения, `id` совпадает с каталогом.
- Разделы на месте, цель не пуста, у `active` есть `holder`.
- У каждого шага есть Что, Как, Зачем и хотя бы один критерий приёмки. Номера шагов уникальны.
- У `done` все критерии отмечены и есть Итог. У `dropped` есть Итог с причиной.
- Задача в `done` не имеет незавершённых шагов и открытых P0/P1 в ревью.
- В карточке и журнале нет похожего на секреты: ключей, токенов, приватных ключей, паролей в URL.
- Предупреждения: просроченная аренда, раздел «Передача» длиннее 25 строк, карточка длиннее 600 строк, открытые вопросы при `review`.

Ошибка возвращает код 1, только предупреждения — код 0.

## Изменения формата

Новая версия формата увеличивает `bridge:` и описывает перевод старых карточек. CLI отказывается изменять карточку незнакомой версии, чтобы не испортить её.
