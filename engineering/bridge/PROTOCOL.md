# Протокол моста для агента

`bridge` — это `engineering/bridge/bin/bridge` в корне репозитория. Карточка задачи — `.bridge/tasks/<id>/task.md`.

## Начало сессии

1. `bridge brief` — прочитайте только это. Остальное открывайте по ссылкам, когда понадобится. Журнал не читайте без причины.
2. Сверьте реальность с карточкой: ветка, последний коммит, незакоммиченные файлы. Расхождение запишите в «Ловушки» и исправьте карточку.
3. `bridge claim <id> --agent <ваше имя>`. Если задачу держит другой с живой арендой, не работайте над ней: сообщите владельцу.

## Во время работы

- Работайте по шагам плана по порядку. Один активный шаг за раз.
- **Контрольная точка после каждого законченного куска и перед долгой операцией:**
  `bridge checkpoint <id> --state "…" --now "S3 — …" --next "…"`.
  Считайте, что сессия может оборваться в любую минуту: всё, что не в карточке, потеряно.
- Узнали неочевидное (команда падает без переменной, тест нестабилен, API ведёт себя иначе) — сразу `--trap "…"`. Это самое ценное для следующего агента.
- Приняли решение, которое кто-то мог бы принять иначе, — `bridge decide <id> "решение — почему"`.
- Не можете продолжать без человека — `bridge ask <id> "вопрос"` и `bridge status <id> blocked`.
- Не меняйте рамки задачи молча. Новое требование — вопрос владельцу.

## Завершение шага

1. Проверки шага зелёные.
2. `bridge step <id> S3 done --check all --result "коммит abc1234; ./gradlew check — 48 тестов"`.
   Итог — доказательство, а не пересказ.

## Конец сессии

- Плановое завершение: `bridge handoff <id> --reason planned`.
- Задача выполнена: пройдите release gate из рабочего процесса, затем `bridge status <id> review`.
- Если заканчивается контекст или лимит, сначала контрольная точка, потом `bridge handoff <id> --reason limit`.

## Как писать «Передачу»

- Факты о текущем состоянии, а не рассказ о том, как вы к нему пришли.
- «Дальше» — одно действие, которое можно начать без вопросов: файл, функция, команда.
- «Незакоммичено» — компилируется ли, проходят ли тесты.
- «Ловушки» — только проверенное. Каждая по одной строке.
- Никаких секретов, токенов, cookie и приватных адресов.

## Ревью

Ревьюер получает пакет из `bridge review <id>` и пишет замечания в `reviews/R<n>.md` в формате из `FORMAT.md`. Ревьюер только читает код, исправления делает автор.
