# Ревью

Ревью ищет то, что автоматика найти не может: неверное понимание требования, дыру в правах, гонку, лишнюю сложность, неправду в документации. Формат и стиль проверяют инструменты.

## Независимость

- Ревьюер не автор изменения. Для агентов — новая сессия без истории автора, по возможности другая модель.
- Ревьюер получает **пакет ревью**: карточку задачи (цель, рамки, критерии приёмки), diff относительно базовой ветки и доказательства проверок. Команда `bridge review <task> --reviewer <имя>` собирает его и создаёт файл отчёта. Параллельные ревьюеры одного раунда получают разные файлы. Повторное ревью — `--since R1`: замечания прошлого раунда и изменения после него.
- Ревьюер по умолчанию только читает. Исправления делает автор, если владелец не решил иначе.
- Утверждение ревьюера тоже требует доказательства: ссылка на строку, сценарий отказа, команда воспроизведения.

## Приоритеты

| Приоритет | Значение | Что делать |
|---|---|---|
| **P0** | Утечка данных, обход прав, потеря или порча данных, падение основного сценария | Остановить линию, исправить немедленно |
| **P1** | Неверное поведение в реальном сценарии, гонка, нарушение контракта, отсутствующий тест на рискованное поведение | Исправить до продолжения |
| **P2** | Лишняя сложность, слабое имя, неполная документация, редкий пограничный случай | Исправить или перенести в задачу с причиной |
| **P3** | Вкус, мелкая читаемость | На усмотрение автора |

## Формат замечания

Замечания записываются в файл ревью задачи (`.bridge/tasks/<task>/reviews/R1.md`) строками одинаковой формы:

```markdown
- **F3** [P1] `server/src/main/kotlin/.../TaskController.kt:42` — Позиция задачи меняется без проверки ревизии.
  Сценарий: два пользователя двигают одну карточку, второй молча перезаписывает первого.
  Решение: [open]
```

Автор отвечает в поле **Решение**:

- `[fixed <commit>]` — исправлено, с коммитом;
- `[deferred <задача>: причина]` — перенесено в другую задачу;
- `[rejected: причина]` — автор не согласен, с доводом;
- `[waived <кто>: причина]` — владелец осознанно принял риск.

Правила для P0 и P1:

- P0 исправляется, перенос P0 запрещён.
- P1 переносится, только если замечание касается артефакта вне этого изменения, а целевая задача входит в тот же выпуск и блокирует его.
- `[rejected]` у P0/P1 ждёт решения владельца: он превращает его в `[waived …]` или требует исправления.

`bridge status done` отказывает, а `bridge check` сообщает ошибку, пока есть P0/P1 в состоянии `[open]` или `[rejected]`, а также перенесённое P0.

## Чек-лист

Ревьюер проходит пункты, относящиеся к изменению, и не тратит время на остальные.

**Требования**
- [ ] Каждый критерий приёмки выполнен и подтверждён доказательством.
- [ ] В реализацию не попало то, что «не входит».

**Безопасность и данные**
- [ ] Actor и права берутся из проверенных учётных данных. Чужой проект — `404`.
- [ ] RLS и проверки приложения согласованы. Нет пути с данными без контекста доступа.
- [ ] Ввод ограничен, неизвестные поля отклоняются. Секреты не попадают в логи и ответы.

**Корректность**
- [ ] Изменение, аудит и событие в одной транзакции. Повтор запроса идемпотентен. Устаревшая ревизия отклоняется.
- [ ] Порядок блокировок совпадает с остальными командами. Права перепроверяются после блокировки.
- [ ] Ошибки внешних систем обработаны: таймаут, повтор, деградация.

**Производительность**
- [ ] Нет N+1, выборки ограничены, нужные индексы есть.
- [ ] Память и размер ответа ограничены при больших данных.

**Простота и имена**
- [ ] Нет абстракций «на будущее», дублирования и мёртвого кода.
- [ ] Имена соответствуют [конвенции](conventions/naming.md).

**Тесты**
- [ ] Тесты упадут, если сломать проверяемое поведение.
- [ ] Покрыты сценарии из [обязательного списка](testing.md#обязательные-сценарии-для-каждого-изменяющего-эндпоинта).

**Контракт и документация**
- [ ] OpenAPI, миграции, runbook и README совпадают с поведением.
- [ ] Документы не обещают нереализованного.

## Итог ревью

В конце файла ревью:

```markdown
## Итог
- **Вердикт:** approve | changes-requested
- **Проверено:** что именно (файлы, сценарии, команды)
- **Не проверено:** что осталось вне ревью и почему
```
