Основание: прямой запрос владельца, 3 октября 2026. База 79c9b8f, ветка feat/finance-sign-in-redesign. Состав и оформление Google исключены из изменений.

## Выбранное решение

Финансы строятся вокруг решения: что ожидается относительно утверждённой базы, где отклонение, как его объяснить. Порядок: контекст плана → состояние/действие → прогноз, план, факт, ожидания → категории с объяснениями → просроченные операции. Журнал остаётся отдельным представлением для работы с записями. Не добавляем произвольные банковские показатели, графики без временных данных или фальшивые бюджеты.

Для входа выбрана двухколоночная композиция с открытым описанием продукта и рамкой формы. Альтернативы: оставить крупный плакат (мало информации), добавить иллюстрацию (не объясняет действия), оставить одну форму (теряется контекст первого визита). На телефоне форма идёт первой.

## Публичная DS

Новые CSS-контракты: summary-panel, metric-grid, comparison-table, feature-list; опциональный layout=welcome у iq-auth-screen. Документы — libraries/iquipage/docs/workspace.md и authentication.md. Продукт использует только публичный пакет. CSS вырос с baseline 96253 до около 98650 gzip байт из-за новых публичных композиций; бюджет обновлён осознанно только через size.mjs, допуск 2% сохранён. Нормализован межстрочный интервал. JS-функциональность компонентов не добавлялась.

## Сохранение возможностей

- Утверждённый план, ожидаемые и проведённые операции, прогноз и отклонения остаются отдельными понятиями; расчёты не изменены.
- Валюты не суммируются. Чистый результат явно не назван остатком на счёте.
- Журнал, фильтры, формы, история операций, версии, сохранение/утверждение черновика и объяснения используют существующие обработчики и права.
- Приглашения, почтовый код, ошибки, повторная отправка, OAuth и юридические ссылки сохранены.
- Google: исходные SVG, HTML, ссылка, классы и обработчик не менялись; shell.css не изменён. Контейнер сохраняет ширину формы 360px на desktop и фон canvas.

4. DS build/test/pack, product build/boundaries, finance/auth targeted tests; два независимых code review.
5. Скриншоты до/после и ограничения в outputs/finance-auth. Проверки локального стенда не означают production-приёмку.
