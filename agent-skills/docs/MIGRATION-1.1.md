# Обновление с 1.0

Имена четырёх скиллов и исходный pinned DS 05.7 сохранены. Дизайн-система не обновляется и не включена в архив. Перед заменой сохранить прежние skill-папки и локальные изменения. Установить новые папки полностью, не объединять два набора scripts/assets разных версий. Не менять AGENTS.md/CLAUDE.md целиком.

## Совместимость инструментов
- Assessment schema 1.0 читается как historical diagnostic, но --require-ready не проходит. Новый формат — schema 2.0: independent plan + evidence registry + reciprocal finding verification + scope_ready. Нужные примеры и схемы в review/assets.
- `--current-fingerprint` сохранён; дополнительно для gate передать `--plan`, `--plan-sha256`, `--ds-archive-sha256`.
- Сохранённое ранее PASS не переносить автоматически. Реально существующие evidence могут использоваться только при подходящих fingerprints/методе/среде; отсутствующие сведения нельзя придумать.
- Capture: широкое --allow-remote удалено. Использовать точные --allow-origin. Loopback другого порта теперь тоже нужно явно разрешить. Offline fixture без сети. POST/PUT/PATCH/DELETE блокируются; не выдавать такой capture за полноценную работу API.
- Scanner: вывод snippets по умолчанию отключён; исключения получают ledger. Необоснованное исключение поддерева меняет status на INCOMPLETE. Это намеренное усиление, не регрессия качества продукта.
- Report outputs не перезаписываются. Для повторного запуска выбрать новый run/output. Разрешённые поля run-state помогают продолжить, не создавая заново brief.

## Первое использование
Для точечного исправления не нужно проводить полный discovery. Для полной миграции закрепить полный inventory и приёмочный план. Проверить выбранный клиент вручную сценариями examples/evaluation-cases.json; автоматическое поведение модели пока не сертифицировано.
