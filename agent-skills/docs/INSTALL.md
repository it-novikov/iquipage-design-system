# Установка

## Формат
Каждая папка в `skills/` — самостоятельный Agent Skill: `SKILL.md` с YAML-метаданными и локальные `references/`, `assets/`, `scripts/`. Четыре папки можно использовать вместе или по отдельности. Ссылки не требуют исходной переписки и не идут за пределы каталога скилла. Общие правила намеренно продублированы; проверка комплекта следит за совпадением копий.

Это не установка plugin в ваш аккаунт и не регистрация через этот чат. Действие выполняется в среде, где вы используете агента. Поддержка автоактивации и прав зависит от клиента. `agents/openai.yaml` — необязательная метаинформация для Codex; общие инструкции остаются в SKILL.md.

## Codex: на уровне репозитория
Из распакованного комплекта скопируйте все четыре папки из `skills/` в `<ваш-проект>/.agents/skills/`.

```text
<проект>/.agents/skills/
  iquipage-discovery/SKILL.md
  iquipage-experience-audit/SKILL.md
  iquipage-implement/SKILL.md
  iquipage-review/SKILL.md
```

Проверяйте конфликты имён перед копированием; существующие скиллы не перезаписывать без просмотра diff. В Codex CLI/IDE явный вызов: `$iquipage-implement`, `$iquipage-review` и т.д. Личный scope при необходимости — `~/.agents/skills/`. Если каталог не появился в списке клиента, проверьте путь и перезапустите клиент.

## Claude Code
Скопируйте те же четыре папки в `<ваш-проект>/.claude/skills/`, либо для личного scope в `~/.claude/skills/`. Явный вызов: `/iquipage-implement`, `/iquipage-review` и т.д. Не требуется преобразовывать тело инструкций в другой промпт. Фактический выбор и разрешения клиента нужно проверить отдельно.

## Другой агент
Используйте его документированный Agent Skills loader. При отсутствии loader передайте агенту конкретный SKILL.md и доступ ко всему его каталогу; это ручная загрузка, не автоматическая установка и не доказанная совместимость с продуктом.

## Политика проекта
`templates/AGENTS.fragment.md` можно вручную объединить с существующим AGENTS.md/политикой агента, сохранив все действующие правила. Не заменяйте весь файл. В Claude аналогично объедините содержание с действующей политикой проекта. Политика рекомендует workflow; она не повышает приоритет инструкций над system/security.

## Инструменты
Основные инструкции не требуют исполнения скриптов. Проверка поставки, статический scanner и validator используют Python 3.10+ standard library. Пассивный browser capture отдельно требует Playwright и установленный браузер. Они не устанавливаются и не загружаются автоматически. Реальная приёмка требует способности агента читать код, запускать тестовую среду и управлять UI; при отсутствии инструмента нужно отразить BLOCKED/NOT_RUN.

## Основание
Проверено 2026-09-07 по Agent Skills specification, официальным страницам OpenAI Build skills и Anthropic Claude Code skills. Адреса и область проверенного — в `skills/*/references/sources.md`. Клиентские продукты могут менять discovery и installation behaviour; перед массовым rollout проверить в используемой версии клиента.
