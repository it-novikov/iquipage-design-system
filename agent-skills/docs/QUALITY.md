## Правдивые границы
- Скиллы не устанавливались и не запускались в реальных модельных сессиях. Отсутствие автоактивации или нарушение инструкции конкретной моделью unit-тесты не обнаружат.
- Схема, hash и timestamps проверяют структуру и согласованность. Они не аутентифицируют approval, не доказывают факт исполнения команды и не исключают согласованную подделку всех входов.
- Scanner — regex-разведка, не полный AST-анализ и не detector всех визуальных обходов. Exclusions ledger не доказывает полноту исходных roots.
- Capture не выполняет продуктовый сценарий, не оценивает композицию и не измеряет составной контраст. Сетевой allowlist не заменяет системную песочницу и разрешение на доступ к данным.
- Визуальные и UX-выводы требуют реального просмотра/действий. `gate_ready` действует только на независимо зафиксированный scope, не на весь продукт и не на deploy.
- Позитивные fixtures содержат вымышленные решения и логи специально для тестирования структуры. Их нельзя применять как приёмку продукта.
- Новое внедрение Sprintique, изменение DS и исследование с пользователями не выполнялись. Известное расхождение DS core types 0.5.6/runtime 0.5.7 сохранено как предупреждение.

## Повторение
Из корня распакованного комплекта:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 tests/validate_skills.py
python3 tests/verify_package.py
```

Runtime-помощники используют Python 3.10+ standard library. Для всех разработческих тестов нужны `jsonschema` и `PyYAML`; для browser smoke — `playwright` и установленный Chromium. Точные проверенные версии указаны в `requirements-dev.txt`; зависимости не устанавливаются автоматически. Если их нет, contract-test class может быть пропущен: такой запуск нельзя называть полными 181/181.

`tests/browser_smoke.py` использует `/usr/bin/chromium` и намеренно не перезаписывает evidence. Для нового запуска сначала сохраните прошлые результаты и выберите новый output в копии теста. Он не является тестом реального приложения. Входные approval и fingerprints для новой приёмки брать из независимого согласованного контекста, не из sample.

## Формат и публичные документы
На 2026-09-07 проверены Agent Skills specification, OpenAI build-skills и Claude Code skills. Документы подтверждают структуру SKILL.md, metadata, progressive disclosure и пути установки, но не качество выполнения IQUIPAGE-инструкций. Список источников — в `skills/*/references/sources.md`. Установка/поведение клиента требуют smoke test в его фактической версии.
