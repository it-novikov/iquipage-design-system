# С чего начать

## Для новой функции
«Используй iquipage-discovery. Сначала выясни проблему и ожидания, затем подготовь короткий бриф. Не начинай код до утверждения».
После утверждения — `iquipage-experience-audit` при необходимости анализа существующего пути, затем `iquipage-implement` и `iquipage-review`.

## Для миграции существующего проекта
«Используй iquipage-implement. Внедри принятую IQUIPAGE как полную UI/UX-пересборку всех согласованных экранов. Сохрани рабочие функции и права. Используй публичные компоненты, а отсутствующее сначала передай мне как DS-GAP. По завершении пройди iquipage-review и исправь подтверждённые проблемы в утверждённом scope».

## Для проверки чужого внедрения
«Используй iquipage-review в read-only режиме. Проверь реальный продукт, не только DS-imports. Найди локальные обходы, ошибки композиции, состояния, контраст, отступы, выравнивание, grid и функциональный паритет. Составь отчёт для исправления с reproduction и acceptance».

## Для неудобного интерфейса
«Используй iquipage-experience-audit. Разбери путь новичка, опытного участника и агента-коллеги. Дай конкретную целевую структуру UI/UX, сохранив принятый стиль. Укажи доказательства, гипотезы, приоритеты, DS mapping и missing capabilities».

## Нужные входные данные
Неизменённая поставка DS, проект или доступный preview, согласованный объём и нужные роли/платформы. Агент сначала читает уже доступные материалы и спрашивает только то, что действительно неизвестно. Производственные секреты не копировать в промпт, шаблоны и отчёты.

## Важное
Архив содержит сами скиллы, а не обновлённую дизайн-систему. База `@iquipage/web 0.5.7` закреплена по SHA. Другая поставка допустима после явной проверки и обновления lock, не через «latest». Правила не дают автоматического разрешения на изменение backend, публикацию или deploy.
