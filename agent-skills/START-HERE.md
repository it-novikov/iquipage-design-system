# IQUIPAGE Agent Skills 1.1

**Четыре прежних скилла, усиленные проверки и более короткий рабочий путь.** Дизайн-система остаётся 05.7 и предоставляется отдельно.

## Выбрать по задаче
- Неясна проблема новой функции → `iquipage-discovery`: уточнить неизвестное и подготовить краткий бриф, без кода до утверждения.
- Непонятен пользовательский путь → `iquipage-experience-audit`: разобрать сценарии и предложить конкретную композицию, без правок приложения.
- Уже поручено внедрение/исправление → `iquipage-implement`: сохранить функции, применять DS целиком, missing capabilities передать пользователю.
- Нужна проверка внедрения → `iquipage-review`: код + фактический UI + поведение; исправлять только при разрешении.

## Готовые задания
«Используй iquipage-implement для согласованной миграции. Сначала прочитай источники и сохрани функциональный паритет. Не делай локальные заменители DS; при пробеле сообщи мне. После реализации пройди review и исправь подтверждённые дефекты в том же scope».

«Используй iquipage-review только для задачи редактирования срока. Дизайн уже утверждён, полный discovery не нужен. Проверь вкладку, диалог, состояния и обе темы, не распространяя вывод на непроверенные экраны».

«Используй iquipage-discovery. У нас уже есть приложенный бриф: задай только те вопросы, ответы на которые реально меняют решение. Если данных достаточно — подготовь предложение на утверждение».

## Обновление
Скопировать четыре папки skills/ в поддерживаемый каталог клиента, предварительно сохранив локальные версии. Не менять имена скиллов. [Установка](docs/INSTALL.md), [изменения формата и CLI](docs/MIGRATION-1.1.md), [результаты ревью 1.0](docs/REVIEW-1.0.md).

Валидатор 2.0 сравнивает assessment с отдельно закреплённым acceptance plan; «готов» относится только к этому scope. Hash-проверки не удостоверяют правдивость автора. Для поведения конкретной модели нужен живой прогон; он ещё не выполнен.
