# IQUIPAGE Agent Skills · 1.0.0
Четыре переносимых скилла для полного внедрения IQUIPAGE, приёмки, аудита опыта и problem-first discovery. База — **реально прочитанная Web-поставка 05.7**, а не приблизительное описание её визуального стиля. Сама библиотека DS не изменена и в этот архив не включена.

## Начать
1. Откройте [START-HERE.md](START-HERE.md).
2. Установите четыре каталога из `skills/` в поддерживаемое место вашего агента: [INSTALL.md](docs/INSTALL.md).
3. Предоставьте агенту исходники проекта и неизменённый архив/распакованную DS. Не нужно копировать всю историю чата: принципы и проверенная карта пакета включены в каждый скилл.

| Скилл | Назначение | Основной результат |
|---|---|---|
| `iquipage-discovery` | Проблема, опрос, требования и варианты решения | Короткий бриф на утверждение + требования/решения |
| `iquipage-experience-audit` | Понятность для человека и агентов, архитектура/композиция | Доказательные находки и backlog конкретной переделки |
| `iquipage-implement` | Полная пересборка согласованного UI на публичной DS | Реализация, mapping, реестр покрытия, handoff |
| `iquipage-review` | Код, визуал, UX, доступность, states, performance и обходы DS | Findings + проверяемый гейт + цикл исправлений |

## Основные ограничения
- Скилл — инструкции и помощники для агента, не модель, не UI-library и не техническая гарантия послушания. Он не предоставляет инструменты, доступ к аккаунтам или разрешение на deploy.
- «Использовать всю DS» означает покрыть все нужные продукту сценарии её возможностями; не вставить весь каталог в каждый экран.
- Отсутствующие visual-компоненты/capabilities запрашиваются у владельца. Не создаются локально, не маскируются другим DS и не объявляются готовыми API.
- Framework/API/platform adaptation допустима с чёткой границей и тестами. Нативная реализация нового визуального компонента не становится adaptation от одного названия папки.
- Review по умолчанию не меняет код. В разрешённом цикле внедрения подтверждённые находки исправляются и перепроверяются. Существенное изменение продукта требует согласования.
- Никаких выдуманных исследований, консультантов, тестов, PASS, production cutover или «идеально» без измерений и ограничений.

## Содержимое
`skills/` — четыре самостоятельные папки с SKILL.md, локальными references/templates и помощниками.
`docs/` — установка, общий процесс, качество и handoff комплекта.
`templates/` — нейтральные рабочие формы и фрагмент политики проекта.
`examples/` — стартовые задания и критерии evaluation; это не выполненные внедрения.
`tests/` — исполняемые проверки помощников и структуры.
`reports/` — результаты проверки этого пакета скиллов.
