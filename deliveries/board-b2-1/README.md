# Sprintique Board B2.1 — вложения, обложки и обсуждения

Поставка переиспользуемого модуля и локального серверного стенда.
Это не production-развёртывание Sprintique и не реализация всего плана B1–B5.
Предыдущие пользовательские поставки B1/B2 и Maps R4 не перезаписываются.

## Запуск

Для просмотра откройте `Sprintique-Board-B2.1.html` в Chromium.
Он использует IndexedDB на этом устройстве и работает без внешних HTTP-запросов.
Данные браузерной и серверной версий независимы; автоматической синхронизации нет.

Для сервера, из `packages/maps`:

```sh
npm ci --ignore-scripts --no-fund --no-audit
npm run dev
```

Откройте `http://127.0.0.1:4317/`. Стенд сохраняет данные в `.dev-state`.
Для повторения проверок используйте Node.js 22, как в CI:

```sh
npx --no-install playwright install chromium
npm run verify
```

Тесты создают отдельные временные каталоги и браузерные профили.
Команда `npm run package:board` требует успешной проверки текущего fingerprint.

## Обложка и файлы

Одна необязательная обложка на задачу. Без неё у карточки нет пустого media-блока.
Добавьте изображение сверху документа задачи либо выберите существующее вложение.
«Снять обложку» оставляет файл; удаление файла-обложки снимает обе связи при сохранении.
Изменения применяются кнопкой «Сохранить задачу», а не самим выбором изображения.
Закрытие с отказом от изменений сохраняет прежнюю задачу и обложку.

Поддерживаются PNG/JPEG/WebP, PDF, UTF-8 TXT/MD/CSV/JSON/LOG и ZIP до 10 МБ на файл.
Изображения декодируются и имеют отдельные WebP-версии до 640/1600 px.
Оригинал доступен для скачивания, не исполняется и не вставляется в HTML.
PDF, текстовые документы и ZIP пока скачиваются без встроенного просмотра.
SVG, HTML, внешние URL обложек, распаковка архивов и LLM-генерация не используются.

Двоичные данные хранятся отдельно от JSON задачи. Новая задача получает ID до
загрузки, но запись задачи появляется только при её сохранении. Повтор с тем же
ID не дублирует файл; изменённые данные с прежним ID отклоняются.
Ошибки и отмена не стирают текст задачи. Конкурентное сохранение отклоняется явно.
Временные загрузки истекают через 24 часа; сборка мусора не удаляет связанные файлы.

## Обсуждения

Список запрашивает страницы по 20 кратких записей в пределах одной задачи.
Ответы загружаются при раскрытии треда; нерешённые обсуждения располагаются первыми.
Публикация ответа не перезаписывает описание, чек-листы или обложку задачи.
Изменение серверного снимка при переходе на следующую страницу требует обновления;
открытые редакторы и черновики при этом остаются доступными.
Внутри одного открытого треда история сообщений пока загружается целиком.

## Интеграция

`mountTaskBoard` получает `repository`, `project`, права и `attachmentAdapter` от
приложения. Адаптер можно заменить, не переписывая документ задачи и карточки.
Готовые локальные адаптеры экспортируются из `@iquipage/maps/board/attachments`.
Типы находятся в `types/attachments.d.ts`, `types/board.d.ts`, `types/index.d.ts`.
Без подключённого адаптера добавление файлов недоступно и объяснено в интерфейсе.

`BoardHandle.openTask(id)` открывает актуальный документ в пределах проекта.
Карты передают `focusTaskId` для одиночной ссылки; действие «Открыть созданные
задачи» по-прежнему открывает доску. Связанные сущности не копируются.

Исходная IQUIPAGE 05.7 и её manifest остаются неизменными. Кандидат
0.6.0-board.2 собирается отдельно и содержит задокументированное исправление
жизненного цикла Markdown-редактора при изменении порядка обсуждений.

## Граница готовности

Сервер — локальный однопроцессный reference implementation, не распределённая БД.
Проверки проекта/задачи не заменяют аутентификацию и реальные роли платформы.
Production требует авторизации/ACL, квот, AV/CDR, политики хранения и резервных копий,
облачного Blob-адаптера, индексированных запросов и эксплуатации очередей.

GitHub/GitLab-автоматизация, расширенные правила на карте, виртуализация,
совместное редактирование, live LLM и real-device приёмка остаются в общем плане.
Реальные Safari, touch-устройства, скринридеры и IME не объявлены проверенными.
Headless-проверки движения не являются измерением FPS на устройстве пользователя.
Новых оплачиваемых внешних вызовов или деплоя в этой поставке нет.
